## Spacing Scale

Carried forward from Phase 18 (locked):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon gaps, tight inline spacing |
| sm | 8dp | Compact element spacing (between fields, between picker segments) |
| md | 16dp | Default element padding (horizontal screen edge, vertical section padding) |
| lg | 24dp | Section gaps (heading-to-body, form field groups, modal vertical padding) |
| xl | 32dp | Empty-state vertical centering, top safe area buffer |
| 2xl | 48dp | Not used in this phase |
| 3xl | 64dp | Icon size in empty states only |

**Exceptions (Phase 19 additions):**
- Valence picker segment internal **vertical** padding: 10dp (matches `SegmentedButton` Material 3 compact density — the only non-4-multiple value permitted, justified by the component's built-in density). Horizontal padding is 8dp (on-grid).
- Emoji tag button: minimum 44×44dp touch target (matches existing icon button standard)

All other Phase 19 spacing values are multiples of 4:
- Valence badge / chip padding: 8dp horizontal, 4dp vertical
- Valence badge / chip icon-to-text gap: 4dp
- Emoji overlay badge on goal card / chunk card: 16dp diameter, 4dp offset from top-right of left color bar
- Goal-card emoji-to-name gap: 8dp; chunk-card emoji-to-name gap: handled inline in the title string (no SizedBox)

## Color

Carried forward from Phase 18 (locked). No hex values hardcoded. All references use `colorScheme.*` semantic slots.

| Role | ColorScheme slot | Usage in Phase 19 |
|------|-----------------|-------------------|
| Dominant (60%) | `colorScheme.surface` | Screen backgrounds, dialog backgrounds, picker background |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | Unselected picker segment, valence chip background (neutral) |
| Accent (10%) | `colorScheme.primary` | Selected picker segment border + fill, onboarding step dot (active), "Save" / "Mark as energizing" CTA |
| Destructive | `colorScheme.error` | Reserved for archive/delete only — NOT used for "costs energy" valence |

**Valence color encoding — non-destructive semantic palette:**

The three valence values require a visual signal that reads at a glance without conflicting with the 60/30/10 discipline or misusing `colorScheme.error`. Use `colorScheme.*Container` slots, which Material 3 generates from the mood seed and are always semantically available:

| Valence | Background slot | Icon/text slot | Icon |
|---------|----------------|----------------|------|
| gives | `colorScheme.tertiaryContainer` | `colorScheme.onTertiaryContainer` | `Icons.bolt` (filled, 14dp) |
| neutral | `colorScheme.surfaceContainerHighest` | `colorScheme.onSurfaceVariant` | `Icons.remove` (14dp) |
| costs | `colorScheme.secondaryContainer` | `colorScheme.onSecondaryContainer` | `Icons.hourglass_empty` (14dp) |

**Rationale:** `tertiaryContainer` renders as a warm/accent tonal color (complements the mood seed); `secondaryContainer` renders as a cooler tonal color — the contrast between them is perceptible without using error red. Neither is a destructive semantic. `neutral` falls back to the standard muted surface.

**MUST NOT use `colorScheme.error` or `colorScheme.errorContainer` for "costs energy"** — this is explicitly called out in the Phase 18 contract as reserved for destructive actions.

**Accent reserved for (Phase 19 additions):**
- `SegmentedButton` selected segment in the valence picker (fills with `colorScheme.secondaryContainer` or Material default selected state — use `SegmentedButton`'s built-in selection styling, no override needed)
- "Mark as energizing" / "Skip" CTA in the onboarding energy step
- Active step dot in `_StepDots` (existing, unchanged)

## Component Inventory

### 1. Valence Picker (goal form — new)

**Widget:** `SegmentedButton<EnergyValence>` with three segments

**Placement:** In `GoalFormSheet`, inserted between the goal-name `TextField` and the Priority label row. This reuses the exact structural position of the existing `SegmentedButton<double>` (priority picker) one row below it — two `SegmentedButton` rows stack with `SizedBox(height: 8)` between them.

**Segments:**

| Value | Label | Leading icon |
|-------|-------|--------------|
| `EnergyValence.gives` | "Gives energy" | `Icons.bolt` |
| `EnergyValence.neutral` | "Neutral" | `Icons.remove` |
| `EnergyValence.costs` | "Costs energy" | `Icons.hourglass_empty` |

**Selection behavior:** Single-select, always has exactly one selection. Default selection: `EnergyValence.neutral` for new goals; loaded from persisted value for edit mode.

**Label strategy:** "Gives energy" / "Neutral" / "Costs energy" — full descriptive labels at all widths. At narrow form widths (<320dp content) the `SegmentedButton` will wrap naturally via Flutter's internal layout; do not truncate or use icon-only segments.

**Section label:** Above the picker, a `labelMedium`-styled `Text` widget with `color: colorScheme.onSurfaceVariant` reading "Energy" — matching the existing "Priority" label pattern directly above the priority `SegmentedButton`. **Weight: explicitly `FontWeight.w400`** (NOT the M3-default w500 for `labelMedium`) to honor the locked w400/w600 two-weight contract — the "Priority" label was corrected from w500→w400 in Phase 18; keep "Energy" consistent. The onboarding emoji-picker title uses `titleLarge` (a Phase 18 carry-forward, already in the system).

**State:** `_energyValence` hoisted to `_GoalFormSheetState`, initialized from `goal.energyValence ?? EnergyValence.neutral` in edit mode, `EnergyValence.neutral` in add mode.

### 2. Emoji Tag Picker (goal form — new)

**Widget:** A single tappable `InputChip`-style button with an outlined border and `Icons.tag_outlined` leading icon, placed after the valence picker and before the type-specific fields section. Label: "Add emoji tag" when unset; the emoji character itself when set.

**Affordance:**
- Unset state: `OutlinedButton.icon(icon: Icon(Icons.emoji_emotions_outlined), label: Text('Add emoji'))`
- Set state: The selected emoji rendered in a `Text` widget at `titleMedium` size inside the same `OutlinedButton`, with a trailing `Icons.close` `IconButton` to clear it
- Touch target: minimum 44×44dp via `OutlinedButton` default sizing

**Picker mechanism:** On tap, show a `showModalBottomSheet` (mobile) or `showDialog` (desktop, >= 720dp) containing a grid of ~40 common emoji organized in 5 rows × 8 columns. Use the existing `showAdaptiveFormModal` routing logic to choose between sheet and dialog. The emoji grid uses `GridView.count(crossAxisCount: 8)` with 44×44dp cells.

**Emoji set (40 total, hardcoded):** Cover common activities/energy domains:
```
🏃 🧘 📚 🎨 🎵 🌿 ☕ 🍎 💪 🧠
🌊 🔥 ✨ 🌙 ☀️ 🏔 🌸 🎯 💡 🛠
📝 🎮 🤝 🧹 🍳 💻 🌍 ❤️ 😊 🙏
🦉 🐕 🌱 🏡 ⚡ 🎸 🎭 📸 🧪 🎁
```

**Stored value:** A single Unicode emoji character (or null). Hive field 13 (`String? emojiTag`).

### 3. Valence Badge on Goal Card (goal_card.dart — new)

**Placement:** In the secondary row of `GoalCard` (the row that currently contains the `secondary` stat text and `_PriorityChip`). The valence badge is added to the right of the priority chip (or replaces the empty secondary row if neither `secondary` nor `showPriorityChip` is present).

**Structure:**

```
Row(
  children: [
    if (secondary != null) Expanded(child: Text(secondary, bodySmall)),
    if (showPriorityChip) _PriorityChip(...),
    if (goal.energyValence != EnergyValence.neutral) ...[
      SizedBox(width: 4),
      _ValenceBadge(valence: goal.energyValence),
    ],
  ],
)
```

**`_ValenceBadge` widget (file-private, parallel to `_PriorityChip`):**

```
Container(
  padding: EdgeInsets.symmetric(horizontal: 8, vertical: 4),
  decoration: BoxDecoration(
    color: {valenceBackground},
    borderRadius: BorderRadius.circular(8),
  ),
  child: Row(
    mainAxisSize: MainAxisSize.min,
    children: [
      Icon({valenceIcon}, size: 12, color: {valenceIconColor}),
      SizedBox(width: 4),
      Text({valenceLabel}, labelSmall, color: {valenceIconColor}, fontWeight: w600),
    ],
  ),
)
```

Label text: "Gives" / "Costs" (neutral shows no badge — badge is suppressed for neutral).

**Emoji tag rendering on goal card:** The emoji (if set) is shown in the title row, inserted between the type icon and the goal name:

```
Row(
  children: [
    Icon(_typeIcon, size: 16, color: goalColor),
    if (goal.emojiTag != null) ...[
      SizedBox(width: 4),
      Text(goal.emojiTag!, style: TextStyle(fontSize: 16)),
    ],
    SizedBox(width: 8), // emoji/icon-to-name gap, on-grid
    Expanded(child: Text(goal.name, titleMedium, ellipsis)),
    ...
  ],
)
```

### 4. Valence + Emoji on Chunk Card (chunk_card.dart — new)

**Placement:** In `_WorkChunkContent`, after the rationale `bodySmall` line and before the priority badge. This inserts the valence + emoji signal into the existing metadata column.

**Rendering:**

- If the goal has an emoji tag: show the emoji inline before the goal name in the title `Text`. Pattern: `'${goal.emojiTag} ${goalName}'` — rendered as a single `titleMedium` w600 `Text` with `overflow: ellipsis`. This keeps the existing text line count the same.
- If the goal has a non-neutral valence: show `_ValenceChip` (same visual as `_ValenceBadge` in goal_card, file-private copy per the existing `_PriorityChip` duplication pattern) after the rationale line.

**`_ValenceChip` on chunk card:** Identical visual spec to `_ValenceBadge` on goal card (same colors, icon, label). Duplicate the widget as a file-private class in `chunk_card.dart` (consistent with the existing `_PriorityChip` duplication pattern, documented in the Phase 18 UI-SPEC).

**Resolved chunks:** Valence badge and emoji tag inherit the existing `Opacity(opacity: 0.5)` wrapper for resolved (completed/skipped) chunks — no special handling needed.

### 5. Onboarding Energy Step (onboarding_screen.dart — new Screen 4)

**Insertion point:** New `_Screen4` added as page index 3 (after the existing 3 screens). The `_StepDots` total count becomes 4 (`totalPages: 4`). Step dot rendering is unchanged (existing `AnimatedContainer` pattern, `colorScheme.primary` for active).

**Layout:** Follows the `_ScreenLayout` wrapper (existing `SingleChildScrollView` + `ConstrainedBox(minHeight)` + `IntrinsicHeight` pattern).

**Content structure:**

```
Column(
  crossAxisAlignment: CrossAxisAlignment.stretch,
  children: [
    Text("What gives you energy?", headlineSmall),
    SizedBox(height: 8),
    Text(
      "Pick one or two activities that leave you feeling good. "
      "We'll make sure to include them on hard days.",
      bodyMedium, color: onSurfaceVariant,
    ),
    SizedBox(height: 24),
    // Goals list — shows goals created in steps 1 and 3 (if any)
    // Each row: goal name + "Mark as energizing" toggle
    ...goalRows,
    // Empty state — shown when no goals exist yet (user skipped steps 1 & 3)
    if (goalRows.isEmpty)
      Text(
        "No goals yet — add one below.",
        bodyMedium, color: onSurfaceVariant, textAlign: center,
      ),
    SizedBox(height: 16),
    // Quick-add a new energizing goal
    OutlinedButton.icon(
      icon: Icon(Icons.add),
      label: Text("Add something energizing"),
      onPressed: _addEnergyGoal,
    ),
    Spacer(),
    // CTA row
    Row(
      children: [
        Expanded(child: TextButton(onPressed: _skip, child: Text("Skip"))),
        SizedBox(width: 8),
        ElevatedButton(onPressed: _complete, child: Text("Let's go")),
      ],
    ),
  ],
)
```

**Goal rows (each existing onboarding goal):**

```
ListTile(
  contentPadding: EdgeInsets.zero,
  leading: Text(goal.emojiTag ?? '', style: TextStyle(fontSize: 20)),
  title: Text(goal.name, bodyMedium),
  trailing: FilterChip(
    label: Text("Energizing"),
    selected: _markedGoalIds.contains(goal.id),
    onSelected: (sel) => setState(...),
    avatar: sel ? Icon(Icons.bolt, size: 14) : null,
  ),
)
```

**State:** `_markedGoalIds` — a `Set<String>` of goal IDs the user marks as energizing on this screen. On `_complete`, each marked goal's `energyValence` is updated to `EnergyValence.gives` before `goalsNotifier.saveGoal(goal)`.

**Skip behavior:** Tapping "Skip" calls `_completeOnboarding()` without applying any valence overrides — all goals remain at their `neutral` default.

**"Add something energizing" quick-add:** Opens a minimal inline text field (not a modal) that appears below the button when tapped, with a goal name `TextField` and `Icons.check_circle_outlined` confirm button inline. The quick-added goal gets `energyValence: EnergyValence.gives` by default and is added to the goals list. Goal type defaults to `GoalType.timeTarget` with `weeklyHourBudget: 3.0` (same seed pattern as Screen 1).

## Interaction Contracts

### Valence Picker

| State | Visual |
|-------|--------|
| Unselected segment | `SegmentedButton` default unselected styling (surfaceContainerHighest fill, outlineVariant border) |
| Selected segment | `SegmentedButton` default selected styling (secondaryContainer fill, primary border) — uses Flutter's built-in selection state, no override needed |
| Hover (desktop) | `SegmentedButton` default hover overlay |

Selection is immediate on tap — no confirmation. Selection persists to `_energyValence` state variable and is saved only when the form's "Save Goal" / "Add Goal" CTA is tapped.

### Emoji Picker Grid

| Interaction | Behavior |
|-------------|----------|
| Tap emoji cell | Dismiss sheet/dialog, set `_emojiTag` in form state, update the button label |
| Tap clear icon on set button | Clear `_emojiTag`, revert button to "Add emoji" |
| Tap outside picker sheet/dialog | Dismiss without change |

The picker is a read-only selection grid — no search, no custom input.

### Valence Badge visibility rule

Neutral valence = no badge shown anywhere (goal card, chunk card). This keeps the UI uncluttered for the majority of goals that remain at neutral. Only "gives" and "costs" produce visible badges.

### Onboarding energy step — back navigation

The PageView uses `NeverScrollableScrollPhysics` (existing). No back button is provided between steps (matching current onboarding pattern). The step dots are purely indicative. A "Skip" TextButton is present on Screen 4.

## Screen-by-Screen Summary

### Goal Form (`goal_form_sheet.dart`)

New elements inserted into the existing `Column` children list:

1. After goal name `TextField` + `SizedBox(height: 12)`:
   - `Text('Energy', labelMedium, onSurfaceVariant)` — section label
   - `SegmentedButton<EnergyValence>` — 3 segments (gives / neutral / costs)
   - `SizedBox(height: 8)`
2. After the valence picker, before the Priority label:
   - `OutlinedButton.icon` — emoji tag affordance
   - `SizedBox(height: 8)`

The Priority `SegmentedButton` block (`SizedBox(height: 16)` terminator) is unchanged.

### Goal Card (`lib/screens/goals/widgets/goal_card.dart`)

Changes to `_GoalCardState.build`:

1. Title row: insert `Text(goal.emojiTag!, fontSize: 16)` between the type icon and goal name, when `goal.emojiTag != null`.
2. Secondary row: append `_ValenceBadge(valence: goal.energyValence)` after `_PriorityChip`, when `goal.energyValence != EnergyValence.neutral`.
3. Add file-private `_ValenceBadge` widget class.

### Chunk Card (`lib/screens/schedule/widgets/chunk_card.dart`)

Changes to `_WorkChunkContent.build`:

1. Goal name `Text`: prepend emoji when available — change string expression from `goalName ?? ...` to `'${goalEmoji != null ? "$goalEmoji " : ""}${goalName ?? ...}'`. The `goalEmoji` parameter is added to `ChunkCard` and `_WorkChunkContent` with the same null-safe forwarding pattern as existing props.
2. After rationale line: append `_ValenceChip(valence: goalValence)` when valence is non-neutral. `goalValence` is a new nullable `EnergyValence?` parameter.
3. Add `goalEmoji` (`String?`) and `goalValence` (`EnergyValence?`) constructor parameters to `ChunkCard` and `_WorkChunkContent`.
4. Add file-private `_ValenceChip` widget class (visual duplicate of `_ValenceBadge`).

### Onboarding (`lib/screens/onboarding/onboarding_screen.dart`)

Changes:

1. `_StepDots(totalPages: 4)` — bump dot count.
2. Add `_Screen4` as a new `StatefulWidget` in the `PageView` children list (index 3).
3. `_OnboardingScreenState`: add `_screen4MarkedGoalIds` (`Set<String>`) and `_screen4QuickGoals` (`List<Goal>`) state. During `_completeOnboarding`, apply `EnergyValence.gives` to marked goals before `goalsNotifier.saveGoal`.
