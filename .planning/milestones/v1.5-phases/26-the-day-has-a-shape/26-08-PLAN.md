# Plan 26-08 — Tighten the live-row reservation (G-02)

## Objective

Close `26-UAT.md` G-02: roughly 80px of dead white space renders between the live row and the next
card, because `kLiveRowReservedHeight = 240.0` over-reserves relative to what `LiveRowCard`
actually draws.

## Background — read this before touching the constant

The live row's content-driven swell is the **one locked exception** to CAL-01's proportional-height
rule, carried forward from Phase 22/23 UAT. Because `Positioned` children cannot negotiate size
post-layout, plan 26-01 reserved a fixed estimate (`kLiveRowReservedHeight = 240.0`) and threads it
through `TimelineGeometry` as a `liveExtraPx` term applied to every consumer — rows, hour hairlines,
now-line, scroll target. `26-RESEARCH.md` Pitfall 3 recommended the fixed estimate over a two-pass
measure/correct; Dan reaffirmed that choice on 2026-08-11 when offered the two-pass alternative.

So this plan **tightens the estimate; it does not replace the mechanism.**

### The measurement trap — this is the whole difficulty of this plan

The 240.0 figure came from pumping the widget under `flutter test`, whose placeholder font has no
real Roboto metrics and inflates measured glyph widths to a fontSize-wide box per character. The
live row's height is **text-driven** (kicker, title, remaining-time line, progress bar, next-line,
and — for a work chunk — an action row), so it is precisely the class of quantity
`26-VALIDATION.md` routes to the manual-only gate.

This codebase has now been bitten by this twice: `kGutterWidth` went 46 → 75 (harness measurement)
→ 52 (corrected after a real-browser check), and `kPixelsPerMinute` went 4.0 → 5.5 on a harness
measurement that is still formally provisional.

**Do not measure this constant with `flutter test`.** Measure it in a real browser.

### Measure the TALLEST variant, not the one that is convenient

An agent observation on 2026-08-11 measured a **break** live row at roughly 143 logical px in a
430px-wide browser. A break live row is the *short* variant — Phase 23's LIVE-01 deliberately
suppresses the Complete/Skip action row for breaks. A **work** live row carries that action row and
is therefore taller. Reserving against the break variant would clip a work live row, which is a
strictly worse bug than the dead space being fixed.

Measure the work variant. Sanity-check the break variant fits under the same reservation.
