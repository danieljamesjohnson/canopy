# Plan 26-10 — Nothing at the edges gets sheared (G-04, G-05, G-06)

## Objective

Close the three findings in `26-UI-REVIEW.md` (18/24, Visuals scored 1/4):

- **G-04** — every day's first and last hour-axis label is clipped in half. Unconditional.
- **G-05** — the now-line has the same root cause and clips at `PreStart` / `DayComplete`. This one
  is a real CAL-02 failure.
- **G-06** — `formatMinutesCompact` emits no AM marker, now on the app's most prominent element.

## Root cause shared by G-04 and G-05

Both widgets are positioned as `Positioned(top: geometry.yFor(x) - <height>/2, height: <height>)`
so they straddle their own y. `hourBoundariesIn` (`time_format.dart:74-81`) always includes
`rangeStart` as the first boundary and `rangeEnd` as the last, and `yFor` maps those to exactly `0`
and `totalHeight`. The outer `SizedBox(height: geometry.totalHeight)` wraps a `Stack` with no
`clipBehavior` override, and `Stack` defaults to `Clip.hardEdge` — so the first box paints from
`y = -h/2` and is cut at `y = 0`, and the last is cut symmetrically at `totalHeight`.

For the now-line the same geometry bites whenever `nowMinutes` is within
`kNowLineHeight / 2 / kPixelsPerMinute ≈ 2.5` minutes of a range edge — which is precisely
`PreStart` and `DayComplete`, because in those two states `rangeStart` / `rangeEnd` are derived
**from `nowMinutes` itself**. So the "primary visual anchor" clips at exactly the two moments when
nothing else on screen locates now.

## Which fix to take — read this, the obvious one is wrong

`26-UI-REVIEW.md` offers two options. **Take the second (reserve padding), not the first
(`Clip.none`).**

`clipBehavior: Clip.none` is a one-liner and does un-shear the labels, but it lets the top boundary
box paint ~10px *above* the Stack — into the PreStart header block directly above it. That
reintroduces the header/label overlap visible in this phase's earliest gate screenshot. Trading a
sheared label for a label colliding with body copy is not a fix.

So: **reserve `kHourAxisHeight / 2` of headroom at the top and the same at the bottom** of the
Stack's total height, and offset every `yFor` result by that amount, so no `Positioned` box can
ever start above `0` or end below `totalHeight`.

Note `kHourAxisHeight / 2` is the larger of the two half-heights only if
`kHourAxisHeight >= kNowLineHeight` — check both constants and reserve `max(kHourAxisHeight,
kNowLineHeight) / 2` so the now-line is covered too. State the value you chose and why.

**The now-line's position must stay truthful.** Do NOT clamp or nudge the line to make it fit — its
position IS the claim CAL-02 makes. Padding the container is legitimate because it moves the whole
coordinate system consistently; clamping one element is not, because it makes that element lie
about its minute. (Clamping would arguably be tolerable for a *label*, which only names an hour —
but do not special-case it; one consistent coordinate system is simpler and cannot drift.)
