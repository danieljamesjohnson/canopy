# Plan 26-09 — The chip yields to the live row (G-03)

## Objective

Close `26-UAT.md` G-03: the now-line's time chip paints on top of the **live row's** title. This is
the case Dan originally reported at the 26-06 gate and which plan 26-07 did **not** actually fix.

## Why 26-07 missed this — read before writing the test

26-07 diagnosed the collision against ordinary `ChunkCard`s, which sit behind a `16dp` outer inset
plus a `52dp` reserved gutter, so their content begins at x≈68. Confining the chip to
`kGutterWidth` genuinely fixed those, and that fix is correct and stays.

But the **live row is full-bleed by design** — the UI-SPEC's "let now break the grid" rule, carried
from Phase 22/23. `LiveRowCard` extends to x=0 and its title begins at x≈16, which is exactly where
the gutter-confined chip now sits. There is no free gutter column where the live row renders, so
"put the chip in the gutter" has no meaning there.

**The test failure is the important part.** 26-07's regression test asserted
`chipRect.right <= cardRect.left` using a finder for **`ChunkCard`**. The live row is
**`LiveRowCard`** — a different widget — so the assertion never evaluated the reported case, went
green, and the bug was reported fixed. A test that proves the wrong thing is worse than no test,
because it converts an open bug into a closed one.

The verification observed at 26-08 (a chip clear of the title on a mid-chunk render) was also
misleading: it landed on a **break** live row, whose shorter content happened to leave the title
clear. Coincidence, not coverage.

## Dan's decision (2026-08-11)

Hide the chip when the line falls inside the live row; keep the rule. Rationale he selected: the
chip is redundant there, because `LiveRowCard` already states `RIGHT NOW · 8:00 AM` and
`15 min left · until 8:25 AM` in larger type. The rule alone still marks the exact position.

Explicitly rejected: indenting the live row to match ordinary cards (reverses the deliberate
full-bleed decision), and inset-the-text-only (asymmetric internal padding on one card type).

<action>
Add a `showChip` bool parameter to `NowLineOverlay` (default `true`). When false, build only the
2dp rule and skip the chip entirely.

At the call site in `today_screen.dart`, pass
`showChip: !geometry.nowIsInsideLiveRow(nowMinutes)` — or compute it inline from the geometry's
existing `liveStartMinutes` / `liveEndMinutes` if adding a helper is heavier than it is worth. Use
the SAME half-open boundary convention the geometry already uses for `liveExtraPx`
(`>= liveStart && < liveEnd`, matching the existing `>=`-at-`liveEndMinutes` logic documented in
`timeline_geometry.dart`) so the chip's visibility can never disagree with the row layout about
where the live span begins and ends.

Do NOT recompute the live span from `resolveNowState` or from the chunk list — read it off
`TimelineGeometry`, which is the single arithmetic authority for this surface. Introducing a second
source of "where is the live row" is the exact regression class this phase has been guarding.

**Do NOT change the rule.** It must still span the full content width and cross the live row — that
crossing is the truthful mid-chunk position CAL-02 exists to deliver.

**Do NOT change the screen-reader label.** The `Semantics(label: 'Now — ${formatMinutes(...)}')`
wrapper at the call site must keep announcing the full time in every state, including inside the
live row where the chip is now visually absent. A sighted user reads the time off the live row's own
copy; a screen-reader user must not silently lose it.

Update the widget's doc comment to record why `showChip` exists (the live row is full-bleed, so
there is no gutter to occupy) so nobody "simplifies" the parameter away later.
</action>
