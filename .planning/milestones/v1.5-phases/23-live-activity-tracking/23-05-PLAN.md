<objective>
Close **G-03**, the only outright defect in the Phase 23 UAT: Dan opened the app at 9:13 with a
chunk starting at 9:15 and the live row never appeared until he manually refreshed the browser.

The obvious suspect was falsified in `23-GAP-ANALYSIS.md`: a scratch widget test pumped the real
1-minute `Timer.periodic` across the PreStart→Active boundary and **passed**, and the existing
NOW-01 test (`today_screen_now_state_test.dart:810-921`) already covers that happy path. So a plan
that only adds another happy-path tick test closes nothing.

The real single point of failure is `didChangeAppLifecycleState` (`today_screen.dart:150-166`):
`paused` unconditionally cancels **both** timers, and `resumed` is the **only** code path anywhere
in the file that revives either one. One missed or delayed `resumed` — plausible during the debug
build's ~20s single-bundle first paint, on a devtools focus steal, or under browser background-tab
throttling — leaves both timers dead permanently, and a full page reload (`initState`) is the only
cure. That is exactly the symptom Dan reported.

Purpose: the core promise of Phase 23 is that the screen tracks the current activity on its own.
A screen that silently stops tracking is worse than one that never claimed to.
Output: a lifecycle handler with no single point of failure, a self-heal path, and a regression
test that genuinely discriminates the bug.
</objective>
