  <behavior>
    Capacity table (max discretionary work chunks; apply 80% rule to get schedulable count):
    - Mood 1: max 6, schedule 80% = 4-5
    - Mood 2: max 8, schedule 80% = 6
    - Mood 3: max 10, schedule 80% = 8
    - Mood 4: max 12, schedule 80% = 9-10
    - Mood 5: max 14, schedule 80% = 11

    Allocation sequence (in fixed order):
    1. Commitment blocks for today's weekday — chunk into 25-min slots anchored to startMinutes
    2. Habits — one chunk per active habit goal (not committed: commitment chunks already placed)
    3. Outcome goals (mood 3-5 only, or any mood if deadline == today) — sorted by urgency score descending
    4. Time-target goals (mood 3-5 only) — sorted by priorityWeight descending (no CompletionLog in Phase 3)
    5. Stop when discretionary work chunk count reaches 80% of mood capacity

    Break insertion (applied AFTER work allocation):
    - Walk ordered work chunks
    - After each work chunk insert a shortBreak (5 min, goalId: null)
    - After every 3rd work chunk (mood 1-2) or 4th work chunk (mood 3-5), replace the pending shortBreak with a longBreak (25 min) instead

    Specific test cases:
    - Test 1: mood=3, 0 goals, 0 blocks → empty list (no work chunks, no breaks to insert)
    - Test 2: commitment block Mon–Fri, 60-min window → 2 work chunks + correct anchoredStartMinutes; not generated on Saturday
    - Test 3: habit goal + outcome goal, mood=1 → only habit chunk appears (no outcome chunk)
    - Test 4: habit goal + outcome goal with deadline=today, mood=1 → both chunks appear (deadline today exception)
    - Test 5: mood=5, enough goals to hit capacity → work chunk count ≤ 11 (80% of 14, rounded)
    - Test 6: 4 work chunks, mood=3 → shortBreak after chunks 1,2,3; longBreak after chunk 4 (4th triggers long)
    - Test 7: 3 work chunks, mood=1 → shortBreak after chunks 1,2; longBreak after chunk 3 (3rd triggers long on mood 1-2)
    - Test 8: outcome goal with deadline=today → daysRemaining floors at 1, no exception thrown
    - Test 9: outcome goal with null deadline → scheduled with low urgency score (still appears if capacity allows)
  </behavior>
  <implementation>
    Create `lib/services/` directory. Implement `ScheduleGeneratorService` with a single public method:

    ```dart
    List<ScheduledChunk> generate({
      required List<Goal> goals,
      required List<CommitmentBlock> blocks,
      required int moodIndex,   // 1–5
      required DateTime date,   // used to filter daysOfWeek
    })
    ```

    Import `dart:math` for `max()`. No Flutter imports. No async.

    The method returns a flat ordered list: commitment chunks interleaved with discretionary chunks, followed by break insertion pass over the full work list.

    For commitment chunks: filter blocks by `block.daysOfWeek.contains(date.weekday)`, then for each block walk cursor from startMinutes to endMinutes in 25-min steps creating ScheduledChunk with chunkTypeIndex=ChunkType.work.index, goalId=null, anchoredStartMinutes=cursor, rationale=block.name, durationMinutes=25.

    For habit goals: include active (non-archived) habits always, one chunk each, rationale="Habit".

    Urgency score for outcome goals: `(g.priorityWeight ?? 0.5) * 2.0 / max(1, deadline.difference(date).inDays).toDouble()` — where `2.0` is the placeholder chunksRemaining (Phase 3 has no CompletionLog). Null deadline = score of `(priorityWeight ?? 0.5) * 0.1`.

    For time-target goals (mood 3-5 only): sort by `(g.priorityWeight ?? 0.5)` descending; one chunk each; rationale="Weekly goal".

    Break insertion pass: iterate through ALL work chunks collected so far; maintain a workChunkCounter; after each work chunk append a shortBreak; when workChunkCounter % longBreakEvery == 0, replace the just-appended shortBreak with a longBreak. longBreakEvery = (moodIndex <= 2) ? 3 : 4.

    Note: commitment chunks count toward total output but are NOT counted against discretionary capacity (they are fixed). Only habit/outcome/time-target chunks count toward the 80% discretionary cap.
  </implementation>
