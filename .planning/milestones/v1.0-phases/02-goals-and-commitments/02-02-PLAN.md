GoalsNotifier implementation:
- `final GoalRepository _repository = HiveGoalRepository();`
- `List<Goal> _goals = [];` (active goals only, sorted by sortOrder)
- `List<Goal> get goals => List.unmodifiable(_goals);`
- Computed getters: `timeTargetGoals`, `outcomeGoals`, `habitGoals` (filter by GoalType)
- `Future<void> loadGoals()` — calls `_repository.getActive()`, sorts by sortOrder, notifyListeners
- `Future<void> saveGoal(Goal goal)` — calls `_repository.save(goal)`, then `loadGoals()`
- `Future<void> archiveGoal(String id)` — fetches by id, sets `isArchived = true`, saves, reloads. Use `_repository.getById(id)` then `_repository.save(goal)`. Do NOT call `_repository.delete()` — archive only.
- `Future<List<Goal>> getArchivedGoals()` — calls `_repository.getAll()`, filters `isArchived == true`, returns sorted by name. Does NOT call notifyListeners (read-only for archived screen).
- `Future<void> reorder(GoalType type, int oldIndex, int newIndex)` — reorders within the type group only. Algorithm: get the goals of that type (as mutable list), if newIndex > oldIndex decrement newIndex by 1, remove at oldIndex and insert at newIndex, update sortOrder field for each item in the group (index 0, 1, 2...), save each changed goal, call loadGoals().
- `String autoColor()` — returns next color from palette based on `_goals.length % palette.length`. Palette: `['#4CAF50', '#2196F3', '#FF9800', '#9C27B0', '#F44336', '#00BCD4', '#FF5722', '#607D8B']`

Replace the stub `lib/providers/commitments_notifier.dart`:
- `final CommitmentBlockRepository _repository = HiveCommitmentBlockRepository();`
- `List<CommitmentBlock> _blocks = [];`
- `List<CommitmentBlock> get blocks => List.unmodifiable(_blocks);`
- `Future<void> loadBlocks()` — `_repository.getAll()`, notifyListeners
- `Future<void> saveBlock(CommitmentBlock block)` — save, then loadBlocks
- `Future<void> deleteBlock(String id)` — `_repository.delete(id)`, then loadBlocks. Commitment blocks can be hard-deleted (unlike goals which are archive-only).

Use `context.read<GoalsNotifier>().loadGoals()` pattern note: notifiers do NOT take BuildContext. They call their own repository directly. Initialize HiveGoalRepository and HiveCommitmentBlockRepository as field declarations (not in constructor body) — they are stateless wrappers that open the box by name.
