## Typography

Material 3 textTheme roles mapped to this phase's usage. All values use `Theme.of(context).textTheme.*` — never hardcoded sizes except where noted.

| Role | Material 3 Token | Approx Size | Weight | Line Height | Usage in Phase 5 |
|------|-----------------|-------------|--------|-------------|-----------------|
| Display | `titleLarge` + `fontSize: 48` override | 48px | bold (700) | 1.1 | Hero stat number ("247") — matches end_of_day_summary_screen pattern |
| Heading | `headlineSmall` | ~24px | normal (400) | 1.2 | Section titles in data section, reflection question text |
| Title | `titleMedium` | ~16px | bold (700) | 1.3 | "By goal" labels, section subheadings |
| Body/Label | `bodyMedium` / `labelMedium` / `bodySmall` | ~14px / ~12px | normal (400) | 1.5 / 1.4 | Hero stat label, reflection suggestions, chart legend text, chip labels, section headers, archive suggestion notes, completion rate percentages |

**Declared font weights: normal (400) and bold (700) only.** `labelMedium`'s Material default of weight 500 is treated as normal (400) for purposes of this contract — no weight 500 distinction is made.

**Chart axis exception:** Week axis labels in the bar chart use `fontSize: 9` hardcoded. This is a narrow exception for compact chart axis rendering only — it is not a named type role and does not constitute a fifth size in the type scale.

**Typography rules:**
- Use `onSurfaceVariant` color for secondary/supporting text (labels, subtitles, helper text)
- Use `onSurface` for primary content text
- Reflection question text uses `headlineSmall` — large enough to read without glasses, small enough to fit 2+ lines

Source: Established by existing code patterns across all Phase 1–4 screens.

## Color

This project uses Material 3 dynamic color from `ColorScheme.fromSeed(seedColor: Color(0xFF3D6B4F))` (forest green). All color references use `Theme.of(context).colorScheme.*` tokens — never hardcoded hex values except for goal colors (which come from `GoalsNotifier` palette).

| Role | ColorScheme Token | Usage |
|------|------------------|-------|
| Dominant (60%) | `colorScheme.surface` | Page background, chart center space, modal backgrounds |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | Reflection question cards, goal adjustment cards, archive suggestion cards |
| Accent (10%) | `colorScheme.primary` | Bar chart bars, progress indicators, active step dots, "Finish review" CTA button |
| Accent variant | `colorScheme.primaryContainer` | Home screen review banner background |
| Destructive | `colorScheme.error` | Archive confirmation button only |

Accent (`colorScheme.primary`) reserved for:
1. Bar chart bar fill color
2. Step progress dots (active state) in reflection section
3. "Finish review" ElevatedButton
4. "Start review" button in home screen banner

Goal colors (donut chart slices and goal card left bars): sourced from `GoalsNotifier` color palette via `hexToColor()` helper (already exists in `chunk_card.dart`). The "Time not spent" donut slice uses `colorScheme.outlineVariant` (neutral grey — honest but not alarming).

**Mood color system:** The existing `_moodColors` map in `home_screen.dart` is established visual language. Do not apply mood colors to the quarterly review — the review is celebratory and should not carry mood connotations.

Source: `main.dart` seed color `0xFF3D6B4F`, `home_screen.dart` `_moodColors`, `chunk_card.dart` `hexToColor()`, `end_of_day_summary_screen.dart` color usage.

## Screen Layout Contract

### QuarterlyReviewScreen — Three-Section Flow

**Route:** `/review` (full-screen, outside `StatefulShellRoute`, no bottom nav bar) — already wired in `router.dart`.

**Structure:** Three distinct sections navigated top-to-bottom in a continuous `PageView` at the screen level (or explicit "Next" buttons between sections — either approach acceptable; RESEARCH.md Pattern 4 recommended). Within Section 2, a nested `PageView` handles question-by-question navigation.

```
QuarterlyReviewScreen (StatefulWidget)
├── AppBar: "Your quarter" + close (X) icon
├── Outer navigation: Section indicator (3 dots) or section label
└── Section PageView
    ├── Section 1 — DataSection
    │   ├── Hero stat: "247 chunks completed" (48px bold)
    │   ├── DonutChart (200px height, centered)
    │   ├── Chart legend (goal name + color swatch + %)
    │   ├── WeeklyBarChart (180px height)
    │   └── "Next: Reflect" ElevatedButton (bottom)
    ├── Section 2 — ReflectionSection
    │   ├── Question step dots (3–5 dots, active = primary)
    │   └── Question PageView (NeverScrollableScrollPhysics)
    │       └── ReflectionQuestionCard per question
    │           ├── Question text (headlineSmall)
    │           ├── 2–3 suggestion chips (tappable)
    │           └── "Other..." TextButton → inline TextField
    └── Section 3 — AdjustmentsSection
        ├── Section heading: "Set your priorities for next quarter"
        ├── ReorderableListView of GoalAdjustmentTile
        │   └── per tile: color bar + name + drag handle + optional archive prompt
        └── "Finish review" ElevatedButton (bottom)
```

**AppBar:** Title "Your quarter". Leading: close icon (X) that pops the route. No other actions. Elevation 0.

**No bottom nav bar:** Confirmed by D-14 and existing router structure.

## Interaction Contracts

### Section 1 — Data Display (no user interaction on charts)

- Charts render immediately from aggregated data — no loading spinners for data already in memory
- No touch callbacks on `PieChart` or `BarChart` (per D-01 and RESEARCH.md anti-patterns)
- "Next: Reflect" button advances to Section 2 via `_controller.nextPage(duration: Duration(milliseconds: 300), curve: Curves.easeInOut)`
- Donut chart "Time not spent" slice uses `colorScheme.outlineVariant` — labeled in legend as "Time not spent" (per D-02)

### Section 2 — Reflection Questions

- Swipe gesture: disabled on outer PageView (NeverScrollableScrollPhysics) to prevent accidental section skip
- Answer by tapping a suggestion chip → answer recorded → `_controller.nextPage()` advances to next question automatically (300ms easeInOut)
- "Other" tap: reveals an inline `TextField` below the chips. User types + taps "Done" or submits keyboard → answer recorded → auto-advance
- Last question answered → auto-advance to Section 3 (no manual "Next" needed)
- Back arrow in AppBar is disabled/hidden during reflection to prevent losing progress; only the X close button (confirms discard) is available

**Reflection Questions (5 fixed, Claude's discretion — celebratory/warm tone per D-07 and D-08):**

| # | Question | Suggested answers (data-driven) |
|---|----------|--------------------------------|
| 1 | "Which goal gave you the most energy this quarter?" | Top 3 goal names by completion rate + "Other" |
| 2 | "What are you most proud of from the last 90 days?" | Top 3 goal names by absolute chunks completed + "Other" |
| 3 | "Which goal felt harder to show up for?" | Bottom 3 goal names by completion rate (only if ≥1 chunk scheduled) + "Other" |
| 4 | "Is there a goal you want to give more focus next quarter?" | All active goal names + "Other" |
| 5 | "Anything you want to let go of for now?" | Goals with ≤20% completion rate + "Nothing — keep them all" + "Other" |

### Section 3 — Goal Adjustments

- Drag to reorder: `ReorderableDelayedDragStartListener` on drag handle icon. Long-press activates drag on mobile.
- Archive suggestion: shown inline below any goal with ≤20% quarterly completion rate. Text: "This one rarely made it in — archive it?" with a "Archive" `TextButton` (uses `colorScheme.error` text color) and "Keep" `TextButton`. Tapping either dismisses the prompt. Tapping "Archive" calls `GoalsNotifier.archive(goalId)`.
- "Finish review" button at bottom: saves new sort order to `GoalsNotifier` (via new `reorderAll(List<String> orderedIds)` method), persists `QuarterlySnapshot`, pops route.
- "Finish review" is disabled (greyed) while save is in progress (standard `_isSaving` bool pattern per `onboarding_screen.dart`).

### Home Screen Review Banner (D-12)

- Placement: immediately below the `ScheduleProgressBar` if schedule exists, or as first content in empty state
- Dismissable: `Dismissible` widget with `key: const Key('review_banner')`, swipe-to-dismiss stores dismissed state in memory (not persisted — reappears on app restart until review is completed or window closes)
- "Start review" button: `context.push('/review')`
- Banner copy: "Your quarterly review is ready — see how far you've come."
- Banner subtitle: "Takes about 5 minutes."
- Banner vertical padding: 8px (sm token) top and bottom
- Dismiss icon: `Icons.close` trailing the banner title row

### Settings — Past Reviews Entry (D-15)

- New `ListTile` in `settings_screen.dart`: "Past reviews" with trailing `Icons.chevron_right`
- Navigates to a new route `/settings/past-reviews` showing a simple `ListView` of `QuarterlySnapshot` records sorted descending by `completedAt`
- Each row: "Q{n} — {periodStartYmd formatted as 'Jan 2026'}" + trailing "{N} chunks completed"
- Empty state if no snapshots: "No reviews yet — complete your first quarterly review to see it here."
