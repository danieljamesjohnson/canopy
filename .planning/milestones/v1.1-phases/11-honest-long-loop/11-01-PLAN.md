<objective>
Fix the donut chart's invisible-slice bug (REVIEW-01) and wire priority write-back at the data layer (REVIEW-02), plus stand up the Wave 0 test scaffolds for both requirements.

REVIEW-01 root cause: `donut_chart.dart` iterates only active `goals`, so commitment-attributed logs (stored as `log.goalId == CommitmentBlock.id` per Phase 10-01) and archived-goal logs are silently dropped — they never become a slice. Fix: classify every key in `goalChunkTotals` against three lookup sets (active goal ids, archived goal ids, commitment block ids) with an "Other" catch-all, drawing a slice for each non-zero category so the percentage denominator (sum of drawn slices) reads 100%.

REVIEW-02 root cause: `schedule_generator.dart` orders by `priorityWeight` and never reads `sortOrder`, but the review's reorder path (`reorderAll`) writes only `sortOrder`. Fix: add `GoalsNotifier.reorderAllWithPriority(orderedIds)` that also writes `priorityWeight` via the linear spread `0.75 - 0.5 * i / (n - 1)`. The adjustments call-site swap and screen-load wiring land in Plan 02 (Wave 2).

Purpose: Make the quarterly review count all logged time honestly and make priority changes a real input to generation.
Output: Updated DonutChart/DataSection/GoalsNotifier + new/updated tests for slice correctness, weight write-back, and generator ordering.
</objective>

<threat_model>
## Trust Boundaries

Canopy is a local-only, single-user Flutter app — no network, no auth, no backend, no LLM API, local Hive storage only (per PROJECT.md). The only trust boundary is in-process: persisted Hive data → aggregation/generation read paths. The realistic threat surface is data-integrity, not external attack.

| Boundary | Description |
|----------|-------------|
| Hive completion logs → donut aggregation | A logged id that fails to classify must not silently vanish from the chart total |
| Drag order → persisted priorityWeight | A reorder that does not produce distinct monotonic weights would leave generation unchanged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | DonutChart slice classification | mitigate | Every goalChunkTotals key is routed to exactly one slice (active / archived / commitment / Other catch-all); percentage denominator = sum of drawn slices; verified by the Task 1 percentage-sum + commitment + archived tests |
| T-11-02 | Tampering | reorderAllWithPriority priorityWeight write | mitigate | Linear spread guarantees distinct monotonic weights (0.75→0.25); Task 1 notifier test asserts persisted values, generator-ordering test asserts the write changes output — a silent no-op write would fail both |
| T-11-03 | Information disclosure | local Hive store | accept | Single-user local device app; no PII leaves the device; no network surface — no high-severity external threat exists for this phase |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | No packages added this phase (RESEARCH Package Legitimacy Audit: "No new packages introduced"); no install tasks, so no slopcheck checkpoint required |

There are no high-severity external (web/auth/network) threats in this phase; the milestone constraints forbid network and AI surfaces entirely.
</threat_model>
