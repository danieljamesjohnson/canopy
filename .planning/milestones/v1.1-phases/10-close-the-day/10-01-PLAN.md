<objective>
Lay down the Phase 10 data-layer foundation and fix commitment-time attribution (CLOSE-03).

Add the `commitmentId` carrier field to `ScheduledChunk` (HiveField 9) and the evening-reminder
settings fields to `AppSettings` (HiveFields 7-8) as additive Hive migrations, bump the schema
version 4 → 5, regenerate the `.g.dart` adapters, set `commitmentId` on commitment chunks at
generation time, and apply the `chunk.commitmentId ?? chunk.goalId ?? ''` fallback to all three
completion-log write sites so commitment time stops being logged with an empty goal id.

Purpose: Today, commitment-block chunks log `goalId: ''`, and the summary/aggregation layer
explicitly skips empty-goalId entries — so all commitment time is silently dropped. CLOSE-03 makes
the log correct, which is the precondition for Phase 11's honest aggregation. The schema fields for
the evening reminder (HiveFields 7-8) are co-located here so the single migration 4→5 covers every
new field this phase introduces, keeping Wave 2 plans free of schema churn.
Output: `commitmentId` field + regen adapter, evening-reminder AppSettings fields + regen adapter,
migration 4→5, generator Step 1 attribution, three corrected log sites, regression test.
</objective>
