<objective>
Rework `checkin_screen.dart` so the check-in is legible at every mood level (CHECKIN-01) and the lighter-day choice becomes a well-timed, unambiguous post-commit decision screen instead of an always-visible inline toggle (CHECKIN-02).

Two coupled changes land in one file and ship together:
1. **Contrast + interaction states (CHECKIN-01):** a luminance-adaptive `_onBgColor` getter replaces every hardcoded `Colors.white` foreground reference (the source of the mood-4 sage and mood-5 amber WCAG failures), and emoji targets gain hover + pressed visual feedback via `MouseRegion` + `AnimatedContainer`.
2. **Lighter-day decision flow (CHECKIN-02):** remove the inline `Switch`, add a `_generationDone` state gate, and insert a third `AnimatedSwitcher` child (`_buildDecisionBody`) that presents two explicit `_LighterDayCard` choices after the user commits with "Let's go."

Both edits live in `_CheckinScreenState`, so they cannot be parallelized across plans — they are sequenced as tasks within this plan. `_onBgColor` (Task 1) is consumed by the decision screen and "Let's go" button (Task 2), so Task 1 lands first.

Purpose: The first real dogfood (`.planning/research/dogfood-2026-06-12/`) flagged the amber-wash contrast failure and the ambiguous inline lighter-day toggle. This plan closes both.
Output: A legible, hover-aware check-in screen with a two-step commit → lighter-day-decision → acknowledgment flow, plus unit and widget test coverage.
</objective>
