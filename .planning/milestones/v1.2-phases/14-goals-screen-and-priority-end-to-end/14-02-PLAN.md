<objective>
Make priority a primary scheduling signal in the engine and render the priority badge on every schedule chunk card so the user can see — and trust — that changing a goal's priority changes the generated schedule.

This plan covers PRIORITY-01 (priority measurably influences generation beyond a tiebreaker) and the chunk-card half of GOALS-02 (priority badge on schedule cards). It is file-isolated to `lib/services/`, `lib/screens/schedule/`, and `lib/screens/home/widgets/` (+ its tests) so it runs in parallel with Plan 14-01 (Goals screen UI), which owns `lib/screens/goals/`. There is ZERO file overlap with 14-01.

Purpose: Before this phase, priority was a tiebreaker for time-target goals, had no effect on habit ordering, and was invisible on the schedule. The engine changes are pure Dart (no Flutter/Hive/BuildContext) and are the highest-value work for success criteria 3 and 4 — they are implemented and tested first.

Output: Engine Step 2 + Step 4 priority logic in `schedule_generator.dart`, `goalPriorityWeight` threaded through ChunkCard → SwipeableChunkCard ← ScheduleScreen and into ActiveChunkCard, three new engine test cases, and one new chunk-badge widget test.
</objective>
