<objective>
Make the Goals screen read as an explicit prioritization view with a legible priority visual language, and make drag-reordering actually write priority weight so the engine responds to it.

This plan covers GOALS-01 (purpose explicit + obvious reorder affordance) and the goal-card half of GOALS-02 (priority visual language on goal cards). It is file-isolated to `lib/screens/goals/` (+ its tests) so it runs in parallel with Plan 14-02 (schedule cards + engine), which owns `lib/screens/schedule/`, `lib/screens/home/widgets/`, and `lib/services/`.

Purpose: After the first dogfood, the Goals screen's purpose was unclear, the drag affordance read as "two ambiguous slashes," priority was invisible after the form save, and reordering had no scheduling effect. This plan fixes all four.

Output: A redesigned `GoalsScreen` (heading, `Icons.drag_indicator` on desktop + mobile, reorder-writes-priority), a `_PriorityChip` widget + chip on `GoalCard`, one updated widget test, and two new widget tests.
</objective>
