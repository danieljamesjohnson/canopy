## Root cause, restated precisely (why a new tier, not a bigger compact one)

`26-UI-SPEC.md`'s own "Break, Compact tier" already tried to solve this exact problem once: it
specifies the dashed box's *padding* dropping to `0dp` ("a real value on the 8-pt scale ... the
label is vertically centered ... which is what a 20px-tall box needs anyway"). The shipped code
(`lib/screens/schedule/widgets/chunk_card.dart:137-160`) does exactly that —
`Padding(vertical: 0)` inside the `CustomPaint`. **What the spec never zeroed is the outer
`Container`'s own `margin: EdgeInsets.symmetric(vertical: 4)`** (line 139) — 8dp of vertical space
the padding fix didn't touch, on top of one `bodySmall` text line's real-device height. That gap is
almost certainly the specific arithmetic behind `SEED-005`'s measured "52dp natural height, 32dp
clipped" (harness-inflated, but the qualitative story — margin the spec forgot to zero, stacked on
top of a real text line, in a 20dp box — holds regardless of which font renders it).

This phase does **not** patch that margin and call the compact tier fixed. The ROADMAP's decision
is a **new**, visually distinct tier below it — matching the precedent Phase 27 set for the live
row (`kCompactLiveMinHeight` / two genuinely different layouts, not one tier squeezed twice). The
margin miss above is cited as evidence for *why* the new tier's own margin must be zeroed
deliberately (see "Sub-compact tier" below) — this phase is not repeating that specific mistake a
second time under a new name.

## Architecture: a third density tier, break-scoped

### What changes, and where

1. **`ChunkCardDensity` (`lib/screens/schedule/widgets/chunk_card.dart:12-33`) gains one new
   value: `subCompact`.** Doc comment states its trigger and scope explicitly (slot height, break
   rows only — see below), mirroring the existing three values' comment style.

2. **`ChunkCard._buildBreak` (`chunk_card.dart:129-217`) gains a third branch**, checked before the
   existing `compact` branch:

   ```dart
   if (density == ChunkCardDensity.subCompact) {
     return _buildSubCompactBreak(context, title);
   }
   if (density == ChunkCardDensity.compact) {
     // unchanged
   }
   ```

3. **`_WorkChunkContent.build`'s density switch (`chunk_card.dart:397-413`) must add a
   `ChunkCardDensity.subCompact` arm to stay exhaustive** (Dart's enum-switch-expression
   exhaustiveness is a compile error, not a lint, the moment a fourth value exists — the same
   mechanical consequence Phase 27's 27-01-PLAN.md hit adding `NowMarkerRow`). **Deliberate scope
   decision:** this arm is a defensive fallback only — route it to the identical rendering
   `_buildSubCompactBreak`-style content would produce for a work title (see "Scope boundary"
   below) — it is **not reachable from any current call site** and does not need its own measured
   threshold. Do not build a parallel `kSubCompactWorkMinHeight` constant for it.

4. **`today_screen.dart`'s break density selection (`today_screen.dart:789-792`)** gains a third
   band:

   ```dart
   final density = isBreak
       ? (slot >= kFullBreakMinHeight
             ? ChunkCardDensity.full
             : slot >= kSubCompactBreakMinHeight
                 ? ChunkCardDensity.compact
                 : ChunkCardDensity.subCompact)
       : (slot >= kFullTierMinHeight
             ? ChunkCardDensity.full
             : ChunkCardDensity.compact);   // work branch UNCHANGED — see "Scope boundary"
   ```

5. **`timeline_geometry.dart` gains one new constant**, `kSubCompactBreakMinHeight`, colocated with
   `kFullTierMinHeight` / `kFullBreakMinHeight` / `kCompactLiveMinHeight` (the existing
   density-threshold cluster) — not inside `chunk_card.dart`, matching the established "one file
   owns every Today-timeline density threshold" convention `27-UI-SPEC.md` set.

**Nothing about `Positioned(height: slot)`, `ClipRect`, `OverflowBox`, or `TimelineGeometry.yFor`/
`heightFor` changes.** The new branch only changes which content renders *inside* the
already-fixed-height box (D-02's box-never-inflates rule, carried forward unmodified) — this is
what makes SEEBREAK-02 true by construction rather than by a new assertion: the slot a break
occupies is `durationMinutes * kPixelsPerMinute` before this phase, during this phase's new
branch, and after it, unconditionally. State this explicitly in the plan's acceptance criteria
rather than leaving it implicit.

### Scope boundary — breaks only, work chunks get a documented dead-path fallback

`29-CONTEXT.md`'s domain scope names `chunk_card.dart` broadly ("the non-live break/chunk card"),
but the phase's actual defect, requirements (SEEBREAK-01: "every **break** is identifiable as a
break"), and every piece of cited evidence (`SEED-005`'s table has exactly one clipped row: the
5-minute break) are break-specific. Deciding explicitly rather than leaving it ambiguous:

- **The density-selection call site (`today_screen.dart`) only ever produces `subCompact` for
  break rows.** The work branch keeps its existing two-way `full`/`compact` split, unchanged.
- **Under the current engine (Phase 28's lattice), this is exhaustive in practice, not just in
  scope.** `LATTICE-01`/`LATTICE-02` emit breaks of exactly two durations: 5 min (20dp, always
  `< kFullBreakMinHeight`, and — per the measurement recipe below — expected to always land below
  `kSubCompactBreakMinHeight` too) and 30 min (120dp, always `>= kFullBreakMinHeight`). **A short
  break renders `subCompact` unconditionally today; a long break renders `full` unconditionally
  today; the `compact` break tier is unreachable via the generator's current output** (it would
  only fire for a break duration this codebase does not currently generate, e.g. 10-20 minutes).
  Do not delete `compact`'s break branch — the rule is still slot-height-driven, not
  chunk-type-driven, per `26-UI-SPEC.md`'s own stated principle ("keyed on `durationMinutes`, not
  on chunk type"), and a future cadence change could reach it.
- **Work chunks are not exercised by this phase's evidence, but are not structurally guaranteed to
  stay ≥88dp either** — commitment-anchored work chunks size to their commitment window (Phase 28
  research), so a very short anchored commitment is possible in principle. This phase does **not**
  extend the sub-compact treatment to work chunks (no reported defect, no measurement evidence,
  and expanding scope here is exactly the kind of untracked scope creep this project's `CONTEXT.md`
  process exists to prevent). It only makes the enum switch compile by giving `subCompact` a
  content branch inside `_WorkChunkContent` — visually identical to the break sub-compact
  treatment (title + hairline, using `_titleText` in place of the break's `title`) — documented in
  code as unreachable from any current call site, so a future phase that *does* need it has a
  ready (if unmeasured) fallback rather than a fresh compile error.

## The sub-compact tier (SEEBREAK-01)

**"A single hairline-with-label"** (ROADMAP's own phrase) — no `Card`, no dashed border box, no
outer margin. A thin divider line spans the row, with the break's label centered on it:

```dart
Widget _buildSubCompactBreak(BuildContext context, String title) {
  final theme = Theme.of(context);
  return Semantics(
    // Duration is dropped from the visible label (see Copywriting below) — restate it for
    // screen readers, the same "narrower visible string than the meaning it needs to convey"
    // pattern 27-UI-SPEC.md's single-line tier and NowLineOverlay already use.
    label: '$title, ${chunk.durationMinutes} min',
    excludeSemantics: true,
    child: Row(
      crossAxisAlignment: CrossAxisAlignment.center,
      children: [
        Expanded(
          child: Divider(height: 1, thickness: 1, color: theme.colorScheme.outlineVariant),
        ),
        Padding(
          padding: const EdgeInsets.symmetric(horizontal: 8),
          child: Text(
            title,
            maxLines: 1,
            overflow: TextOverflow.ellipsis,
            style: theme.textTheme.bodySmall?.copyWith(
              color: theme.colorScheme.onSurfaceVariant,
            ),
          ),
        ),
        Expanded(
          child: Divider(height: 1, thickness: 1, color: theme.colorScheme.outlineVariant),
        ),
      ],
    ),
  );
}
```

**Design notes, each answering a specific thing the previous compact tier got wrong:**

- **Zero outer margin, explicitly** (not `EdgeInsets.symmetric(vertical: 4)` like the compact
  tier's `Container`, not restated here at all). This is the direct fix for the root cause above —
  the smallest guaranteed slot (20dp) cannot spend 8dp of it on margin and still leave room for one
  legible text line. Identical reasoning to Phase 27's `LiveRowCard` single-line tier
  (`PD-27-01`), applied to the same problem in a different card. The visible seam between this row
  and its neighbors is preserved anyway: the work `Card` above and below still carries its own
  `margin: EdgeInsets.symmetric(vertical: 4)` (unchanged), and Flutter `Card`/`Container` margins
  don't collapse, so the neighbor alone supplies the visible gap — the exact mechanism
  `27-UI-SPEC.md` already used to justify the same move.
- **No `CustomPaint` dashed border.** The horizontal `Divider` line **is** the break's visual
  vocabulary at this size — it is not trying to be a smaller dashed box, it's a different idiom
  (the classic "divider with label" pattern), which is also cheaper: no painter, no corner radius
  decision at a size where a border box reads as noise.
  `Divider(height: 1, thickness: 1)` — not the default `height: 16` — so the widget occupies
  exactly its stroke thickness, leaving the `Row`'s cross-axis extent to be set by the `Text`
  (its tallest child), not by the divider's own default padding.
- **Zero vertical padding around the label**, matching the compact tier's already-correct choice —
  `Center`/`CrossAxisAlignment.center` positions the text within the row instead of pushing it away
  from an edge with padding a 20dp box can't spare.
  - No new spacing token — `0` is a valid point on the existing 8-pt scale (per
    `26-UI-SPEC.md`'s own precedent for the compact tier's padding, and `27-UI-SPEC.md`'s for the
    live single-line tier's margin).
- **No tap target**, matching every existing break tier (`full`/`compact` never wire `onTap` for
  breaks — `ChunkCard._buildBreak` has no `GestureDetector` at any density). Not a new
  restriction; simply unchanged.
- **Horizontal insets:** this row renders **through the existing `TimelineRowTile`** wrapper
  (unlike `LiveRowCard`, which is positioned `left: 0, right: 0` with no wrapper and must restate
  its own horizontal offsets). It therefore inherits `kGutterWidth` + `kTimelineRowInset` /
  `kCardLeftInset` automatically — do **not** add a second horizontal inset inside this widget; the
  `Padding(horizontal: 8)` above is the label's own breathing room from the divider lines, nothing
  more.

## The threshold constant and where it lives

**`kSubCompactBreakMinHeight`** — colocate in `timeline_geometry.dart`, immediately after
`kFullBreakMinHeight`, matching the file's existing "every density threshold that governs the
Today timeline lives here" convention.

**Working target: `24.0`.** Source: the ROADMAP's own estimate ("below a measured threshold
(~24dp)"), corroborated by the root-cause arithmetic above (8dp margin the compact tier never
zeroed + one real-device `bodySmall` line, which typically runs ~14–18dp at default text scale) —
**this is a placeholder, not a measurement, and must not be treated as final.** Consistent with
this project's three-strikes history on exactly this kind of constant (`kGutterWidth`
46→75→52, `kPixelsPerMinute` 4.0→5.5→4.0, `kCompactLiveMinHeight` 60→84→88), it ships here as an
honest estimate.

**What this constant means precisely:** the slot height at or above which the *existing, unchanged*
`compact` break tier's own natural height fits without clipping; below it, `subCompact` renders
instead. It is **not** a measurement of the new sub-compact tier's own height (that tier is
designed to fit comfortably under any plausible break slot, including the smallest, 20dp) — it is
a measurement of where `compact` (margin `8dp` + padding `0dp` + one `bodySmall` line, unchanged by
this phase) stops fitting.

**Re-measurement is mandatory before this constant ships**, per the same recipe class Phase 27
used (`27-UI-SPEC.md` "The threshold constant and where it lives"):

1. Implement the sub-compact tier exactly as specified above; leave the `compact` tier's own code
   untouched (measuring it as-shipped is the point).
2. `flutter build web --debug --source-maps --pwa-strategy=none`.
3. Serve with `python3 tools/serve-uat.py <port> --dir build/web` (never
   `python3 -m http.server` — `CLAUDE.md` trap #3).
4. Generate a day whose lattice includes at least one short break (any mood works — every mood's
   lattice includes 5-minute breaks per Phase 28) and scroll it into view.
5. Screenshot headless Chromium at a mobile viewport (e.g. 430×930, DPR 1),
   `--use-gl=swiftshader --enable-unsafe-swiftshader` (avoids the `CONTEXT_LOST_WEBGL` false-blank
   trap, `CLAUDE.md` trap #2).
6. Because `compact` is unreachable at any duration this build actually generates (see "Scope
   boundary"), measuring its natural height directly requires a temporary harness: either (a) a
   `--dart-define`-gated debug affordance that forces one break row to render at `compact` density
   regardless of slot (mirroring the `/gsd-spike` `--dart-define` pattern from
   `.planning/spikes/001-live-row-in-a-true-grid/`), or (b) render `ChunkCard` at `compact` density
   standalone (unconstrained height) in a throwaway debug route and pixel-measure it there. Either
   is acceptable; record which was used.
7. Pixel-count the compact tier's rendered height (dashed border's outer extent), the same
   band-detection method `measure_card_fill.py` uses (crib from
   `.planning/phases/27-true-grid/tools/`).
8. Set `kSubCompactBreakMinHeight` to that measured height **rounded up** to the nearest 4dp (this
   is a "does it fit" threshold, not a "does it look good" one — round toward the safer, larger
   value rather than adding a separate explicit safety margin on top of a rounding step).
9. Separately confirm the sub-compact tier's own natural height (drive to a live-adjacent short
   break, 5 min) stays comfortably under its 20dp slot — if it doesn't, tighten the tier itself
   (this constant does not gate the sub-compact tier's own fit, only the cutover point away from
   `compact`).
10. Run `measure_hours.py` (or equivalent) against a screenshot taken with the sub-compact tier
    rendering — confirm it still prints `UNIFORM`. This is the SEEBREAK-02 proof in pixels, not
    just arithmetic (mirrors Phase 27's own closing verification step).

**What would invalidate this value:** any change to the `compact` break tier's own margin,
padding, border stroke, or `bodySmall` typography; any global text-scale change. Re-measure with
the recipe above — never from `flutter test`.

## Verification obligation — the work chunk's own 26dp overflow (ROADMAP item 4)

`SEED-005`'s table also flagged a 25-minute work chunk clipping 26dp inside its 100dp slot (126dp
natural vs. 100dp slot). **This document's expectation, stated so the plan doesn't have to
re-derive it from scratch, but not treated as settled without the real-browser check below:**

- `timeline_geometry.dart`'s own `kPixelsPerMinute` doc comment already records a **real-browser**
  measurement of the `full`-tier work card (the tier actually selected at a 100dp slot, since
  `100 >= kFullTierMinHeight` (88)) at **70dp + 8dp Card margin = 78dp**, comfortably inside the
  100dp slot with ~22dp of slack — measured via headless Chromium against the compacted `full`
  tier, 2026-08-18.
- `SEED-005`'s 126dp figure is very likely the **`flutter test` placeholder-font harness bound**
  the project's own carry-forward invariant warns about (STATE.md: "flutter test's placeholder
  font inflates glyph metrics ... a harness bound, not a device requirement"), not a real-device
  measurement — its own caveat section says exactly this ("52dp and 126dp are harness bounds").
- **Default expectation: this is a harness artifact, not a real defect, and needs no code
  change.** But this is a *default*, not a dismissal — the plan's real-browser step (already
  required above for `kSubCompactBreakMinHeight`) must include a screenshot of a standard 25-minute
  work chunk and confirm its rendered height stays inside its 100dp slot with no `ClipRect`
  clipping visible. Record the measured number in the plan's summary either way. If the real
  number contradicts this expectation and shows genuine on-device clipping, that is a defect this
  phase must still fix (padding/typography, not a slot-height change) — do not silently accept a
  contradicting measurement just because this document predicted otherwise.

## Spacing Scale

Reuses `26-UI-SPEC.md`'s declared 8-pt scale without modification. This phase's additions:

| Token | Value | Usage |
|-------|-------|-------|
| (reused, on-scale) | 0px | Sub-compact tier's outer margin (explicit exception, justified above) and label padding-vertical |
| (reused `sm`) | 8px | Sub-compact tier's label horizontal padding (between divider and text) |
| (existing) | 1px | Divider stroke thickness/height — not a spacing token, a border-width value, unchanged from the compact tier's own 1dp stroke |

**One declared exception, stated explicitly per this project's spacing-scale discipline:** the
sub-compact tier's `margin` is `0` on **all four sides** (unlike `LiveRowCard`'s single-line tier,
which is `0` vertically only because it has no `TimelineRowTile` to supply horizontal inset — this
row *does* render through `TimelineRowTile`, so horizontal `0` margin is correct here, not the
regression class `PD-27-01` corrected). `0` is a valid point on the 8-pt scale (trivially a
multiple of 4), not a sub-4dp violation — same standing as every prior "margin/padding drops to
`0dp`" exception in this codebase's density-tier history.

No other exceptions.

## Verification — pixels, and a human, not `flutter test` alone

Restated from `29-CONTEXT.md`'s locked constraints, because the checker/executor consumes this
document directly:

1. **`flutter test`'s placeholder font cannot validate legibility.** It can validate the
   grid-accuracy invariant (SEEBREAK-02: `heightFor(start, duration) == duration * kPixelsPerMinute`
   for a chunk at every density) — that is pure arithmetic and IS trustworthy in a widget test, per
   this project's carry-forward invariant. It CANNOT validate that the sub-compact tier's text is
   legible or that the compact→sub-compact cutover threshold is right — those need pixels from a
   real browser, using the recipe above.
2. **A new regression test belongs in the suite regardless:** every break, at every density,
   renders inside a `Positioned` whose `height` equals `durationMinutes * kPixelsPerMinute` — no
   density branch may special-case the box height. (Test authorship is the planner/executor's job;
   named here because it is the concrete, non-negotiable proof SEEBREAK-02 holds.)
3. **This phase MUST end in a `checkpoint:human-verify` task — no automated pass substitutes for
   it** (`29-CONTEXT.md`, restated from the ROADMAP). Precedent: Phase 27 scored 16/17 automated and
   still failed 2 of 3 items on the human check (36dp touch targets; the now-line striking through
   text) — both had passed everything automated. The plan must include a task where a human opens
   the served debug build and confirms, by eye, that a 5-minute break reads as *a break* and not a
   divider — this document's whole purpose is to make that human check meaningful, not to replace
   it.
