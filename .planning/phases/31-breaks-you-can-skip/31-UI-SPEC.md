## D-31-01 — Swipe direction(s) for a break

**Decision: one-directional. `DismissDirection.endToStart` only (left swipe = skip). No
`startToEnd`/complete direction for any break, at any density.**

**Reasoning:**

- "Complete a break" is not a meaningful action under this codebase's own established framing:
  D-06 (`26-UI-SPEC.md`, carried forward unmodified) already states breaks "are not achievements" —
  no bold title, no emoji, no celebratory check icon. `markComplete` is never called for a break
  today and this phase does not start calling it. `chunk.isCompleted` stays permanently `false` for
  every break chunk — this is a locked invariant, not an oversight (see the regression-test
  obligation in "Verification" below).
- One-directional swipe also keeps the **whole timeline's gesture vocabulary singular and
  learnable**: a left swipe means the same thing everywhere — "I'm done attending to this, move
  past it" — whether the row is a work chunk (skip) or a break (skip). Only work chunks
  additionally support a right swipe (complete), which is a distinct, opt-in achievement concept
  that never applies to a break. A user does not have to learn a break-specific gesture map.
- `Dismissible.background` is supplied (shown while dragging), `secondaryBackground` is omitted —
  Flutter's `Dismissible` requires only the widget for the direction(s) actually enabled.

**Resolved chunks stay non-re-swipeable, exactly like work chunks:**
`direction: (chunk.isCompleted || chunk.isSkipped) ? DismissDirection.none : DismissDirection.endToStart`
(the `isCompleted` check is defensive/future-proofing only — see above, it can never be true for a
break under this phase's scope).

## D-31-02 — The 20dp grab target

**The problem, restated precisely.** A 5-minute break's rendered slot is
`5 × kPixelsPerMinute = 20.0dp` (unchanged, `timeline_geometry.dart`). iOS's minimum touch target is
44pt; Material's is 48dp. A drag gesture must be *initiated* by a touch-down whose contact point
lands inside the target widget's hit-test area — 20dp is roughly the width of a fingertip's contact
patch, not a safe margin around it. **The grid is not negotiable (SEEBREAK-02/D-03): the rendered
slot cannot change.** The fix has to widen where a touch is *accepted*, not what is *painted*.

### The mechanism

**A break's touch-target (the `Dismissible`'s own hit-test box) is grown taller than its painted
slot. Everything that actually paints — the card content, the swipe-reveal background/icon — stays
confined to exactly `slot` height, vertically centered inside the larger invisible box.**

Concretely, for a break chunk whose `slot < kMinBreakDragTarget` (new constant, see below):

```
topSlop    = clamp(kBreakHitSlop, 0, precedingRowSlot / 2)   // 0 if no preceding row
bottomSlop = clamp(kBreakHitSlop, 0, followingRowSlot / 2)   // 0 if no following row

Positioned(
  top: geometry.yFor(start) - topSlop,
  left: 0,
  right: 0,
  height: slot + topSlop + bottomSlop,      // the Dismissible's OWN size — this is the hit-test box
  child: Dismissible(
    key: ValueKey(chunk.id),
    direction: resolved ? DismissDirection.none : DismissDirection.endToStart,
    confirmDismiss: (_) async { await notifier.markSkipped(chunk.id); ...; return false; },
    background: _confinedToSlot(slot, _skipReveal(context)),   // Align(center) + SizedBox(height: slot)
    child: _confinedToSlot(
      slot,
      ClipRect(child: OverflowBox(
        alignment: Alignment.topCenter, minHeight: 0, maxHeight: double.infinity,
        child: TimelineRowTile(child: _buildChunkCard(context, chunk, density)),
      )),
    ),
  ),
)
```

Where `_confinedToSlot(slot, child) = Align(alignment: Alignment.center, child: SizedBox(height: slot, child: child))`.

**New constants (`timeline_geometry.dart`, colocated with the existing density-threshold cluster,
per the file's own "one file owns every Today-timeline threshold" convention):**

| Constant | Value | What it means |
|---|---|---|
| `kBreakHitSlop` | `16.0` | Extra invisible hit-test reach added above **and** below a break's own slot, before any clamp. On-grid (multiple of 4). |
| `kMinBreakDragTarget` | `48.0` | Slop is applied only while `slot < kMinBreakDragTarget` — a break already at or above this height needs no help (its own slot already clears both Material's 48dp and iOS's 44pt). |

**Resulting effective touch-target heights:**

| Break | Slot | Slop applied? | Effective hit-test height |
|---|---|---|---|
| Short break, 5 min | 20dp | yes (20 < 48) | 20 + 16 + 16 = **52dp** — clears Material (48dp) and iOS (44pt) |
| Long break, 30 min | 120dp | no (120 ≥ 48) | 120dp — unchanged, already generous |
| Hypothetical compact-tier break (32–88dp, unreachable under today's lattice) | e.g. 60dp | no (60 ≥ 48) | 60dp — already clears both minimums |

Only the 5-minute break is affected in practice, matching Phase 29's own finding that the
sub-compact tier is the one live case.

### Why this does not steal touches from the work chunks above and below — the crux, answered explicitly

**The claim: extending a break's hit-test box by up to 16dp into the vertical space nominally
"belonging" to the adjacent work-chunk rows above and below cannot capture a touch that the
neighboring row's own gesture layer would otherwise have received — because that space is not
reachable by the neighbor's own gesture layer *at all*, today, regardless of this phase.**

The proof rests on a mechanism this codebase already has in place for every non-live row (PD-10,
`today_screen.dart`, unchanged by this phase): **every row is wrapped in its own
`ClipRect`**, sized to exactly `Positioned(height: slot)`. `ClipRect` clips both paint *and*
hit-testing by default (`RenderClipRect.hitTest` rejects any position outside its own clip rect
before it ever delegates to its child) — this is why `OverflowBox` is safe to use for oversized
content in the first place: content can lay out taller than its slot, but nothing outside `[top,
top+slot)` can ever be painted *or touched*, including by `Dismissible`'s own internal gesture
detector, which is `HitTestBehavior.opaque` and would otherwise happily claim its whole box.
Because rows are laid out **back-to-back with zero gap** (`TimelineGeometry.yFor`/`heightFor` are
exactly additive, confirmed for every chunk on the lattice), a work chunk's own `ClipRect` ends
**exactly** at the pixel where the next break's slot begins — there is no shared "margin" band two
rows both think they own; the boundary is a hard, zero-width line, and nothing on either side can be
hit-tested past it today.

So: a break's enlarged, *unclipped* hit-test box reaching `topSlop`/`bottomSlop` past its own slot
extends into pixel territory that the **neighbor's own `ClipRect` already makes permanently
unreachable to the neighbor** — not "usually unclaimed," but structurally, provably unclaimed,
independent of z-order, paint order, or Dismissible's own opacity setting. There is nothing for the
break's expanded hit region to compete with. The only other widget kind that could occupy that space
(`GapFreeRow`/`LeadingFreeRow`, rendered when there's a true schedule gap) carries no gesture
detector at all (`FreeTimeRow` is a static informational row — confirmed by inspection, zero
`GestureDetector`/`Dismissible` in `free_time_row.dart`), so slop reaching into a free-time row is
equally inert there.

**What would invalidate this:** anything that removes the per-row `ClipRect` (PD-10's safety net,
load-bearing for this proof, not just for content overflow); anything that gives `FreeTimeRow` its
own gesture handling; or a chunk shorter than `2 × kBreakHitSlop` immediately adjacent to a break
(defensive clamp above already halves `kBreakHitSlop` against a short neighbor's own slot, but a
neighbor under 32dp — not producible by today's lattice, which sandwiches every break between
25-minute-or-longer work chunks — would need re-checking by hand).

**What this does NOT solve, and is deliberately left unsolved:** whether a real thumb's touch
centroid reliably lands inside a 52dp *invisible* band it cannot see the edges of. That is exactly
the physical question the ROADMAP says no assertion settles — it is what the mandatory human UAT
checkpoint (below) exists to answer. This document's job is to make the *geometric* claim airtight
(no theft, target cleared) and be honest about the *human* claim it cannot make from a desk.

**Deliberately not used: a lower `dismissThresholds` completion distance.** The ROADMAP names this
as a second available lever ("a lower drag threshold for short rows"). It is not needed: a break's
`Dismissible` spans the same full row width work chunks already use (`left: 0, right: 0`,
unaffected by the height-only hit-slop fix above), so the *horizontal travel distance* required to
complete a swipe once started is identical to what already ships and works for every work chunk
today. There is no a priori reason to expect that axis needs help, and changing it would be an
unforced, unevidenced deviation from the existing gesture feel. If the human UAT finds otherwise,
record it and revisit — do not pre-emptively tune a threshold with no evidence it's wrong (this
project's own measure-first discipline, `kSubCompactBreakMinHeight`/`kPixelsPerMinute` history).

### Hit-test envelope vs. rendered height — why SEEBREAK-02/SKIPBREAK-02 both hold

SKIPBREAK-02 and SEEBREAK-02 both say **rendered height** must equal `durationMinutes ×
kPixelsPerMinute` exactly. The mechanism above makes the outer `Positioned` (and therefore
`Dismissible`'s own `size`) taller than that for a short break — but nothing paints in the extra
space. `Align(center) + SizedBox(height: slot)` confines *every* visible thing — the card/hairline
content, and the swipe-reveal `background` — to a band exactly `slot` tall, vertically centered
inside the larger invisible box. "Rendered height," read as *what a person sees painted on screen*,
is unchanged: still exactly `duration × kPixelsPerMinute`, at rest and mid-drag alike. The
touch-target enlargement is a hit-test-only concept with no visual footprint — this distinction must
be preserved by the regression test (see "Verification"): assert the *painted* extent stays
duration-exact (existing SEEBREAK-02 test, unmodified) as a **separate** assertion from a **new**
one proving a touch inside the slop band is still accepted by the break's `Dismissible`.

### Where this lives in the code

- **`today_screen.dart`**'s break arm of `_buildPositionedRow` (today: `Positioned(height: slot,
  child: ClipRect(child: OverflowBox(...)))`, unconditionally) gains the slop-aware envelope above,
  computed from the already-available ordered row list (to derive `precedingRowSlot`/
  `followingRowSlot` for the defensive clamp). The **work-chunk arm is untouched** — no slop, no
  restructuring; every work chunk's slot is already ≥88dp (`kFullTierMinHeight`) under today's
  evidence, well above both touch-target minimums. (A commitment-anchored work chunk is not
  *structurally* guaranteed ≥88dp — `29-UI-SPEC.md`'s "Scope boundary" already flagged this as
  theoretically possible and out of that phase's evidence-scope; it stays out of this phase's scope
  for the identical reason — no reported defect, no measurement evidence, do not silently widen.)
- **`swipeable_chunk_card.dart`** loses its `chunk.chunkType != ChunkType.work` early return (that
  return, and its doc comment "Break chunks are returned as plain ChunkCards without swipe
  wrapping," are what this phase supersedes). It gains a break-specific `Dismissible` branch:
  `direction: endToStart` only, `background:` = the skip reveal (below), no `secondaryBackground`.
  It also needs a way to confine its own painted content to a caller-supplied height distinct from
  its own layout box, for the break case — an additive `visualHeight` parameter (default `null` =
  "size to whatever the parent gives me," preserving every existing call site byte-for-byte) that,
  when set, wraps `child`/`background` each in `Align(center) + SizedBox(height: visualHeight)`
  before their own `ClipRect`/`OverflowBox`. Planning may instead choose to keep this confinement
  logic entirely in `today_screen.dart` and leave `SwipeableChunkCard` unaware of slop — either
  split is acceptable; the requirement is only that the confinement wraps `child` **and**
  `background` independently (Dismissible does not share one wrapper across both).

### The skip-reveal background

Reuses the exact visual vocabulary the work-chunk skip reveal already established
(`swipeable_chunk_card.dart`'s `secondaryBackground`): `colorScheme.error` fill,
`colorScheme.onError` icon tint, `Icons.arrow_forward`, right-aligned. One deliberate, justified
deviation: the icon is sized to fit inside the confined `slot` band rather than the fixed `28`
work chunks use, since a 5-minute break's `slot` (20dp) is shorter than a 28dp icon. **Icon size:
`min(20.0, slot - 4.0)` clamped to a minimum of `12.0`** — at `slot = 20dp` this gives a `16dp`
icon (comfortably inside with padding either side); at `slot ≥ 24dp` (every other tier) it reaches
the full `20dp`, still smaller than the work-chunk 28dp because a break's content is already the
smallest/quietest element on the timeline (D-06) and the reveal should not out-weigh it.

## D-31-03 — What skipping a break means

**Locked (per `31-CONTEXT.md`): "mark it skipped and move on."** `markSkipped` already does exactly
this and is already fully type-agnostic — confirmed by reading `schedule_notifier.dart:678-739`:
it sets `chunk.isSkipped = true`, saves, appends a `CompletionLog`, and its streak write-back is
guarded by `chunk.goalId != null && chunk.goalId!.isNotEmpty` — a break's `goalId` is always `null`
(`scheduled_chunk.dart:8`, "Break types have null goalId"), so that guard is provably inert for
every break. **No engine change needed for this decision itself** — it is a UI-wiring change only
(D-31-01/02 above are the whole of what's required to make `markSkipped` reachable from a break
row).

**On screen, this means:** skipping a break changes nothing about the timeline's shape. The break's
row stays exactly where it was, at its original `displayStartMinutes`/`durationMinutes`, rendered
with the skipped visual treatment (D-31-04). Every other chunk's start time is untouched —
`markSkipped` never writes to any chunk other than the one passed in. The next work chunk still
starts exactly when it always did. This is the "counter-intuitive but honest" reading the ROADMAP
names, and this document's only job regarding it is to confirm the UI does not *imply* otherwise —
no animation, no collapse, no re-flow of the rows below a skipped break. It just changes state in
place, identically to how a skipped work chunk already behaves today.

## D-31-05 — A guard gap this phase's own decision surfaces (new finding, in-scope per the ROADMAP's own instruction)

The ROADMAP explicitly instructs: *"`_absorbReclaimedTimeIntoNextBreak` (Phase 23 G-05) already
moves a break when work finishes early — read it before designing, so the two behaviours do not
contradict each other."* Reading it (`schedule_notifier.dart:529-592`) surfaces a real interaction
this phase's own D-31-03 decision newly makes reachable:

**The bug.** `_absorbReclaimedTimeIntoNextBreak` runs on every `markComplete` call for a work chunk,
looks up the immediately-following chunk by clock order, and — if it is a break whose window has
not yet opened (`Guard 7: nowMinutes >= breakStart → null`) — moves its start to `now` and extends
its duration to preserve its original end. **None of its eight guards check `next.isSkipped`.**
Before this phase, that gap was inert: no break could ever be `isSkipped == true`, so the code path
that would resurrect one never fired. After this phase ships, it becomes reachable: skip break B,
then later complete the immediately-*preceding* work chunk early, and G-05 will move/extend break
B's `syntheticStartMinutes`/`durationMinutes` **out from under its own skipped state** — the row
would still render with `isSkipped: true` styling (D-31-04), but its position and duration would
silently change, contradicting "mark it skipped and move on" (D-31-03) and misleading anyone reading
the chunk's own persisted fields later (e.g., a future streak/history view).

**Fix, minimal and in-scope:** add one guard to `_absorbReclaimedTimeIntoNextBreak`, alongside the
existing eight — `if (next.isSkipped) return null;` — placed with Guard 5/6 (the break-eligibility
checks), before the window-open check. This is a one-line, narrowly-scoped correction to an
*existing* function's guard completeness, not an engine redesign, and it is exactly what the
ROADMAP's own instruction was asking planning to check for. Flag prominently for the plan — this is
an `lib/providers/schedule_notifier.dart` change, not a UI file, but it is required for D-31-03 to
hold once breaks are skippable.

**A regression test is required**: complete a work chunk early with an *already-skipped* following
break present, and assert the break's `syntheticStartMinutes`/`durationMinutes` are unchanged (and
`isSkipped` stays `true`) after the completion. Pair it with the existing G-05 test (an *unresolved*
following break still absorbs correctly) so the guard's addition is proven not to break the original
behavior.

## D-31-04 — Skipped-break rendering, every density

**Because a break can only ever be `unresolved` or `isSkipped` (D-31-01: never `isCompleted`), there
is no ambiguity to render — a muted/struck-through break is unambiguously "skipped," no separate
icon or word is structurally required to disambiguate from a "completed" state that cannot occur.**
This simplifies the design to reusing exactly the vocabulary this codebase already has for a
resolved *work* chunk, rather than inventing a break-specific one.

| Element | Existing work-chunk precedent | Applied to breaks (this phase) |
|---|---|---|
| Whole-row muting | `Opacity(contentOpacity)`, `contentOpacity = isResolved ? 0.5 : 1.0` (`_WorkChunkContent.build`) | **Same `0.5` value, same mechanism** — wraps the break's entire rendered content (icon + title + trailing text at `full`/`detailed`; the dashed box at `compact`; the divider+label at `sub-compact`) when `chunk.isSkipped` |
| Title decoration | `titleStyle.decoration = isResolved ? TextDecoration.lineThrough : null` (`_buildContentShell`) | **Same decoration, same trigger** (`chunk.isSkipped` — a break is never `isCompleted`, so this is equivalent to work chunks' `isResolved` in practice) — applied to the break's title text (`'Short break'`/`'Long break'`, text content unchanged, only the decoration flag changes) at **every** tier including sub-compact |
| Trailing status swap | `_buildTrailingStatus`: `Text('skipped', bodySmall onSurfaceVariant)` replacing the unchecked-radio icon | **`full`/`detailed` tier only** (the only tier with a dedicated trailing text slot): the existing `'${chunk.durationMinutes} min'` trailing text is replaced by the literal string `'skipped'` (lowercase, verbatim reuse of the exact existing work-chunk string — not a new copy decision) when `chunk.isSkipped`. `compact`/`sub-compact` have no spare width for a second text element — D-02 forbids growing the box to make room, so they rely on opacity + strikethrough alone (see legibility note below) |

**Per-tier implementation:**

- **Full / detailed** (`_buildBreak`'s bottom branch): wrap the existing `Row` (icon + title +
  `Spacer` + trailing text) in `Opacity(opacity: chunk.isSkipped ? 0.5 : 1.0)`; add
  `decoration: chunk.isSkipped ? TextDecoration.lineThrough : null` to `titleStyle`; change the
  trailing `Text('${chunk.durationMinutes} min')` to
  `Text(chunk.isSkipped ? 'skipped' : '${chunk.durationMinutes} min')`. The existing
  `if (chunk.isCompleted) ... check_circle` branch is untouched (dead for breaks, per D-31-01, kept
  for the same reason Phase 29 kept the dead `compact` break tier — a future change could reach it).
- **Compact**: wrap the existing `CustomPaint(dashed border)` in
  `Opacity(opacity: chunk.isSkipped ? 0.5 : 1.0)`; add the same `lineThrough` decoration to its
  `Text(title)`. No trailing element added (no room without restructuring the tier's `Center`, which
  risks reopening the exact clipping defect Phase 29 fixed at this size). **Add an explicit
  `Semantics(label: '$title, ${chunk.durationMinutes} min${chunk.isSkipped ? ", skipped" : ""}')`**
  wrapper here — today this tier has no Semantics wrapper at all, and strikethrough/opacity convey
  nothing to a screen reader, so without this the compact tier's skipped state would be silently
  inaccessible.
- **Sub-compact** (`_SubCompactRow`): add an `isSkipped` parameter (`bool`, default `false` so no
  existing call site changes); when `true`, wrap the `Row` in `Opacity(opacity: 0.5)` and add
  `decoration: TextDecoration.lineThrough` to the label `Text`. Update the `semanticsLabel` the
  caller passes to append `', skipped'` when applicable
  (`'$title, ${chunk.durationMinutes} min, skipped'`), mirroring the tier's existing pattern of the
  spoken label restating what the visible content drops or, here, adds silently via decoration
  alone.

**Legibility flag for the mandatory real-browser step (not a new step — folds into the one already
required by D-31-02's human UAT):** sub-compact's divider/label already render at
`colorScheme.outlineVariant`/`onSurfaceVariant` — comparatively low-contrast tones already. Halving
opacity again at this tier is a plausible legibility risk this document cannot settle from a desk.
**Default: apply `0.5` uniformly across all three tiers for consistency** ("reads as a smaller
sibling of the same family," `29-UI-SPEC.md`'s own framing, applied to state as well as size now).
**If the human UAT finds sub-compact's skipped state unreadable at `0.5`, raise the opacity for that
tier only** (document the new value and why, following this file's own `kBreakHitSlop`-style
"decide, verify, correct if wrong" posture) — do not silently pre-empt this without evidence either
way.

## Spacing Scale

Reuses the existing 8-pt scale (`26`–`29-UI-SPEC.md`) without modification, plus one new
interaction-geometry constant:

| Token | Value | Usage |
|-------|-------|-------|
| `kBreakHitSlop` | 16px | Invisible hit-test extension above/below a sub-48dp break's own slot (D-31-02). On-grid (4 × 4). Not a visual/paint value — see "Hit-test envelope vs. rendered height" above for why this does not count as a spacing exception in the visual sense. |
| (reused) | 4px | Icon padding around the confined skip-reveal icon (`min(20, slot-4)` clamp) |

No paint-affecting spacing exceptions. `kBreakHitSlop` is the one genuinely new token this phase
introduces, and it governs gesture geometry, not layout.

## Typography

No new type roles, no new weights. Reuses `bodySmall` (sub-compact/compact label),
`bodyMedium`/`titleMedium` (full/detailed, per `isLong`) exactly as `26`–`29-UI-SPEC.md` already
declared. This phase's only typographic addition is a **decoration flag**
(`TextDecoration.lineThrough`), not a new size/weight/role — applied conditionally on
`chunk.isSkipped`, reusing the identical mechanism `_WorkChunkContent` already uses for its own
resolved state.

| Role | Size | Weight | New this phase |
|------|------|--------|-----------------|
| Break label, unresolved | 12–16px (tier-dependent, unchanged) | 400 / 500 (long, unchanged) | — |
| Break label, skipped | same size/weight as unresolved | same | `+ TextDecoration.lineThrough` |
| Trailing "skipped" text (full/detailed only) | 12px (`bodySmall`, matches `_buildTrailingStatus`'s existing string) | 400 | new string content, reused style |

Stays within the project's existing 2-weight maximum (400 body, 600 emphasis is used elsewhere but
not introduced here) — this phase adds a decoration, not a weight.

### E1 — break swipe-to-skip gesture

| Category | Status | Resolution / Reason |

| loading | ✅ resolved (explicit) | **No loading affordance is introduced.** `confirmDismiss` returns `false` so the row springs back to rest immediately; `markSkipped`'s Hive write completes off the gesture path and the skipped rendering appears on the next `notifyListeners()`. **Acceptance:** no spinner, skeleton, or disabled state appears on the break-swipe path — identical to the shipped work-chunk swipe. |
| error | ✅ resolved (explicit) | Reuses `markSkipped`'s existing WR-05 revert-and-rethrow verbatim (`schedule_notifier.dart:727-738`). **Acceptance:** with a throwing repository, `chunk.isSkipped` is left `false` and the row renders unresolved — no half-applied state. ## Verification — pixels, hit-testing, and a human, not `flutter test` alone

1. **SEEBREAK-02/SKIPBREAK-02 stay provable in `flutter test`, as pure arithmetic**, and this is a
   *separate* assertion from the new hit-test claim (do not conflate them in one test): every break,
   at every density and every resolved state, renders inside a `Positioned` whose **painted**
   content — not the enlarged `Dismissible` box — occupies exactly `durationMinutes ×
   kPixelsPerMinute`. Assert this against the confined `SizedBox(height: slot)` wrapper's own size,
   not against the outer `Positioned`'s height (which is deliberately taller for a sub-48dp break —
   asserting the outer height would be asserting the wrong thing and could falsely fail a correct
   implementation, or falsely pass a broken one that grows the *visible* box instead).
2. **A new widget test proves the hit-test claim in `flutter test`**: a synthetic drag started at a
   y-offset up to `kBreakHitSlop` beyond a sub-48dp break's painted top/bottom edge still resolves
   to that break's `Dismissible` and calls `markSkipped`. Pair it with a negative test: a drag
   started well inside the *neighbor's* own painted content (not in the slop band) still resolves to
   the neighbor, proving no theft in the one case `flutter test`'s exact-coordinate synthetic
   gestures actually can settle.
3. **`flutter test` cannot settle whether a real thumb's touch centroid reliably lands in an
   *invisible* 52dp band it cannot see the edges of.** This is exactly the class of thing this
   project's `CLAUDE.md`/ROADMAP calls out repeatedly (Phase 27's 16/17-automated-then-2/3-human-
   failed precedent). **This phase MUST end in a `checkpoint:human-verify` task.** The human check
   must confirm, on a real touch device: (a) a thumb can reliably initiate and complete a skip swipe
   on a 5-minute break without also triggering the adjacent work chunk's own swipe; (b) the skipped
   visual state (D-31-04) is legible at every tier, sub-compact included; (c) skipping a break does
   not visibly move or resize anything else on the timeline (D-31-03).
4. **D-31-05's regression test is required** and is a `lib/providers/schedule_notifier.dart` /
   `test/providers/schedule_notifier_test.dart` concern, not a widget test — proven RED against the
   unfixed guard first, per this project's carry-forward "regression tests must be proven RED"
   invariant.
5. **Mandatory ⟳ Re-check-in step, per CLAUDE.md trap #4**, for any UAT step that judges a
   freshly-generated day's break placement or timing (D-31-03's "nothing else moves" claim) — an
   already-generated day is never regenerated on load, so this UAT's own instructions must include
   the re-check-in step explicitly, first, marked mandatory, the same as Phase 30's closing UAT did.
