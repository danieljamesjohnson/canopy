<objective>
Close **Gap 2** of the Phase 31 UAT: a break that is *currently running* has no skip affordance at
all. This was `PD-31-06` — a deliberate, recorded scope exclusion, surfaced to the owner unruled
rather than read as consent, then asked directly and **RULED on 2026-08-26 as D-31-07: fold it into
this gap closure. Skip only — never Complete.**

Purpose: it ships **with** the D-31-06 acquisition fix so a single re-run of the human UAT covers
both. It also removes the only reason verification truth #14 abstained. That truth (UI-SPEC E2 — a
live break composes the live-row treatment with the skipped treatment) went `insufficient_spec`
**solely because no code path existed to exercise it**; `LiveRowCard` had zero references to
`isSkipped`/`isCompleted`. Once a live break can be skipped, that excuse is gone. **It must not
re-abstain.**

Output: a live break that can be skipped at both live density tiers, that never offers Complete, and
a proven — not asserted — composition of the live and skipped treatments.

**A finding the executor must not paper over.** `LiveRowCard` picks its tier from `slotHeight`:
`_buildCompact` at or above `kCompactLiveMinHeight` (88.0), `_buildSingleLine` below it. A 30-minute
live long break is 120dp and gets the compact tier, so a Skip *button* reaches it. **A 5-minute live
short break is 20dp and gets the single-line tier, which renders no action buttons for any chunk
type** — and 5-minute breaks are the common case, arriving every 25 minutes. Flipping the
`showActions` gate alone therefore delivers nothing for the break the owner will actually meet. That
is why this plan does both: the button where a button fits, and the same left-swipe gesture the
owner already uses on non-live breaks where it does not.
</objective>

  owner's 2026-08-21 instruction is unchanged by D-31-07; `_buildLiveRow`'s existing
