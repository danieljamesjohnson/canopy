<objective>
Close the guard gap this phase's own decision makes reachable, and prove the two claims about
skipping a break that live below the UI: that it moves nothing else on the day, and that it
touches no habit data.

`_absorbReclaimedTimeIntoNextBreak` (Phase 23, G-05) moves and extends the following break when a
work chunk is completed early. None of its eight guards checks `next.isSkipped`. Before Phase 31
that was inert — no UI path could set a break's `isSkipped`. Plan 31-01 just built that path. From
now on, skipping a break and then completing the preceding work chunk early silently rewrites the
skipped break's start and duration underneath its own skipped rendering — which directly
contradicts D-31-03's "mark it skipped and move on."

Purpose: this is the one place where a UI-only phase has an engine consequence, and it is the
exact interaction the ROADMAP told planning to go and read for. One line fixes it; a test proven
red first is what makes the fix mean something.

Output: a ninth guard, two regression cases, a streak-inertness assertion, and captured RED
evidence.
</objective>
