<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-entered feed URL → network fetch | The user can point the app at any URL; the app must not follow a non-HTTPS one and must not log it |
| OS permission dialog → app | The OS owns the decision; the app owns explaining what a denial means |
| device-reported calendar names → UI | Free text of unbounded length from outside the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-35-12 | Information Disclosure | feed URL rendered as a `ListTile` title fallback | low | accept | The URL is the user's own and is shown only on their own device, on a screen they navigated to deliberately. It is ellipsized, and it is never logged (T-35-02) |
| T-35-13 | Spoofing | a non-HTTPS feed URL entered on the add form | medium | mitigate | Rejected at add time with the same inline validation error as an unreadable feed; the URL is not persisted |
| T-35-14 | Denial of Service | a device-reported calendar name of unbounded length | low | mitigate | `maxLines: 1` + ellipsis on every device-reported string; asserted by the 120-character overflow test |
| T-35-15 | Elevation of Privilege | the screen reaching a plugin directly and requesting write access | high | mitigate | The screen imports only `CalendarSource`, which declares no write verb; enforced by the plugin-import grep in Task 1's acceptance criteria (CAL-03) |
| T-35-SC | Tampering | package installs | high | accept | No package is added by this plan; the gate ran in 35-01 Task 1 |
</threat_model>
