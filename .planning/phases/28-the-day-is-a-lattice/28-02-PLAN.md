<objective>
Prove that the shape D-06 introduces — a 5-minute break immediately followed by a 30-minute break —
survives everything downstream of the generator, and prove it RED first.

Nothing in this codebase has ever seen two consecutive non-work chunks. `28-PATTERNS.md`'s exhaustive
grep found that no production file outside `schedule_generator.dart` reads `reservedBreakMinutes`, so
the risk is not a field consumer — it is code that assumes the emitted **sequence** never has two
adjacent breaks. `28-RESEARCH.md` Open Question 3 verified by code reading that the presentation
layer renders breaks generically, but explicitly flagged that this was never verified by actually
producing the shape, because it has never been possible.

Purpose: close that gap with an automated test rather than the "quick manual smoke check" the
research proposed. CONTEXT.md D-06 is explicit that this gets a real test.

Output: `test/screens/lattice_break_pair_test.dart`, failing against the unfixed engine.

**Intermediate state notice:** this plan leaves failing tests. Plan 28-03 turns them green. Do not
touch `lib/` here.

**No browser step.** 28-VALIDATION.md: "if a headless-Chromium measurement is proposed, that is a
planning error." This is a `flutter test` widget test — the harness renderer, no screenshots, no
pixel measurement of glyphs. Geometric assertions computed from arithmetic (`yFor`, `heightFor`) are
trustworthy in the test harness; text-driven measurements are not, per STATE.md's carried-forward
test-harness caveat — so assert positions and counts, never text widths.
</objective>

<lattice_arithmetic>
## The fixture that produces the pair, and what it produces

Use the existing `BREAK-01: mood=1` fixture shape (2 habits + 2 time-targets, `moodIndex: 1`,
`blocks: []`, `lighterDay: false`) — `28-PATTERNS.md` quotes it verbatim at lines 1842-1876 of
`test/services/schedule_generator_test.dart`, with the comment deriving why it yields exactly
4 discretionary work chunks (cap=4, habitCeiling=2, FILL-01 clamps each time-target to 1 chunk).

mood 1 → N=2, so chunks 2 and 4 are both cadence boundaries. Under the fixed engine the day is:

`W@480(25) SB@505(5) W@510(25) SB@535(5) LB@540(30) W@570(25) SB@595(5) W@600(25) SB@625(5) LB@630(30)`

Ten chunks, containing **two** short→long break pairs: one mid-day (indices 3,4) and one trailing
(indices 8,9). The mid-day pair is the interesting one for rendering — it has a work chunk after it.

Under the **unfixed** engine the same fixture yields 7 chunks with a single 25-minute long break at
index 3 that *replaces* the short break, so no adjacent break pair exists anywhere. That absence is
what makes this plan's tests RED.

Cell rule, for deriving anything else: an ordinary chunk emits work@S(25) + shortBreak@S+25(5) and
the next cell starts at S+30; a boundary chunk additionally emits longBreak@S+30(30) and the next
cell starts at S+60.
