<objective>
Replace `kCompactLiveMinHeight`'s honest estimate with a real-browser measurement, and prove
GRID-01 end-to-end in pixels rather than in arithmetic.

Purpose: this is the only part of the phase `flutter test` structurally cannot do. 240dp and 372dp
both satisfy all 560 existing tests. And this project has shipped a wrong harness-derived layout
constant three times — `kGutterWidth` 46→75→52, `kPixelsPerMinute` 4.0→5.5→4.0,
`kLiveRowReservedHeight` 240→232. `kCompactLiveMinHeight` is exactly that class of number and is
currently a deliberate placeholder. This plan makes it a measurement or the phase does not close.

Output: a measured constant with a house-style doc comment, a committed pixel-count script,
evidence screenshots, a `UNIFORM` verdict, and a human sign-off on the one thing pixels cannot
answer — whether a 36dp tap target is usable by a thumb.
</objective>

  screenshot in a viewer is not a measurement and will not be accepted here.

  thresholds in one file with no cross-reference is a future "which one is right?" bug. Either
  collapse them with a stated reason, or keep them separate with a doc comment saying why they are

  outcome that is not acceptable.

  boundary tests reference `kCompactLiveMinHeight` symbolically and should survive any value; if a
  fixture using a literal slot height flips tier, change the fixture.

  slot means reintroducing a live-row exception, which reopens GRID-01 (`27-UI-SPEC.md` step 8).
