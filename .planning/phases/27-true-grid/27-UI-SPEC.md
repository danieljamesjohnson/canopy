> Visual and interaction contract for Phase 27: True Grid (GRID-01, GRID-02).
> Agent-generated by `gsd-ui-researcher`. Discuss was skipped — the phase's one open design
> question (what the live row becomes once its slot stops growing) was already settled by

> the five hard constraints it implies, are treated as locked inputs here, not re-litigated. This
> document's job is the five things the spike deliberately left open (per `27-CONTEXT.md`'s
> `<specifics>` block) — the compact tier's minimum height, the progress bar, the now-line
> collision, the single-line tier's content, and long-title overflow.

## Architecture: the live row joins the grid (foundational — read first)

**What deletes.** `TimelineGeometry.liveExtraPx` — the field, the `forDay()` computation block
that derives it from `kLiveRowReservedHeight - liveDurationPx`, and the `offset += liveExtraPx`
branch inside `yFor()` — is removed outright, not zeroed. `yFor()` becomes purely
`(clamped - rangeStart) * kPixelsPerMinute + kTimelineEdgePadding`: linear, no branch, no
special case. `kLiveRowReservedHeight` becomes dead the moment that block is gone and is deleted
with it (its long amendment-history doc comment can move to this file's history or a commit
message — it does not need to survive as a comment attached to nothing).

`liveStartMinutes` / `liveEndMinutes` **stay** on `TimelineGeometry` — they are still load-bearing
for `26-UI-SPEC.md`'s G-03 now-line-chip suppression (the chip hides specifically while
`nowMinutes` falls inside the live row's span). That mechanism is untouched by this phase and
continues to work unmodified once `liveExtraPx` is gone, because it reads the start/end minutes
directly, never the extra-height term.

**What the live row's positioning becomes.** Today the live row is the one `ChunkRow` arm
rendered with no `height:`, deliberately, so `LiveRowCard` can swell to its content-driven size.
That branch is deleted. The live row now goes through the **same** path every ordinary row
already uses:

```
Positioned(
  top: geometry.yFor(start),
  left: 0, right: 0,
  height: geometry.heightFor(start, chunk.durationMinutes),   // duration-exact, no exception
  child: ClipRect(
    child: OverflowBox(
      alignment: Alignment.topCenter,
      minHeight: 0, maxHeight: double.infinity,
      child: LiveRowCard(..., slotHeight: <that same height>),
    ),
  ),
)
```

`LiveRowCard` gains a `slotHeight` parameter (non-null in every real call site — there is no
longer a "swelled, unconstrained" code path to fall back to; the old unconstrained `build()`
branch is deleted along with `slotHeight == null`, not kept as dead code). `slotHeight` picks one
of exactly two tiers, below. `OverflowBox`'s `alignment: Alignment.topCenter` means a tier's
content stays pinned to the top of its slot — if a slot is taller than a tier's natural content
(e.g. an unusually long live work chunk), the card simply leaves blank `primaryContainer`-colored
space below it inside its own `Card`, the same way an ordinary `ChunkCard` Full tier does today.
It never clips *upward* into a taller slot — clipping is only a risk when natural content height
exceeds the slot, which is exactly what the two thresholds below exist to prevent.

**Consequence for tests.** `test/screens/today_timeline_model_test.dart`'s G-02 test (pins
`kLiveRowReservedHeight` to `[measured, measured+16]`) tests a constant that no longer exists and
must be deleted, not adapted. The roadmap's closing requirement — a new equidistance test
asserting `yFor(h+60) - yFor(h)` is constant across every hour boundary with a live chunk present
— is the test that replaces it as this phase's actual regression coverage. (Test authorship is
the planner/executor's job; named here because it is the concrete, non-negotiable proof that
GRID-01 holds.)

## The live row's two density tiers (GRID-02) — answers open questions 1, 2, 4, 5

**One rule, mirroring `26-UI-SPEC.md`'s existing rule for ordinary `ChunkCard`s exactly:**
slot height picks the tier. Not chunk type, not whether the chunk is a work block or a break —
purely `slotHeight`. A live long break at its 100dp slot renders the same tier a live 25-minute
work chunk does; a live short break at 20dp renders the same tier a live 12-minute work chunk
would. This is deliberate: `kFullTierMinHeight` already established this exact pattern for
non-live rows, and the spike's own finding was that the live row had simply been the one row
exempt from a rule the rest of the timeline already followed — obeying it is a simplification,
not a new mechanism.

There are **exactly two tiers.** There is no third, "squeezed" tier for the band between them —
this directly answers open question 1's "what happens to live chunks that fall in the band."
Anything at or above the compact threshold gets the compact tier; anything below it, all the way
down to the shortest generated chunk (a 5-minute break, 20dp), gets the single-line tier. A live
work chunk shorter than the compact threshold (rare — the schedule generator's default is 25
minutes — but not structurally prevented) simply renders single-line, same as a short break. This
mirrors `26-UI-SPEC.md`'s own stance on its rare Compact tier for ordinary work chunks: "the rule
must exist because nothing in this codebase currently guarantees a work chunk can't be shorter."

| Tier | Trigger | Natural height | Status |
|------|---------|-----------------|--------|
| **Compact** | `slotHeight >= kCompactLiveMinHeight` | **TARGET ~88dp — MUST be re-measured, see recipe below** | Not yet measured for this exact design (progress bar dropped, margin corrected — invalidates the spike's 90dp number, which measured a different layout) |
| **Single-line** | `slotHeight < kCompactLiveMinHeight` | **measured 19px in the spike**, real browser, unchanged layout intent (margin further reduced here, so ≤19px) | Spike number transfers; re-verify per recipe, low risk |

### Compact tier (open questions 1, 2, 5)

Layout, top to bottom, inside a `Card`:

1. **Row: kicker+title column (Expanded) + action icons (trailing, fixed width).**
   - Kicker: unchanged copy/style from the shipped card — `kicker.toUpperCase()` (e.g. `"RIGHT
     NOW"`), `labelSmall` (12px/400 base), weight overridden to 600, `onPrimaryContainer` at 72%
     opacity, letter-spacing 0.5. **One line, `TextOverflow.ellipsis`** (was already one line).
   - Title: **`titleMedium` (16px), weight 600** — a deliberate *size* reduction from the shipped
     card's `headlineSmall`, the same compaction move already applied to `ChunkCard`'s own `full`
     tier per `timeline_geometry.dart`'s "5.5 → 4.0" history, but the *weight* carries over
     unchanged at 600 rather than being bumped: `titleMedium`/600 is already `26-UI-SPEC.md`'s own
     locked "Heading" type role (its Typography table names it verbatim for "Full-tier work-chunk
     title; long-break title"), so this tier needs no weight override at all — it reuses an
     existing role rather than inventing one, and it matches the kicker's own 600, keeping the
     live row to a single emphasis weight (see Typography below). Full-opacity
     `onPrimaryContainer`. **One line, `TextOverflow.ellipsis`** — down from the shipped card's
     up-to-two-line wrap. This is a deliberate, accepted downgrade (open question 5): a compact
     card has no vertical budget for a second title line, and the trade is the same one
     `26-UI-SPEC.md` already made for ordinary `ChunkCard`s' Compact tier. No stacking-vs-sharing
     ambiguity: kicker and title are two **stacked** lines (kicker above title, 0dp gap between
     them — they read as one visual block), never on one shared line — matches the spike's shipped
     layout, which is correct as built.
   - Action icons (work chunks only, `showActions == chunk.chunkType == ChunkType.work`, matching
     the shipped `LiveRowCard`'s existing gate — unchanged): two bare `IconButton`s, **not** the
     shipped card's `FilledButton.icon`/`OutlinedButton.icon`. `Icons.check_circle_outline` tinted
     `colorScheme.primary` (Complete), `Icons.skip_next_outlined` tinted `colorScheme.error`
     (Skip) — same semantic color roles as every other Complete/Skip pair in the app, just
     icon-only chrome instead of a labelled button. Each constrained to **36×36dp**, `Tooltip`
     `'Complete'` / `'Skip'` (screen-reader accessible name, same pattern as the shipped card's
     buttons already have via their labels).
     **Declared spacing exception:** 36dp is below the 44dp WCAG-recommended touch target. This is
     a stated, deliberate trade, not an oversight — a 100dp slot carrying a two-line title block
     plus a countdown line cannot also fit two 44dp targets side by side without either the title
     or the countdown losing its line. Accepted for this phase, but **not accepted as permanently
     settled by this document alone** — flag it explicitly in this phase's UAT round (tap the
     Complete/Skip icons on an actual touch device, not just a mouse in a browser) rather than
     letting the exception go unverified past sign-off; if it turns out to be a real usability
     problem, the fix is more slot height (revisit `kPixelsPerMinute`), not shrinking the text
     further.
2. **Gap: 4dp** (`SizedBox(height: 4)`, on-scale).
3. **Remaining-time line.** Unchanged copy/style from the shipped card — `remainingLabel`,
   `bodySmall` (12px/400), `onPrimaryContainer` at 82% opacity, tabular figures. **One line,
   `TextOverflow.ellipsis`** (new — the shipped card had no overflow handling here because it had
   unlimited vertical room; a compact card needs one).
4. **No progress bar** (open question 2 — decided: **drop it**, not "consider dropping it").
   Reasoning, not just the roadmap's flag: once the card is duration-exact, the now-line's
   position *within* the card's vertical span **is** the fraction elapsed — the same fact the
   `LinearProgressIndicator` was re-rendering. `26-UI-SPEC.md`'s own now-line contract already
   makes the line the app's designated "where am I" answer ("the screen's primary visual anchor
   ... out-rank[s] everything else in the visual hierarchy"); keeping a second, redundant
   progress indicator inside the very card the line is designed to out-rank is exactly the
   duplication CAL-02 already argued against. Dropping it also buys back the vertical room open
   question 1 needs — estimated ~10dp, per the spike's own measurement of the bar's footprint
   (`SizedBox(height: 6)` + 4dp `minHeight` bar ≈ 10dp) — which is the single largest lever
   available for widening the compact threshold's clearance over a standard 25-minute chunk's
   100dp slot.

Card chrome: `margin: EdgeInsets.only(top: 4, bottom: 4, left: kCardLeftInset, right:
kTimelineRowInset)` — the **standard** Card-seam margin from `26-UI-SPEC.md`'s "Card seams"
section, not the spike's ad hoc `2/2`. This tier is the common case (every standard 25-minute
live chunk uses it), so it should look identical in spacing rhythm to every neighboring row, not
carry its own special-cased margin. `padding: EdgeInsets.symmetric(horizontal: 12, vertical: 8)`
— corrected from the spike's asymmetric `14/8/6/8` to a clean, symmetric, fully-on-scale value
(12 and 8 are both multiples of 4); the spike's asymmetry bought a few px of button breathing
room that isn't worth carrying into the contract as an unexplained irregularity. `Card` fill,
shape, elevation: unchanged from the shipped card — `colorScheme.primaryContainer`, square
corners (`BorderRadius.zero`), `elevation: 6`, `shadowColor: colorScheme.shadow` (prominence
carried entirely by these, per the hard constraint — never by height).

### Single-line tier (open questions 1, 4, 5)

For a live 5-minute break (20dp) and anything shorter than the compact threshold. One line of
text, nothing else:

```
Row(
  children: [
    Expanded(
      child: Text(title, maxLines: 1, overflow: TextOverflow.ellipsis, style: labelMedium/600),
    ),
    Text(' · $remainingLabel', maxLines: 1, style: labelMedium/600),  // never truncates
  ],
)
```

- **Copy (locked, new this phase):** `title` (the live chunk's own title/status string, e.g.
  `"Taking a break"`, `"Exercise"` — reuses `_liveTitle`, unchanged) followed by `" · "` and
  `remainingLabel` (e.g. `"3 min left · until 9:20 AM"`, unchanged). **The kicker
  (`"RIGHT NOW"`) is dropped entirely from the single-line tier** — there is no room for a third
  piece of information on one line, and the row's own fill/elevation/position under the now-line
  already carry the "this is happening right now" signal without needing to say it again in text.
- **Overflow priority (open question 5, extended):** the `Row`/`Expanded` split above is a
  deliberate departure from the spike's single `Text('$title · $remainingLabel', maxLines: 1,
  overflow: ellipsis)`, which ellipsizes the *whole* string from the end — meaning a long goal
  title could silently push the countdown (`remainingLabel`) off the visible row entirely, the one
  piece of information on this row a user cannot get anywhere else at a glance. Splitting into an
  `Expanded` title + a non-expanded, never-truncated remaining-time suffix guarantees the
  countdown is always fully visible; only the title (which the user already knows, since it names
  what they are doing right now) sacrifices characters when the two together don't fit.
- **Typography:** `labelMedium` (~12–14px depending on `TextTheme`), **weight 600** — the same
  single emphasis weight as the compact tier's kicker and title (not a third weight; see
  Typography below), `onPrimaryContainer` at **full opacity** (not the 72–82% alpha the compact
  tier's secondary lines use) — full contrast is deliberate here because this line is both the
  row's only content and, per the now-line collision decision below, the one most likely to have
  a 2dp rule drawn across it routinely; alpha'd text under a crossing line is a legibility risk
  this tier can't afford to take. Weight alone is not what carries this line's emphasis over the
  compact tier's secondary lines — full opacity does that work, so 600 (not a heavier weight) is
  sufficient here too.
- **Card chrome — explicit exception to the standard Card-seam margin:** `margin: EdgeInsets.zero`
  ~~(all four sides)~~ **VERTICALLY ONLY — corrected 2026-08-18, see PD-27-01 below**,
  `padding: EdgeInsets.symmetric(horizontal: 12, vertical: 0)`, text
  **vertically centered** in the `Card` via `Row`'s `crossAxisAlignment: CrossAxisAlignment.center`
  rather than pushed away from an edge by padding. This is not a new kind of exception — it is the
  **identical** move `26-UI-SPEC.md` already made for the ordinary break Compact tier ("Vertical
  padding drops to `0dp` ... the label is vertically centered inside the row's slot via alignment
  rather than pushed away from the dashed edge by padding, which is what a 20px-tall box needs
  anyway"). `0` is a valid point on the 8-pt scale; margin is zeroed here (rather than kept at the
  Card-seam standard 4dp/4dp) specifically because the smallest guaranteed slot (20dp, a 5-minute
  break) cannot spend 8dp of it on margin and still leave room for one legible text line — the
  visual seam between this row and its neighbors is preserved anyway, because the *adjacent* rows
  still carry their own 4dp margins (Flutter `Card` margins don't collapse, so the neighbor's
  margin alone supplies the visible gap).
- **Fill, shape, elevation:** same prominence markers as the compact tier —
  `colorScheme.primaryContainer`, square corners, `elevation: 4` (slightly less than the compact
  tier's 6, matching the spike's own choice — a 20dp strip doesn't need as much shadow spread to
  read as raised).
- **Accessibility (new — not in the spike, added here to close a gap the compaction opens):**
  because the visible string drops the `"RIGHT NOW"` kicker for space, a screen-reader user who
  only hears the rendered text loses the "this is current" framing the compact tier's kicker still
  gives. Wrap the row in `Semantics(label: 'Right now: $title, $remainingLabel', excludeSemantics:
  true)` — the same `excludeSemantics: true` pattern `26-UI-SPEC.md`'s `NowLineOverlay` already
  uses for exactly this reason (a narrower visible string than the meaning it needs to convey).
- **Tap target:** for a live **work** chunk that happens to render single-line (the rare
  short-work-chunk edge case — not the normal short-break case, which has no actions to begin
  with), the whole row opens `ChunkDetailSheet` on tap, which already carries Complete/Skip for
  any unresolved chunk. This mirrors `26-UI-SPEC.md`'s existing rule for ordinary `ChunkCard`
  Compact-tier work rows ("no inline action row ... reached via the row's own tap") and is what
  keeps the spike's "Complete/Skip reachable while live? yes" claim true even in the one state the
  spike didn't test (a short work chunk, rather than a short break, landing in the tight tier). A
  live **break** in the single-line tier keeps the existing, unchanged rule: no tap target at all
  (nothing to complete or inspect about a break — `26-UI-SPEC.md`'s own reasoning, carried forward
  verbatim).

### The threshold constant and where it lives

`kCompactLiveMinHeight` — colocate it in `timeline_geometry.dart` alongside `kFullTierMinHeight`
and `kFullBreakMinHeight` (the existing density-threshold constants), not inside
`live_row_card.dart` where the spike's private `_kCompactLiveMinHeight` lived — this groups every
density threshold that governs the Today timeline in one place, matching how the file already
documents its own measurement history for every sibling constant.

**Working target: `88.0`.** Derivation, stated as an estimate, not a measurement: the spike
measured the compact tier's natural height at 90dp *with* a progress bar and a 4dp-total margin;
dropping the bar (≈10dp) and widening the margin to the standard 4dp/4dp (≈+4dp net over the
spike's 2dp/2dp) nets to roughly 84dp, and 88.0 adds a small explicit safety margin in the same
spirit as this file's other corrected constants (`kLiveRowReservedHeight`'s `224 measured + 8
safety = 232.0`). **This number is not measured and must not be treated as final.** It happens to
equal the already-shipped `kFullTierMinHeight` (88.0) — if the real-browser measurement below
lands at or near that same figure, reusing `kFullTierMinHeight` itself rather than introducing a
second, nearly-identical constant is worth considering during planning; if it lands meaningfully
different, keep them separate (they threshold different card layouts and have no reason to be
coupled).

**Re-measurement is mandatory before this constant ships**, per this project's three-strikes
history (`kGutterWidth` 46→75→52, `kPixelsPerMinute` 4.0→5.5→4.0, `kLiveRowReservedHeight`
240→232 — all `flutter test`-derived numbers that were wrong). Recipe:

1. Implement the compact tier exactly as specified above (no progress bar, corrected margin).
2. `flutter build web --debug --source-maps --pwa-strategy=none`.
3. Serve with `python3 tools/serve-uat.py <port> --dir build/web` (never
   `python3 -m http.server` — see `CLAUDE.md` trap #3).
4. Drive to a simulated instant inside a live **work** chunk (e.g. 20% through a 25-minute chunk,
   matching the spike's `08:55` capture) via `flutter.dev_clock_offset_micros` in `localStorage`
   — reuse `.planning/spikes/001-live-row-in-a-true-grid/tools/drive.cjs` as the pattern.
5. Screenshot headless Chromium at 430×930, DPR 1, `--use-gl=swiftshader
   --enable-unsafe-swiftshader` (avoids the `CONTEXT_LOST_WEBGL` false-blank trap).
6. Pixel-count the compact card's `primaryContainer` fill height, the same method
   `26-08-SUMMARY.md`/the spike used.
7. Set `kCompactLiveMinHeight` to that measured height (+ a small explicit safety margin,
   documented inline exactly like every other constant in this file already is).
8. Separately confirm the single-line tier's natural height (drive to a live 5-minute break, e.g.
   `09:17` matching the spike) stays comfortably under 20dp — if the accessibility `Semantics`
   wrapper or the zero-margin change pushed it over, tighten further before shipping; do not raise
   the slot itself (that would reopen GRID-01).
9. Run `.planning/spikes/001-live-row-in-a-true-grid/tools/measure_hours.py` against a screenshot
   taken while a chunk is live — must print `UNIFORM`.

## The now-line crossing the live card (open question 3)

**Decision: option 3 — design the card so a crossing is harmless. No z-order change, no rule
suppression.** The now-line's rule (the 2dp stroke, as opposed to its time chip) stays exactly
as `26-UI-SPEC.md` already specifies it everywhere else on the timeline: full opacity,
`colorScheme.primary`, full content width, topmost z-order, `IgnorePointer`, and — this is the
part this phase explicitly reaffirms rather than reopens — **still crossing the live card
uncrossed and unsuppressed**, exactly as the G-03 amendment already decided for the *chip*
("The `2dp` rule is explicitly unchanged — it still spans the full content width and still
crosses the card; only the chip is confined... That crossing is the truthful mid-chunk position
CAL-02 exists to deliver").

Why not the other two options, explicitly:

- **Drawing the live card above the now-line overlay** would special-case exactly the one thing
  CAL-02's architecture is built to avoid: "[the overlay] does not know or care whether a
  `ChunkCard`, a free-time gap, or the `LiveRowCard` is beneath it at that y-offset. This is what
  makes CAL-02's 'including inside an activity's span' true without a special case." Every other
  card on the timeline already renders under the line; carving the live row out the moment it
  becomes visually tight would be inconsistent with the very reasoning `26-UI-SPEC.md` used to
  justify the topmost z-order in the first place.
- **Suppressing the rule where it crosses the live card** would reverse the *specific* decision
  Dan already made once at this exact seam (26-UAT.md G-03): suppress the chip (redundant — the
  card already states the time in its own copy), keep the rule (the truthful position is the
  point). Re-litigating that now, only because the card got shorter, treats "the line collides
  with text more often" as a new problem rather than what it actually is: the same collision,
  more frequent, which a design choice inside the card (below) can absorb without touching the
  line's own contract a second time.

**What makes the crossing harmless in practice**, evidenced by the spike's own screenshots
(`variant-a-0855-work-live.png`, `variant-a-0917-break-live.png`) rather than asserted: in both
captures the line crosses directly through rendered text (the kicker line at 8:55, the entire
single-line string at 9:17) and the text remains legible on both sides of the stroke in both
images. The mechanism that makes this work, kept intact by this contract:

1. **The stroke stays thin (2dp) and the text stays high-contrast** — `onPrimaryContainer` at
   full or near-full opacity against `primaryContainer` fill, `colorScheme.primary` for the
   stroke. A 2dp line crossing a 12–16px glyph obscures a small enough fraction of any character
   that reading is unaffected — the spike's evidence is the proof, not a claim.
2. **No text line is shorter than the stroke needs to cross cleanly** — every text line in both
   tiers (kicker, title, remaining, single-line combined) is at minimum `labelSmall`/12px, tall
   enough that a 2dp rule crossing it lands within a single line's vertical band and never
   straddles two stacked lines' baselines simultaneously.
3. **The single-line tier's full-opacity text (decided above, not the compact tier's 72–82%
   alpha secondary lines) is deliberately the highest-contrast text on the whole live row** —
   because it is also the tier most likely to be crossed on *every* single frame it exists for
   (a 20dp card gives the line nowhere to land but on the one line of content), unlike the compact
   tier where the line only crosses whichever one of three lines happens to sit at the current
   fraction-elapsed.

No suppression logic, no conditional rendering, no new parameter on `NowLineOverlay` — this
section is a design constraint on `LiveRowCard`'s own contrast and line-count choices, not a
change to the now-line's existing, already-locked contract.

## Spacing Scale

Reuses `26-UI-SPEC.md`'s declared 8-pt scale (`xs` 4 / `sm` 8 / `md` 16 / `lg` 24 / `xl-3xl`
32/48/64) without modification. This phase's additions:

| Token | Value | Usage |
|-------|-------|-------|
| (reused `xs`) | 4px | Gap between the compact tier's kicker+title block and its remaining-time line |
| (reused `sm`) | 8px | Compact tier's Card vertical padding; single-line tier's horizontal padding |
| (reused, custom) | 12px | Compact tier's Card horizontal padding (multiple of 4, not separately tokenized in `26-UI-SPEC.md` either) |
| (reused, Card-seam standard) | 4px top/bottom | Compact tier's Card margin — the same value every other row already uses, not a new one |

**One declared exception, stated explicitly per this project's spacing-scale discipline:**
the **single-line tier's Card margin is `0` vertically** — a valid point on the 8-pt scale
(`0` is trivially a multiple of `4`), not a sub-4dp violation, and not a new kind of exception:
it is the identical move `26-UI-SPEC.md` already made for the ordinary break Compact tier's
vertical padding, applied here to margin instead because the smallest guaranteed slot (20dp)
cannot spend any of its height on margin and still fit one legible text line. See "Single-line
tier" above for the full reasoning and why the visual seam between rows survives anyway.

### PD-27-01 — corrected 2026-08-18: vertical only, NOT all four sides

**This document originally said `EdgeInsets.zero` "(all four sides)". That was wrong, and would
have re-shipped a regression this project has already fixed once.** Caught by `gsd-planner` during
Phase 27 planning and confirmed by `gsd-plan-checker`.

Every word of the justification above is about *vertical* budget — a 20dp slot cannot spend height
on margin. None of it argues for zeroing *horizontal* margin, and zeroing it is actively harmful:
the live row is positioned `left: 0, right: 0` with **no `TimelineRowTile`**, so unlike the
ordinary break Compact tier this paragraph analogises to, nothing else supplies its horizontal
inset. A horizontal `0` bleeds the card to the raw viewport edge — the exact regression recorded
in `timeline_row_tile.dart`'s own doc comment ("the live row bled to the raw screen edge"), one of
three attempts that each broke something.

**The contract is:** `EdgeInsets.only(top: 0, bottom: 0, left: kCardLeftInset, right:
kTimelineRowInset)` — zero vertically, standard row insets horizontally. `27-02-PLAN.md` enforces
this with a `grep -c "kCardLeftInset"` acceptance criterion.

This is the general rule for both tiers, and `live_row_card.dart`'s own doc comment already states
it: **every horizontal offset for this row must be stated on the card itself**, because it
inherits no padding from anything.

**Touch-target exception, stated explicitly:** the compact tier's Complete/Skip `IconButton`s are
constrained to **36×36dp**, below the 44dp WCAG-recommended minimum. See "Compact tier" above for
the justification — this is a stated trade, not an oversight, and is called out here so the
checker's spacing dimension does not flag it as an unreviewed gap. **This exception needs a
UAT-specific check** (tap it on an actual touch device before sign-off) rather than being treated
as closed the moment the code matches this document — see the same note under "Compact tier."

No other exceptions. Every other value in this phase (margins, paddings, gaps) sits on the
existing 8-pt scale, matching `26-UI-SPEC.md`'s own closed-set discipline.

## Verification — pixels, not `flutter test` (restated for the checker/executor)

`flutter test` cannot see GRID-01 hold or fail: 240dp and 372dp both satisfy every existing
assertion, because those assertions check `yFor()` against the same arithmetic the implementation
performs. Two independent verifications are required before this phase is called done, neither of
which is a widget-test pump:

1. **`measure_hours.py` prints `UNIFORM`** while a chunk is live, in a real-browser debug build
   served via `tools/serve-uat.py` (per `CLAUDE.md`'s traps #1–#3).
2. **A new equidistance regression test** — `yFor(h+60) - yFor(h)` constant across every hour
   boundary, with a live chunk present in the fixture — closes the hole the existing suite has
   always had. This is the one piece of `flutter test` coverage that *is* trustworthy here,
   because it is a pure geometric/arithmetic assertion (Phase 26's carry-forward invariant: "Test
   -harness caveat ... Geometric assertions (heights and offsets computed from arithmetic) ARE
   trustworthy" — only *text-driven* measurements are the harness's known failure mode).

Every dp figure in the density-tier tables above that is marked TARGET must be replaced with a
real-browser measurement, using the named recipe, before `kCompactLiveMinHeight` is considered
final — this document intentionally ships with an honest estimate rather than a fabricated
"measured" number, consistent with this project's three-times-burned history on exactly this kind
of constant.
