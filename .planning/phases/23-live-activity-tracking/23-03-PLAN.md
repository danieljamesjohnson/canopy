## P-1 — the GapBeforeNext ambiguity, DECIDED

`23-RESEARCH.md` Open Question 1 and `23-VALIDATION.md`'s "Known ambiguity to settle during
planning" both hand this to the planner. **Decision: the `GapBeforeNext` banner does NOT change.
Reading 1.** The `'Up next'` heading, the title line, the optional subtitle, and the
`'Starts at …'` body all stay exactly as they are.

Reasoning, so this is a decision rather than a coin flip:

1. **The source artifact's own format argues for it.** `23-CONTEXT.md` decision 3 supplies a
   verbatim replacement sentence for each of the two states it wants changed. For the gap it
   supplies a *description* — "named as free time inline (Phase 22 decision 5)" — not a
   replacement string and not a removal instruction. Read in context, that sentence explains *why*
   no new gap copy was authored: Phase 22's inline `GapFreeRow`/`LeadingFreeRow` already carry the
   "this is free time" signal in the list itself, so the banner did not need new words.
2. **Removing the banner would make the gap state read *less* truthfully, not more.**
   `GapFreeRow` renders a duration ("Free · 1h 40m"). It does not name what is coming. LIVE-03
   asks each edge state to read truthfully and distinctly; deleting the only place the screen
   says *what* is next during a gap subtracts information the requirement is asking for.
3. **Nothing in any source artifact asks for the removal**, and it would break five currently
   passing assertions (`find.text('Up next')` at `today_screen_now_state_test.dart:611` and
   `today_screen_test.dart:566`, plus their neighbours) that no artifact flags as expected churn.

**The one thing that does change about the gap state is behavioural, not copy:** its
`_chunkTitle(context, next)` call must name a break correctly, because plan 23-01 broadened
`resolveNowState` so `next` can now be a break. That already works via the shared helper — Task 2
proves it with a test rather than assuming it.

This decision is surfaced to Dan for confirmation in plan 23-04's human-verify checkpoint. It is
recorded here as decided so that the LIVE-03 gap test asserts a contract rather than a guess.
