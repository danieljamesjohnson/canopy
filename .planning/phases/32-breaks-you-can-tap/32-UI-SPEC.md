# Phase 32 — UI Design Contract

> Visual and interaction contract for Phase 32: Breaks You Can Tap (TAPBREAK-01, TAPBREAK-02,
> TAPBREAK-03). Agent-generated by `gsd-ui-researcher` in **non-interactive mode**
> (`workflow.skip_discuss=true`, `32-CONTEXT.md`: "Mode: Auto-generated"). D-32-01, D-32-02, D-32-03
> are **owner-ruled and locked** (ROADMAP, 2026-08-27) — this document does not re-open them. Its job
> is everything the ROADMAP's three decisions left open: the exact re-derived constants, the break
> card's new visual design, the Skip button's precise widget tree, and — the gap none of the three
> decisions mentions but that falls directly out of them — what replaces the live 5-minute break's
> **only** skip mechanism once the swipe it depended on is deleted.
>
> **This document EXPLICITLY SUPERSEDES `chunk_card.dart`'s D-06 clause "breaks read transparent with
> a dashed outline, never a filled Card."** The owner's own words ("make it look like a small section
> similar to work") directly countermand that clause for the break card's *container* only. What
> survives from D-06 unmodified: no bold title, no emoji, no colored goal-accent bar on a break (it
> has no goal). The Skip rail's error-family coloring is the app's **existing** skip vocabulary
> (`OutlinedButton`'s `foregroundColor: colorScheme.error`, the now-deleted swipe reveal's
> `colorScheme.error` fill) made permanent, not a new "achievement" signal — breaks still read
> quieter than a goal card, they just also carry a real action now.
>
> **This document also supersedes `29-UI-SPEC.md`'s sub-compact tier and `31-UI-SPEC.md`'s
> hit-slop/grip-glyph mechanism, in full**, per D-32-02's explicit retirement instruction — not
> silently: see "Retirement checklist" below for the itemized list and why each entry is dead.
>
> **Framework note:** Flutter / Material 3, `ColorScheme.fromSeed(Colors.deepOrangeAccent)`
> (unchanged). All colour references are semantic `ColorScheme` slots — never raw hex or `Colors.*`
> literals (closed as debt in Phase 22, carried forward). This phase changes one scale constant
> (D-32-01), adds one new geometry constant (D-32-03), retires five, and replaces the break card's
> container and interaction model — no new color roles, no new type roles.

## Constant re-derivation (D-32-01 cascade)

`kPixelsPerMinute` moves 4.0 → 6.0. Per the ROADMAP's own instruction, every derived constant is
**re-derived, not restated** — some genuinely change, most don't (and the reason each one doesn't is
worth stating explicitly, so a future reader doesn't assume they were missed):

| Constant | File | Value before | Value after | Why |
|---|---|---|---|---|
| `kPixelsPerMinute` | `timeline_geometry.dart` | `4.0` | **`6.0`** | D-32-01, locked. A 5-min break: 20dp → **30dp**. A 25-min work chunk: 100dp → **150dp**. |
| `kFullTierMinHeight` (work) | `timeline_geometry.dart` | `88.0` | **`88.0` — unchanged** | This threshold is compared against absolute slot height, not derived from the pixels-per-minute ratio. A 25-min work chunk grows 100dp→150dp, so slack against this threshold only *increases* (62dp vs. 12dp before). Growing slack never requires re-measurement — only shrinking it does. |
| `kFullBreakMinHeight` | `timeline_geometry.dart` | `88.0` | **`88.0` — kept, but the content behind it changed** | Same reasoning on the ratio. But this phase redesigns the `compact` break tier's content (see below), so the thing that actually needs re-checking is not this threshold's *value* — it is whether the redesigned `compact` card fits inside its **smallest reachable slot, 30dp**, without clipping. That is a real-browser measurement task (see "Verification"), not a constant change. |
| `kSubCompactBreakMinHeight` | `timeline_geometry.dart` | `32.0` | **RETIRED — delete** | The sub-compact tier no longer exists for breaks (D-32-02: "retires Phase 29's `_SubCompactRow` treatment for breaks at the 5-minute tier"). Nothing reads this constant once the tier is gone. |
| `kBreakHitSlop` | `timeline_geometry.dart` | `24.0` | **RETIRED — delete** | Existed solely to grow an invisible swipe-acquisition band. Breaks have no swipe (D-32-02). |
| `kMinBreakDragTarget` | `timeline_geometry.dart` | `48.0` | **RETIRED — delete** | The gate that decided *when* `kBreakHitSlop` applied. Nothing consumes it once `kBreakHitSlop` is gone. |
| `kSubCompactGripSize` | `chunk_card.dart` | `14.0` | **RETIRED — delete** | Sized the `Icons.drag_indicator` grip glyph inside `_SubCompactRow` — the exact icon the owner said reads as "drag and drop," which is the whole reason this phase exists. Deleted with the glyph, not repurposed. |
| `kCompactLiveMinHeight` | `live_row_card.dart` | `88.0` | **`88.0` — unchanged** | Same ratio-independence as `kFullTierMinHeight`. Live long break grows 120dp→180dp (more slack); live short break grows 20dp→30dp — still below the threshold, same qualitative branch as before (single-line tier). |
| `kNowLineHeight`, `kHourAxisHeight`, `kTimelineEdgePadding`, `kLiveActionTouchTarget`, `kGutterWidth` | various | unchanged | **unchanged** | None of these is derived from `kPixelsPerMinute` — they are fixed chrome heights or a horizontal metric. Listed here only so a reader checking "did the migration touch this" gets an explicit no. |
| `kBreakSkipButtonWidth` (**new**) | `timeline_geometry.dart`, colocated with the density-threshold cluster | — | **`64.0`** | D-32-03, locked. See "The Skip rail" below for the exact geometry this produces at every reachable break duration. |

**The known, accepted cost (D-32-01, restated because it governs every measurement below): the day
is 50% taller to scroll.** An 8-hour day goes ~1920dp → ~2880dp. This is not a defect to fix; it is
the trade the owner explicitly took to keep the grid honest (TAPBREAK-02).

## Retirement checklist (D-32-02 cascade) — retire deliberately, do not leave dead mechanism

Per the ROADMAP's explicit instruction ("retire them deliberately; do not leave an unused
invisible-band mechanism in the tree"), every one of these must be **deleted**, not merely stop being
called:

| Item | File | Why it's dead |
|---|---|---|
| `kBreakHitSlop`, `kMinBreakDragTarget` | `timeline_geometry.dart` | No swipe target to widen (see table above). |
| `_needsSlop(...)` | `today_screen.dart` | Existed only to decide (a) whether a break's hit-test envelope should grow and (b) whether the row needed the Layer 1b pass. Neither question exists once breaks have no `Dismissible`. |
| The Layer 1b `Stack` pass | `today_screen.dart`, the `for (final row in timelineRows) if (row is ChunkRow && !row.isLive && ... _needsSlop(...))` loop between Layer 1a and the now-line overlay | Existed solely to win z-order for a slop-bearing break's grown hit-test box against its neighbours (`31-RESEARCH.md` Pitfall 1). With no grown box, there is nothing to win z-order for. Breaks return to Layer 1a, rendered exactly like a work chunk row. |
| The break arm's grown-`Positioned` envelope (`top: geometry.yFor(start) - slop, height: slot + 2 * slop`) | `today_screen.dart`, `_buildPositionedRow`'s `ChunkRow` case | Collapses back to the plain `Positioned(top: geometry.yFor(start), height: slot, ...)` every non-slop row already used — the break arm becomes structurally identical to the work-chunk arm below it, differing only in which card widget it builds. |
| `SwipeableRowShell`/`SwipeableChunkCard`'s `visualHeight` parameter and confinement logic (`_confineReveal`/`_confineContent`) | `swipeable_chunk_card.dart` | Existed only to let a break's `Dismissible` hit-test box exceed its painted slot while confining paint to the slot. Once breaks never reach `SwipeableChunkCard`/`SwipeableRowShell` at all (see below), no call site ever passes `visualHeight` non-null again — it becomes dead code with zero live callers. Delete the parameter and both confinement helpers rather than leaving an unreachable branch, per this phase's own "retire deliberately" instruction (do not repeat Phase 29's precedent of keeping a *documented* dead branch — that precedent applies to a branch a future phase might plausibly reach; this one cannot be reached by construction once the call site is gone). |
| The live-break arm's `SwipeableRowShell` wrapping | `today_screen.dart`, `_buildPositionedRow`'s `isLive && isLiveBreak` branch | Same reasoning — a live break's Skip is now a button (see below), not a gesture. |
| `_SubCompactRow`, `ChunkCardDensity.subCompact`, its `Icons.drag_indicator` glyph | `chunk_card.dart` | The sub-compact tier is retired for breaks; the enum value has no other reachable call site once it is (the work-chunk fallback arm that referenced it was itself dead code, kept only for switch-exhaustiveness against a value that no longer exists — deleting the enum value removes the need for that arm too, not just this phase's usage of it). |
| `_DashedBorderPainter` | `chunk_card.dart` | Used exclusively by the break card's old dashed-outline treatment. The new break card is a filled, bordered `Card` (below) — nothing else in this file uses a dashed border. |
| `SwipeableChunkCard`'s `chunk.chunkType != ChunkType.work` early return | `swipeable_chunk_card.dart` | **Restored, not deleted** — see "Where breaks render now," directly below. Phase 31's `promote` decision deleted this early return so breaks could reach `Dismissible`; Phase 32 reverses that specific choice because breaks no longer use `Dismissible` at all. This is the one item in this table that comes back rather than leaves. |

**Deliberately NOT retired, and why (do not touch these):** `SwipeableChunkCard`, `SwipeableRowShell`,
and every work-chunk swipe path are **unchanged** — work chunks keep the two-directional
`Dismissible` exactly as shipped. `LiveRowCard`'s compact-tier Complete/Skip `IconButton`s (D-31-07)
are unchanged and **survive**, per the ROADMAP's explicit "do not remove" instruction — they are
closer to what the owner asked for than the swipe ever was.

## Where breaks render now — the architecture, end to end

**`SwipeableChunkCard` regains its pre-Phase-31 early return**, now reading:

```dart
if (chunk.chunkType != ChunkType.work) {
  return ChunkCard(
    chunk: chunk,
    goalColor: goalColor,          // always null for a break — forwarded unchanged
    density: density,
    showStartTime: showStartTime,
    // onTap stays null — tappable is still out of scope (owner, 2026-08-21, unchanged)
  );
}
// ...existing work-chunk SwipeableRowShell path, unchanged below this line
```

**`ChunkCard`'s own `_buildBreak` method now owns the Skip action directly** — exactly the pattern
`_WorkChunkContent._buildActionRow` already uses (`context.read<ScheduleNotifier>().markSkipped(chunk.id)`
called straight from the button's `onPressed`, no gesture wrapper in between). This is not a new
pattern this phase invents; it is the same wiring the work-chunk Skip button has always used, applied
to the break card for the first time.

**`today_screen.dart`'s break arm of `_buildPositionedRow` collapses to the work-chunk arm's own
shape** — same `Positioned(height: slot)` → `ClipRect` → `OverflowBox` → `TimelineRowTile` →
`_buildChunkCard` chain, no `visualHeight`, no slop. The only difference between the work and break
arms after this phase is which `ChunkCardDensity` ternary picks the tier (unchanged logic, see table
below) and that `SwipeableChunkCard`'s early return sends a break straight to `ChunkCard` instead of
through `SwipeableRowShell`'s `Dismissible`.

**`markSkipped`'s existing error handling is unaffected.** The revert-and-rethrow behaviour
(`schedule_notifier.dart`, WR-05) lives inside the notifier method itself, not in `Dismissible`'s
`confirmDismiss` — calling it from a button's `onPressed` instead of a gesture callback changes
nothing about how it behaves on failure. The pre-existing, documented, out-of-scope gap (an uncaught
`rethrow` with no `catchError` at the call site) is carried forward unchanged, exactly as
`31-UI-SPEC.md` recorded it — this phase does not touch it.

**Scope note, flagged for the planner rather than silently resolved:** the trailing untimed block
(`today_screen.dart`, the `for (final row in timelineRows) if (row is ChunkRow && row.chunk
.displayStartMinutes == null)` loop, PD-11) currently calls `_buildChunkCard` unconditionally, which
routes through `SwipeableChunkCard` regardless of chunk type. This is a documented preservation branch
the generator does not currently produce output for (no chunk today lacks a clock position) — with
the early return restored above, a break landing here would now correctly render without a swipe
(the early return applies inside `SwipeableChunkCard` regardless of caller), so **no separate fix is
needed at this call site** — noted only so a reader auditing this file doesn't need to re-derive that
conclusion themselves.

## The new break card (TAPBREAK-03) — a real section, not a hairline

**Container.** A `Card` — `RoundedRectangleBorder(borderRadius: 12, side: BorderSide(color:
colorScheme.outlineVariant))`, `color: colorScheme.surfaceContainer`, `clipBehavior: Clip.antiAlias`
(so the Skip rail's fill, below, gets clipped to the card's own rounded right edge automatically) —
this is the **same container language `_WorkChunkContent`'s discretionary-goal Card already uses**,
which is the literal meaning of "look like a small section similar to work." What is deliberately
**not** carried over from a goal card: no colored left accent bar (a break has no goal color), no
bold title, no emoji — D-06's "not an achievement" framing survives for the label side even though
the container no longer does.

**Two tiers, same threshold as before (`kFullBreakMinHeight = 88.0`), same reachability as before**
— under today's lattice (5-min / 30-min breaks only) this remains a two-value split, not a
continuous range:

| Tier | Trigger | Reachable duration @ 6.0 | Slot height |
|---|---|---|---|
| **Compact** | `slot < kFullBreakMinHeight` | Short break, 5 min | **30dp** |
| **Full** | `slot >= kFullBreakMinHeight` | Long break, 30 min | **180dp** |

**Both tiers share one internal shape** — a `Row` whose direct children are (1) the label/icon
column, `Expanded`, and (2) a fixed-width `SizedBox(width: kBreakSkipButtonWidth)` holding the Skip
rail — with `crossAxisAlignment: CrossAxisAlignment.stretch` on the Row, so the rail's height is
*whatever height the Row is given* with no separate height calculation needed. This is what makes
the rail exactly "the full row height" at every tier without a conditional: at 30dp it is
`64 × 30`; at 180dp it is `64 × 180`. Deliberately uniform rather than differentiating "the short
one gets a wide rail, the long one gets a normal button" — the owner's own words were "have a skip
button on the side," stated without qualifying it to one tier, and one shape with no branching is
simpler code besides. **Flag this specific choice for the human UAT** (see "Verification") — it is a
reasonable reading of the instruction, not a re-litigation of a locked decision, and the ROADMAP's
own arithmetic (D-32-03) was derived against the worst case (the 30dp row), so applying the identical
shape to the 180dp row is never a *smaller* target than what was ruled, only a more generous one.

**Compact tier (the load-bearing case — 5-minute break, 30dp).**

```dart
Card(
  margin: EdgeInsets.zero,   // see below — the smallest reachable slot cannot spend any of it on margin
  color: theme.colorScheme.surfaceContainer,
  clipBehavior: Clip.antiAlias,
  shape: RoundedRectangleBorder(
    borderRadius: BorderRadius.circular(12),
    side: BorderSide(color: theme.colorScheme.outlineVariant),
  ),
  child: Row(
    crossAxisAlignment: CrossAxisAlignment.stretch,
    children: [
      Expanded(
        child: Center(
          child: Padding(
            padding: const EdgeInsets.symmetric(horizontal: 12),
            child: Text(
              title,   // 'Short break' — unchanged, verbatim
              maxLines: 1,
              overflow: TextOverflow.ellipsis,
              style: theme.textTheme.bodySmall?.copyWith(
                color: theme.colorScheme.onSurfaceVariant,
                decoration: chunk.isSkipped ? TextDecoration.lineThrough : null,
              ),
            ),
          ),
        ),
      ),
      SizedBox(
        width: kBreakSkipButtonWidth,
        child: chunk.isSkipped ? _SkippedIndicator() : BreakSkipButton(chunk: chunk),
      ),
    ],
  ),
)
```

**`margin: EdgeInsets.zero` is a deliberate, explicitly-justified exception, not an oversight** — same
reasoning `29-UI-SPEC.md`'s sub-compact tier already established for exactly this problem: the
smallest guaranteed break slot (30dp) cannot spend any of it on a 4dp-top + 4dp-bottom margin and
still leave comfortable room for the border, the label, and the rail's own icon+text. The neighbouring
work chunk's own Card still carries its usual 4dp margin, and Flutter margins don't collapse, so the
visible seam between rows is preserved by the neighbour alone — the identical mechanism Phase 29 used
to justify the same move.

**Full tier (long break, 180dp)** keeps the existing heavier weight within the same vocabulary (UAT
G-02, unchanged): `titleMedium` at `w500`, the leading `Icons.self_improvement` icon, and — the one
thing this phase changes for this tier — `margin: EdgeInsets.symmetric(vertical: 4)` restored (there
is no room pressure at 180dp) and the trailing `Spacer()` + duration/`'skipped'` text replaced by the
same `SizedBox(width: kBreakSkipButtonWidth)` rail structure the compact tier uses. The internal
`Row`/`Padding`/icon layout otherwise matches what already ships today, unchanged.

**Mandatory real-browser check before this ships (see "Verification"):** does the compact tier's
content — one `bodySmall` line, zero margin, inside a bordered `Card` — actually fit inside 30dp
without clipping? This project's own three-strikes constant history (`kGutterWidth`,
`kPixelsPerMinute`, `kCompactLiveMinHeight`, `kSubCompactBreakMinHeight`) says do not assume; measure.
The reasoned expectation, stated so the plan doesn't start from zero: one `bodySmall` line is
typically 16–18dp with real Roboto metrics, plus a 1dp border, well inside 30dp — but this is an
estimate, not a measurement, and must be confirmed with the same headless-Chromium recipe Phase 29/31
already established (`--use-gl=swiftshader --enable-unsafe-swiftshader`, debug build on port 8143).

## The Skip rail — D-32-03's exact geometry

**Recommended file: `lib/widgets/break_skip_button.dart`** — a new top-level shared widget (matching
this codebase's existing convention of putting cross-cutting widgets in `lib/widgets/`, alongside
`responsive_shell.dart`, rather than under either `lib/screens/schedule/widgets/` or
`lib/screens/today/widgets/`, since **both** the non-live break card (`chunk_card.dart`, under
`schedule/widgets/`) and the live break's single-line tier (`live_row_card.dart`, under
`today/widgets/`) need the identical visual — putting it under either feature folder would make the
other feature reach across a folder boundary for no reason, and the two Skip surfaces drifting apart
visually is exactly the kind of inconsistency a shared widget prevents. This is Claude's discretion,
not ROADMAP-mandated; the planner may choose a different location as long as both call sites render
identically.

```dart
class BreakSkipButton extends StatelessWidget {
  const BreakSkipButton({super.key, required this.chunkId, required this.accessibleTitle});

  final String chunkId;
  final String accessibleTitle;   // e.g. 'Short break' / 'Long break' — for the Semantics label below

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);
    final colorScheme = theme.colorScheme;
    return Semantics(
      button: true,
      label: 'Skip $accessibleTitle',
      child: Material(
        color: colorScheme.errorContainer,
        child: InkWell(
          onTap: () => context.read<ScheduleNotifier>().markSkipped(chunkId),
          child: Center(
            child: Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                Icon(Icons.skip_next_outlined, color: colorScheme.onErrorContainer, size: 18),
                Text(
                  'Skip',
                  style: theme.textTheme.labelSmall?.copyWith(
                    color: colorScheme.onErrorContainer,
                    fontWeight: FontWeight.w600,
                  ),
                ),
              ],
            ),
          ),
        ),
      ),
    );
  }
}
```

**Icon-above-label, not side-by-side, and why that matters at 30dp.** `kBreakSkipButtonWidth = 64.0`
gives ~40dp of usable width after the `Card`'s own padding/border — comfortable for either an 18dp
icon + gap + "Skip" side-by-side, or the same two elements stacked. Stacked is specified because it
reads unambiguously as a single button at every tier (side-by-side risks looking like two separate
tap targets — an icon-only zone and a text-only zone — at 30dp tall where there's no vertical room to
visually group them as one unit). At 180dp (full tier) the same stacked shape still reads correctly,
just with more empty rail above and below it — acceptable, since `Center` handles that automatically.

**Exact math (D-32-03, restated because it is the geometric core of TAPBREAK-01):**

- Compact tier (5-min break): rail is **64dp × 30dp = 1920dp²**, against Material's 48×48 = 2304dp²
  guideline. Deliberately under, and deliberately so — the target earns its area from *width*, and
  every pixel of the 1920dp² is *visible* paint (`colorScheme.errorContainer` fill), not an invisible
  slop band. Meeting a spec number with an invisible target (Phase 31's failed approach, twice) is a
  weaker guarantee than missing it slightly with a visible one — the owner's own framing, restated
  here because it is the reasoning this whole button's shape rests on.
- Full tier (30-min break): rail is **64dp × 180dp = 11520dp²** — far more generous, no tension with
  any minimum.

**Visible label: `'Skip'`** — unchanged from the app's existing skip vocabulary (the work-chunk
`OutlinedButton.icon` already reads "Skip", not "Skip this chunk"), so no new copy decision, just the
existing word made permanent instead of transient. **Accessibility label: `'Skip $accessibleTitle'`**
(e.g. "Skip Short break") — restates which break this button acts on, since a screen reader
traversing the row does not automatically know the button belongs to the card next to it. This is the
same "narrower visible string than the meaning it needs to convey for a screen reader" pattern
`29-UI-SPEC.md`'s sub-compact tier and `27-UI-SPEC.md`'s single-line tier both already established —
not a new pattern.

**Deliberate correction to the established `excludeSemantics` pattern — read before implementing.**
Every prior break tier (`_buildBreak`'s `compact`/`subCompact` branches) wraps the whole row in
`Semantics(label: ..., excludeSemantics: true, child: Row(...))`, because those rows had **no**
focusable child — the wrapper's whole job was to collapse several child widgets' redundant/absent
semantics into one clean announcement. **That pattern must NOT be copied onto the new break card.**
The row now contains a real interactive `Semantics(button: true, ...)` node (the Skip button, above)
— wrapping the outer row in `excludeSemantics: true` would **swallow the button's own semantics
entirely**, making it invisible to a screen reader even though it is visibly rendered and tappable. Do
not add an outer excluding wrapper here; let the label `Text` expose its own implicit semantics and
let `BreakSkipButton`'s own `Semantics(button: true, ...)` stand on its own. This is the single
easiest accessibility regression a straight copy-paste of the old pattern would introduce, flagged
explicitly so the executor doesn't reproduce it.

**Once resolved (`chunk.isSkipped`): the rail slot stays the same width, its content swaps.** Rather
than restructuring the `Row` (Expanded-only, full width) once a break is skipped, the 64dp trailing
slot stays in place and its content becomes a small centered `Text('skipped', bodySmall,
onSurfaceVariant)` — **verbatim reuse of D-31-04's existing "skipped" string**, not a new copy
decision, just relocated from "after a `Spacer()`" into this rail slot. This keeps the row's geometry
identical in both states (useful for a stable widget-test assertion of TAPBREAK-02/SKIPBREAK-02: the
slot never resizes regardless of resolved state) rather than conditionally reflowing the `Row`.

## The live break's single-line tier — a gap D-32-02 opens and this document closes

**This is not named anywhere in the ROADMAP entry, and it must be, because D-32-02 silently deletes
the only Skip mechanism a live 5-minute break currently has.**

At 6.0, a live break's `slotHeight` is either 30dp (5-min short break — **below**
`kCompactLiveMinHeight = 88.0`, so `LiveRowCard` renders its **single-line tier**) or 180dp (30-min
long break — **at or above** the threshold, so it renders the **compact tier**, which already carries
`showActions`-gated `IconButton`s and is unaffected by this phase, per the ROADMAP's explicit "do not
remove" instruction).

**The single-line tier today has no action row at all** — `LiveRowCard._buildSingleLine` renders one
`Text` for the title and one for the countdown, nothing else. The *only* way to skip a live short
break today is Phase 31's `SwipeableRowShell`-wrapped swipe. **D-32-02 deletes that wrapper from
every break, live or not, with no substitute named.** Without a fix, this phase would ship a live
5-minute break with **zero** way to skip it — a regression the ROADMAP does not flag because it was
written before this document worked through `kCompactLiveMinHeight`'s reachability at the new scale.

**Resolution: `LiveRowCard._buildSingleLine` gains the identical `BreakSkipButton` rail the non-live
break card uses**, at the same `kBreakSkipButtonWidth = 64.0`, spanning the row's own height (30dp for
a live short break) via the same `Row(crossAxisAlignment: stretch)` shape:

```dart
Row(
  crossAxisAlignment: CrossAxisAlignment.stretch,
  children: [
    Expanded(child: /* existing title + countdown content, unchanged */),
    SizedBox(
      width: kBreakSkipButtonWidth,
      child: isSkipped ? _SkippedIndicator() : BreakSkipButton(chunkId: chunkId, accessibleTitle: title),
    ),
  ],
)
```

`showActions`/`showComplete` are already correctly wired for this case (`today_screen.dart`:
`showActions: isBreak ? !chunk.isSkipped : true`, `showComplete: !isBreak` — a live break already
asks for "at least one action, Skip only" going into this phase; only the single-line tier's own
layout needs to start honoring that request instead of silently ignoring it, which is what it does
today).

**Why the same shared widget rather than a bespoke live-row button:** visual consistency between a
static short break and a live one is the whole point of this phase's "look like a small section
similar to work" instruction — a user should not learn two different Skip affordances depending on
whether the break happening right now is live. This is Claude's discretion (not ROADMAP-mandated),
resolved in favor of one shared component for exactly this reason.

**The live break's row also loses its `SwipeableRowShell` wrapper** (see "Retirement checklist"),
returning to the plain `ClipRect`/`OverflowBox` pattern the live work-chunk arm already uses —
structurally, after this phase, the live break arm and the live work arm differ only in which
`LiveRowCard` parameters they pass (`showComplete: false`, break-specific kicker/title strings), not
in their wrapping.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (visible, Skip button) | `'Skip'` — unchanged word, reused verbatim from the existing work-chunk Skip button; made permanent instead of transient |
| Skip button accessibility label | `'Skip $accessibleTitle'`, e.g. `'Skip Short break'` / `'Skip Long break'` |
| Break label, unresolved (unchanged) | `'Short break'` / `'Long break'` — verbatim, unchanged |
| Trailing rail, resolved (skipped) | `'skipped'` — verbatim reuse of D-31-04's existing string, relocated into the rail slot rather than a new copy decision |
| Empty state | Not applicable — no list/collection UI introduced |
| Error state | Not applicable — `markSkipped`'s existing revert-and-rethrow path is reused unchanged, invoked from a button instead of a gesture callback (behaviorally identical) |
| Destructive confirmation | Not applicable — skipping a break has no confirmation step, unchanged from every prior phase's posture |

**Sign-off, not a silent pass: the visible "Skip" label is a single word with no object noun** — a
checker FLAG for single-word CTAs, correctly raised, and deliberately kept rather than corrected.
This is a conscious reuse of the app's existing skip vocabulary: the work-chunk `OutlinedButton`
already reads bare `'Skip'`, not `'Skip this chunk'`, and the owner's own framing of this phase was
literally "have a skip button" — inventing a longer label for the break's button alone would create
two dialects for the identical action on two adjacent controls. The FLAG is compensated, not ignored:
the accessibility label (`'Skip $accessibleTitle'`, above) supplies the object noun a screen reader
needs, while a sighted user already has it from the card's own adjacent title text. Recorded here so
this is a reviewed judgment call, not a gap the checker had to catch.

## Verification — pixels, a real browser, and a human, not `flutter test` alone

1. **TAPBREAK-02/the grid stays exact — provable in `flutter test`, as pure arithmetic**, and this is
   unaffected in kind by this phase (it was already the case for SEEBREAK-02/SKIPBREAK-02): every
   break, at both tiers and both resolved states, renders inside a `Positioned` whose painted content
   occupies exactly `durationMinutes × kPixelsPerMinute` at the **new** `6.0`. The removal of the
   grown hit-test envelope actually *simplifies* this proof — there is no longer a separate
   "envelope vs. painted extent" distinction to keep straight (D-31-02's old two-assertion split
   collapses back into the same single assertion the work-chunk arm already uses).

2. **The migration survey already done (per `32-CONTEXT.md`) still governs test-file edits**: 38
   symbolic `kPixelsPerMinute` references across 4 test files follow the constant automatically; 4
   hardcoded pixel literals need re-derivation and justification, individually, per file. This is not
   a hazardous mass migration — do not plan it as one.

3. **A new widget test proves the Skip button, not a gesture, triggers `markSkipped`**: a synthetic
   `tester.tap()` on the rail (not a drag) calls `markSkipped(chunk.id)`, at both tiers, live and
   non-live. Pair it with a negative assertion: no `Dismissible`/`GestureDetector`-driven horizontal
   drag on a break row does anything at all — proving the swipe path is actually gone, not merely
   unused.

4. **The live single-line tier's new Skip rail needs its own dedicated regression test** — this is
   the gap this document identifies that the ROADMAP itself does not name (see above). Without it, a
   live 5-minute break shipping with no way to skip it is exactly the kind of defect this project's
   own carry-forward invariants warn are invisible to a suite that only asserts what the plan already
   expects to find.

5. **`flutter test` cannot settle whether the compact tier's real-device content fits inside 30dp,
   nor whether the redesigned card visually "reads as a section of the day" (TAPBREAK-03) rather than
   still reading small.** This project's placeholder-font caveat applies exactly as it has every prior
   phase. A real-browser screenshot (headless Chromium, `--use-gl=swiftshader
   --enable-unsafe-swiftshader`, debug build on port 8143) confirming no clipping in the compact tier
   is a plan task, not optional polish.

6. **This phase MUST end in a human UAT checkpoint — the fourth in a row**, with the strongest
   precedent yet: Phase 27 failed 2 of 3 human items after 16/17 automated; Phase 29 shipped 587-green
   while the owner saw no breaks at all; Phase 31 went 625-green then 639-green and was contradicted
   by a thumb **twice**, the second time finding a defect (a misleading icon) no assertion in the
   suite could ever have caught. **Reuse port 8143; kill whatever is squatting it first** (this has
   happened on two of the last three UATs on this project). **Mandatory ⟳ Re-check-in first**
   (`CLAUDE.md` trap #4) — this UAT judges timeline rendering built from generated schedule data, so
   the re-check-in step must appear first in the UAT's own instructions, marked mandatory, exactly as
   every prior phase's UAT has done.

   **This UAT must additionally re-ask two things Phase 31 left open, which this phase inherits
   rather than closes:**
   - **D-31-07 was never judged by a human.** `LiveRowCard`'s compact-tier Skip button
     (the live 30-minute break's case) is code-complete and test-proven but has never been confirmed
     on a real device, and this phase changes the surface immediately underneath it (the card's own
     container is unaffected, but the row it sits beside — the short break — looks completely
     different now). Re-ask it in the same sitting.
   - **The "Up next" transition still needs a ruling.** When a live break is skipped,
     `resolveNowState`'s pre-existing advance-past-resolved loop (`now_state.dart:176`) delists it
     from "current," so the header switches from the break to the next chunk while the now-line

   shape, no branching" choice (see "The new break card") is a reasoned default, not a locked
   decision — if a human finds the tall rail odd on a long break, that is new evidence, not a
   contradiction of anything owner-ruled, and should be recorded and revisited exactly the way this
   project has always treated an unmeasured aesthetic call.
