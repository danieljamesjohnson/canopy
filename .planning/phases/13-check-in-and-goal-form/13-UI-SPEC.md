### Mood Background Contract (check-in screen specific)

The five mood seed colors are locked (Phase 3 / Phase 6 decision, `ThemeNotifier.moodSeeds`):

| Mood | Seed Color | WCAG contrast pitfall |
|------|-----------|----------------------|
| 1 | `#4A6275` (slate-blue) | White text passes at ≥ 4.5:1. Safe. |
| 2 | `#5C7A8A` (steel-blue) | White text passes at ≥ 4.5:1. Safe. |
| 3 | `#4A8C7A` (teal-green) | White text passes at ≥ 4.5:1. Safe. |
| 4 | `#7AAF6A` (sage-green) | White text marginal — ~3.5:1. Use w600 (semibold) for body text to compensate. |
| 5 | `#E8C547` (amber-yellow) | **FAILS** WCAG AA for white text at normal weight. White on #E8C547 = ~1.9:1 contrast ratio. |

**Resolution for mood 4 and mood 5 contrast failure:**

For moods where white-on-background fails (moods 4 and 5, and potentially mood 3 at some modulation states), the check-in screen must switch the foreground text color from `Colors.white` to a dark-on-light approach:

Compute `onBg` using luminance threshold:
```dart
Color get _onBgColor {
  if (_selectedMood == null) return Theme.of(context).colorScheme.onSurface;
  final bg = _backgroundColor;
  final luminance = bg.computeLuminance();
  // WCAG contrast requirement: use dark text on light backgrounds (luminance > 0.35).
  return luminance > 0.35 ? const Color(0xFF1A1A1A) : Colors.white;
}
```

This single computed value replaces the current hardcoded `onBg = Colors.white` whenever `_selectedMood != null`. It applies to:
- AppBar title and back-arrow icon
- "Want a lighter day?" label (or lighter-day decision text after this phase's redesign)
- All body text on the mood background

**Lighter-day decision screen foreground color:** Apply the same luminance-threshold logic. The two choice cards use `colorScheme.surface.withAlpha(38)` (15% white or 15% black depending on background luminance) as card background with `colorScheme.outline` (or equivalent luminance-derived border) as border.

**Switch legibility (existing bug — addressed by redesign):** The current `Switch` on amber fails because `activeTrackColor: Colors.white.withAlpha(102)` (40% opacity) becomes invisible on amber. This is resolved by removing the Switch entirely and replacing it with the post-commit lighter-day decision flow (see §Lighter-Day Interaction Contract).

### Hover and Pressed States (CHECKIN-01, CHECKIN-02)

The current `GestureDetector`-wrapped `AnimatedContainer` emoji targets have no hover or pressed visual feedback. Fix:

- Wrap each emoji tap target in `InkWell` (inside `Material`) instead of bare `GestureDetector`, OR add explicit `onHighlightChanged` with `AnimatedContainer` color change on press.
- **Pressed state:** scale the selected ring from `Colors.white.withAlpha(51)` (20%) to `Colors.white.withAlpha(77)` (30%). Duration: 80ms.
- **Hover state (desktop/web):** When `_selectedMood != mood` (non-selected), show a subtle `Colors.white.withAlpha(26)` (10% white) or luminance-adaptive dark equivalent circle on hover. When `_selectedMood == mood`, show hover at `Colors.white.withAlpha(64)` (25%) slightly brighter than rest (20%).
- **"Let's go" button hover (desktop):** The current `ElevatedButton` with `backgroundColor: Colors.white` already provides `ButtonStyle.overlayColor` hover coverage via Material 3 defaults. Ensure no explicit `mouseCursor` suppression is applied.
- **"Let's go" button pressed state:** Material 3 `ElevatedButton` default pressed ripple applies. No additional code needed.

## Check-in Screen Redesign Contract (CHECKIN-01, CHECKIN-02)

### Phase 13 change: two-step commit flow

**Current behavior (to remove):**
1. User selects mood → background tints.
2. "Want a lighter day?" toggle and "Let's go" button appear simultaneously.
3. Toggle state is ambiguous on light-background moods.
4. User must interpret an inline toggle before committing to the day.

**New behavior (this phase):**
1. User selects mood → background tints to mood color. Emoji row stays; all other controls stay hidden.
2. A single "Let's go" button appears (200dp wide pill, `backgroundColor: luminance-adaptive`, same as current pill shape). No toggle visible.
3. User taps "Let's go" → schedule generates. After generation completes, a **lighter-day decision screen** slides in (AnimatedSwitcher, 300ms, same as existing).
4. Lighter-day decision screen presents two explicit choices — NOT a toggle — before navigating to the acknowledgment.
5. User taps a choice → `lighterDay` value is set, `_scheduleGenerated` → true, transition to acknowledgment body.

**Implementation note:** The `_generate()` call needs to accept the `lighterDay` value after the decision screen is shown. Restructure the state machine:

```
State A: mood not selected         → emoji row only
State B: mood selected             → emoji row + "Let's go" button
State C: generating                → "Let's go" button shows CircularProgressIndicator
State D: generated, awaiting decision  → lighter-day decision screen
State E: decision made             → acknowledgment body (existing _buildAcknowledgmentBody)
```

Re-generate with `lighterDay` set:
- The engine call moves from "Let's go" tap to the decision choice tap in State D.
- This means `_generate()` must accept a `bool lighterDay` parameter and be called from the decision screen's choice handlers, not from the "Let's go" button.
- "Let's go" in State B triggers generation with `lighterDay: false` as a provisional call, then shows the decision screen.

**Alternative (simpler, preferred):** Generate on "Let's go" with `lighterDay: false` as a default, then on decision screen, if user picks "Lighter day," call `ScheduleNotifier.generateToday(...)` again with `lighterDay: true`. This regeneration is synchronous and takes < 100ms per existing performance guarantees.


`_LighterDayCard` widget:
- `Container` with `border: Border.all(color: onBgColor.withAlpha(77), width: 1.5)`, `borderRadius: 12dp`
- Background: `onBgColor.withAlpha(26)` (10% fill — provides just enough contrast between card and mood background without obscuring the mood tint)
- `contentPadding: EdgeInsets.all(16)`
- Leading `Icon(icon, color: onBgColor, size: 28)`
- Title: `bodyLarge` w500, `onBgColor`
- Subtitle: `bodySmall` w400, `onBgColor.withAlpha(179)` (70%)
- Minimum height: 72dp (two lines of text + padding)
- Minimum touch target: 44dp height (satisfied by 72dp minimum)
- **Pressed state:** scale to 0.97 with `AnimatedScale`, 80ms duration, `Curves.easeOut`
- **Hover state (desktop):** border opacity increases to `onBgColor.withAlpha(153)` (60%), background increases to `onBgColor.withAlpha(38)` (15%)

**Back affordance:** Include a `TextButton("← Go back")` below the cards that returns to State B (mood selected, "Let's go" visible). Label: "Go back". Color: `onBgColor.withAlpha(179)`.

## Goal Form Sheet Redesign Contract (GOALFORM-01)

### Problem

The dogfood frame (`0027_02m17s.jpg`) shows that on a standard phone viewport (iPhone 14-class, ~844pt height minus keyboard ~340pt ≈ 504pt available), the sheet content is taller than the available space. "Priority" label is clipped at the bottom edge; the SegmentedButton and Save button are entirely off-screen.

### Root cause

The `GoalTypePicker` with `contentPadding: EdgeInsets.all(16)` on each `ListTile` adds `32dp` of vertical padding per card (top + bottom), for a total of `96dp` of padding across three cards, plus the card's `ListTile` minimum height of `56dp` × 3 = `168dp`. Total picker height ≈ 264dp. Add sheet header (drag handle 24dp + title 40dp + spacing 32dp = 96dp) + goal name field (56dp + 16dp spacing) + priority label (20dp) + SegmentedButton (48dp) + archive button (48dp, edit mode) + Cancel/Save row (52dp) + keyboard insets. This exceeds 504dp on constrained viewports.

### Fix: compact GoalTypePicker

Replace `ListTile(contentPadding: EdgeInsets.all(16))` with `ListTile(contentPadding: EdgeInsets.symmetric(horizontal: 12, vertical: 6))`. This reduces each card from ≈ 88dp to ≈ 64dp, saving 72dp total across three cards.

Additional height budget savings:
- Sheet title: reduce `SizedBox(height: 16)` after title to `SizedBox(height: 12)`.
- After picker, reduce `SizedBox(height: 16)` to `SizedBox(height: 12)`.
- After goal name field, reduce `SizedBox(height: 16)` to `SizedBox(height: 12)`.
- Priority label row: use `labelMedium` (12sp) instead of `bodyMedium` (14sp) — not a significant height saving but matches label semantics better.

These changes collectively free ≈ 84dp, which is sufficient to bring the Priority SegmentedButton and Save button above the keyboard line on a standard phone screen height (iPhone 14: 844pt – 340pt keyboard = 504pt available for sheet content).

## States and Transitions

### Check-in Screen State Machine

| State | Condition | What the user sees |
|-------|-----------|-------------------|
| A: Pre-selection | `_selectedMood == null` | Emoji row centered, no button, no toggle. AppBar title in `onSurface` color. Background: `colorScheme.surface`. |

- A → B: instantaneous (no switcher — just setState)
- B → C → D: AnimatedSwitcher with 300ms `FadeTransition` (existing `duration: Duration(milliseconds: 300)`)

## Accessibility Contract

- All interactive elements on the check-in screen must meet WCAG AA contrast ratio (4.5:1 for normal text, 3:1 for large/bold text) at all five mood levels. The luminance-adaptive `_onBgColor` function achieves this by switching from white to `Color(0xFF1A1A1A)` on light backgrounds.
- Lighter-day choice cards: minimum 44dp touch target (72dp actual — exceeds minimum).
- "Let's go" button: minimum 44dp touch target. Current `EdgeInsets.symmetric(vertical: 14)` with 16sp font gives ≈ 48dp — compliant.
- Emoji mood targets: 60dp container — compliant.
- Priority `SegmentedButton`: Material 3 default meets 44dp minimum. No override needed.
- `SegmentedButton` selection state must not rely on color alone — the selected segment shows both background fill AND label weight change (Material 3 default behavior).
- Goal type picker selection must not rely on color alone — selected card shows both `primaryContainer` background AND a visible `primary`-color border.
- Archive button: `colorScheme.error` foreground with white or surface background provides sufficient contrast (Material 3 error token is calibrated for 4.5:1 on surface).
- Generation error SnackBar: use `SnackBar` default styling — `colorScheme.inverseSurface` background with `colorScheme.onInverseSurface` text (Material 3 default) — adequate contrast out of the box.
