## Spacing Scale

All values are `EdgeInsets` / `SizedBox` / `margin` expressed as logical pixels.
Must be multiples of 4.

| Token | Value | Flutter Usage |
|-------|-------|---------------|
| xs | 4 dp | Icon gaps, inline icon padding (`SizedBox(width: 4)`) |
| sm | 8 dp | Row spacing between inline elements (`SizedBox(width: 8)`, `SizedBox(height: 8)`) |
| md | 16 dp | Card horizontal margin, section padding (`EdgeInsets.symmetric(horizontal: 16)`) |
| lg | 24 dp | Empty-state vertical spacing, focus-mode section gaps (`SizedBox(height: 24)`) |
| xl | 32 dp | Empty-state horizontal padding (`EdgeInsets.symmetric(horizontal: 32)`) |
| 2xl | 48 dp | Focus-mode goal name bottom padding; focus-mode timer vertical gap |
| 3xl | 64 dp | Focus-mode icon size (not spacing, but same visual grid) |

Exceptions:
- Short break card fixed height: 48 dp (from existing `chunk_card.dart` — preserve as-is).
- Work card internal vertical padding: 12 dp (`EdgeInsets.symmetric(vertical: 12)`) — already established; keep.
- Colored left bar width: 5 dp (established in `chunk_card.dart`; do not change).
- Touch target minimum: 44 dp height for all tappable cards (enforced by Card + 12dp vertical padding on titleMedium).
- Drag handle padding: `EdgeInsets.only(top: 12, bottom: 8)` — both values are multiples of 4; no additional top-padding token is needed.

**Source:** `chunk_card.dart` lines 47, 145–174; `schedule_screen.dart` lines 109, 163, 186.

## Typography

All roles map directly to Material 3 `TextTheme` roles. Use `Theme.of(context).textTheme.*`.
Do not introduce custom `TextStyle` sizes — rely on the theme's scale.

Exactly 4 TextTheme roles are used across the whole phase. Two weights: w400 (regular) and w600 (semibold), plus w300 reserved for the focus timer only.

| Role | TextTheme Role | Weight Override | Line Height | Usage |
|------|---------------|-----------------|-------------|-------|
| Labels / secondary | `bodySmall` | none (theme default w400) | theme default (~1.3) | Durations, "min break", anchored time string, "X of Y Chunks" progress label |
| Body text | `bodyMedium` | none (w400) | 1.5 | Rationale in detail sheet; break suggestion on focus screen |
| Card title / sheet heading / focus goal name | `titleMedium` | `FontWeight.w600` (semibold) | theme default (~1.4) | Goal name as card primary text (READ-01); goal name at top of detail sheet; goal name on focus screen — use w600 wherever emphasis is needed |
| Focus timer countdown | `displaySmall` | `FontWeight.w300` (light) | 1.0 | Countdown digits — large, calm |

Action button labels use the Flutter `FilledButton` / `OutlinedButton` / `TextButton` default label style (`labelLarge`) — this is a widget default, not an additional semantic size.

**Source:** `chunk_card.dart` lines 192–195, 198–203, 208–212; `schedule_screen.dart` lines 172–182; CONTEXT.md — "Claude's Discretion" area for focus mode styling.

## Color

The app theme is `ColorScheme.fromSeed(Colors.deepOrangeAccent)` with ThemeNotifier applying mood-driven HSL modulation (Phase 6). Phase 8 does not introduce new seed colors — it reads from `ColorScheme` roles.

| Role | ColorScheme Source | Flutter Token | Usage |
|------|-------------------|---------------|-------|
| Dominant (60%) | `colorScheme.surface` | Surface background | Scaffold background, ListView background |
| Secondary (30%) | `colorScheme.surfaceContainerHighest` | Card surface, bottom sheet | Chunk cards, detail sheet, skipped section |
| Accent (10%) | `colorScheme.primary` | Primary interactive | Left bar fallback (no goal color), focus CTA button fill, countdown ring |
| Mood color (accent variant) | `_moodColors[moodIndex]` | Schedule AppBar, progress bar | Already established; carry forward unchanged |
| Destructive | `colorScheme.error` | Skip confirmation color, Defer destructive badge | Skip swipe background color, Defer button text |
| Completed state | `Colors.green.shade600` / `Colors.grey.shade400` | Check icon / desaturated left bar | Established in `chunk_card.dart`; preserve |

Accent reserved for:
1. Left-edge colored bar on work cards when no `goalColor` is available.
2. "Start focus" FilledButton in the detail sheet.
3. Countdown ring/progress indicator on the focus screen.
4. Focus screen "Mark complete" FilledButton.

Do NOT use accent for: break cards, sheet drag handles, secondary action buttons (Skip / Defer), or decorative backgrounds.

Goal-color (passed as `goalColor` parameter) takes precedence over accent for the left bar — this is the established pattern; carry it forward.

## Component Specifications

### Surface 1: Chunk Card Restyle (READ-01)

**What changes from existing `chunk_card.dart`:**

The work variant `_HoverableChunkContent` currently renders `chunk.rationale` as the primary `titleMedium` text (line 188–195). Phase 8 inverts this: the goal name becomes `titleMedium` (primary) and the rationale becomes `bodySmall` (secondary).

**New `ChunkCard` constructor signature** (add `goalName` parameter):

```dart
ChunkCard({
  required ScheduledChunk chunk,
  Color? goalColor,
  String? goalName,      // NEW — resolved in ScheduleScreen, passed in
})
```

**Goal name resolution** (in `schedule_screen.dart`, mirroring `_lookupGoalColor`):

```dart
String? _lookupGoalName(BuildContext context, ScheduledChunk chunk) {
  if (chunk.goalId == null) return null;          // commitment chunk: use rationale (block name)
  final goals = context.read<GoalsNotifier>().goals;
  final goal = goals.where((g) => g.id == chunk.goalId).firstOrNull;
  return goal?.name;
}
```

**Work card title hierarchy:**

| Position | Content | Style |
|----------|---------|-------|
| Primary (line 1) | `goalName ?? chunk.rationale ?? 'Work block'` | `titleMedium` + `FontWeight.w600` |
| Secondary (line 2) | Readable rationale string (see Rationale Strings below) | `bodySmall`, `colorScheme.onSurfaceVariant` |
| Secondary (line 2, commitment) | `_formatMinutes(chunk.anchoredStartMinutes!)` | `bodySmall`, `colorScheme.onSurfaceVariant` |
| Trailing | Duration label + status icon | `bodySmall` (unchanged) |

**Commitment-anchored chunks** (null `goalId`): title = `chunk.rationale` (the block name, already stored there). Secondary text = `_formatMinutes(anchoredStartMinutes)`. No change to existing time display logic.

**Break cards**: visually unchanged. `_buildShortBreak` and `_buildLongBreak` do not receive `goalName`.

**Resolved (completed/skipped) state**: unchanged — `contentOpacity: 0.5`, left bar desaturates to `Colors.grey.shade400`.

**Tap affordance** (new): `GestureDetector` wrapping `_HoverableChunkContent` calls `onTap` callback (provided by `ScheduleScreen`) to open the detail sheet. Break cards are NOT tappable.

**Rationale Strings** (static, Phase 8 — Phase 9 replaces with dynamic):

| Original `chunk.rationale` | Displayed secondary text |
|---------------------------|--------------------------|
| `'Habit'` | `'Daily habit'` |
| `'Outcome goal'` | `'Working toward your goal'` |
| `'Weekly goal'` | `'Your weekly time goal'` |
| `block.name` (commitment) | *(shown as title; secondary = anchored time)* |
| `''` (empty) | *(omit secondary line)* |

The mapping is done in `schedule_screen.dart` when building the `goalName` and rationale parameters — `ChunkCard` receives already-resolved strings.

### Surface 2: Schedule Ordering and Visual Continuity (READ-02)

**All logic lives in `ScheduleGeneratorService`** (pure Dart, no Flutter imports).

**Synthetic start-time assignment** for discretionary chunks:

1. Collect all anchored commitment windows (sorted by `anchoredStartMinutes`).
2. Identify free time slots: gaps before the first window, between windows, and after the last window, anchored to a configurable day start (default: 480 min = 8:00 AM).
3. Assign discretionary work chunks + their breaks into gaps in sequence, stepping by 30 min per work chunk (25 min work + 5 min break) or 50 min after the 3rd/4th work chunk (25 + 25 long break).
4. Sort the final chunk list by effective start time.

**Break trimming rule:**

After the sort + assignment pass, if the last element in the result list is a break (`chunkType != ChunkType.work`), remove it.

**No breaks inside commitment windows:**

When chunking a `CommitmentBlock` into 25-min pieces, no short or long breaks are inserted between those pieces. Break insertion applies only to discretionary work chunks. Commitment chunks within a single block are consecutive.

**Visual continuity indicator (optional, at Claude's discretion):**

A subtle divider (`Divider(height: 1, indent: 16, endIndent: 16)`) between the last commitment-anchored chunk and the first discretionary chunk that follows is acceptable but not required. Decision: omit in Phase 8 for simplicity — the time labels on commitment chunks already create visual separation.

### Surface 3: Chunk Detail Bottom Sheet (READ-03)

**Trigger:** Tap on any work chunk card (not break cards, not resolved chunks).

**Presentation:** `showModalBottomSheet` with `isScrollControlled: true`, `shape: RoundedRectangleBorder(borderRadius: BorderRadius.vertical(top: Radius.circular(16)))`. Matches the Phase 2 goal form sheet pattern.

**Sheet widget name:** `ChunkDetailSheet` (new file: `lib/screens/schedule/widgets/chunk_detail_sheet.dart`).

**Sheet content layout (top to bottom):**

```
┌──────────────────────────────────────────┐
│  [drag handle — centered, top: 12dp]     │
│                                          │
│  [goal color bar, 4dp wide, left edge   │
│   of a Card inside the sheet]           │
│                                          │
│  Goal Name                 titleMedium   │
│  Rationale text            bodyMedium    │
│  Anchored time (if any)    bodySmall     │
│                                          │
│  ──────────────────────────────────────  │
│                                          │
│  [FilledButton]  Mark complete           │
│  [OutlinedButton] Skip chunk            │
│  [TextButton]    Defer to later         │
│                                          │
└──────────────────────────────────────────┘
```

**Drag handle:** `Container(width: 32, height: 4, decoration: BoxDecoration(color: colorScheme.onSurfaceVariant.withValues(alpha: 0.4), borderRadius: BorderRadius.circular(2)))`, centered horizontally, `EdgeInsets.only(top: 12, bottom: 8)`.

**Goal color mini-bar:** `Container(width: 4, height: 48, decoration: BoxDecoration(color: goalColor ?? colorScheme.primary, borderRadius: BorderRadius.circular(2)))` to the left of the goal name + rationale block, inside a `Row`.

**Sheet heading typography:** Goal name rendered with `titleMedium` + `FontWeight.w600`. Rationale rendered with `bodyMedium` at line-height 1.5.

**Action buttons:**

| Button | Type | Icon | Action |
|--------|------|------|--------|
| Mark complete | `FilledButton.icon` | `Icons.check_circle_outline` | `scheduleNotifier.markComplete(chunk.id); Navigator.pop(context)` |
| Skip chunk | `OutlinedButton.icon` | `Icons.skip_next_outlined` | `scheduleNotifier.markSkipped(chunk.id); Navigator.pop(context)` |
| Defer to later | `TextButton.icon` | `Icons.schedule_outlined` | `scheduleNotifier.markDeferred(chunk.id); Navigator.pop(context)` |

All three buttons span full width (`SizedBox(width: double.infinity, child: ...)`), stacked vertically with `sm` (8 dp) gaps between them.

**Two-tap confirmation for destructive actions:** Opening the sheet and then tapping "Skip chunk" or "Defer to later" IS the full confirmation flow. No separate confirm dialog is shown. The two steps (open sheet → tap action) serve as the intentional double-confirmation. This applies to both Skip chunk and Defer to later.

**"Start focus" entry point:** `TextButton.icon(icon: Icon(Icons.center_focus_strong_outlined), label: Text('Start focus'))` placed above the action buttons, right-aligned or full-width. Taps `context.push('/focus', extra: chunk.id)` and closes the sheet.

**Defer behavior (Phase 8 minimal):** `markDeferred` removes the chunk from today's active view (same visual outcome as skip — chunk moves to skipped section). Full cross-day carryover is Phase 10. The button is present and functional; its cross-day effect is deferred.

**Resolved chunks:** If the sheet is opened on an already-completed or already-skipped chunk (e.g., via future edge cases), show goal name + rationale only, with a status badge (`'Completed'` / `'Skipped'`) and no action buttons.

### Surface 4: Focus Mode — `/focus` Route (READ-04)

**Route:** `/focus` — outside `StatefulShellRoute` (no bottom nav), alongside `/summary` and `/review` in `router.dart`. Receives `chunk.id` as `extra` parameter: `GoRoute(path: '/focus', builder: (context, state) => FocusScreen(chunkId: state.extra as String))`.

**Widget name:** `FocusScreen` (new file: `lib/screens/focus/focus_screen.dart`).

**"Current chunk" definition:** The `FocusScreen` receives an explicit `chunkId`. If that chunk is already resolved on arrival, navigate back immediately with a pop. The schedule screen also exposes a "Start focus" entry point that passes the first unresolved work chunk's id (first in day order, `chunkType == ChunkType.work && !isCompleted && !isSkipped`).

**Full-screen layout (single-column, centered):**

```
┌─────────────────────────────────────────────┐
│  AppBar: back arrow only, transparent,      │
│          title: '' (no title in focus mode) │
│                                             │
│  [top 1/3 area]                             │
│  Goal color bar (full-width, 4dp height)    │
│  Goal name           titleMedium w600       │
│  Rationale           bodyMedium             │
│                                             │
│  [center area]                              │
│  Timer display: MM:SS                       │
│    displaySmall, w300, centered             │
│    circular progress ring (optional)        │
│    wraps CircularProgressIndicator or       │
│    custom arc via CustomPainter             │
│                                             │
│  [button row]                               │
│  [Start / Pause] FilledButton  ← primary    │
│  [Done early]    OutlinedButton             │
│                                             │
│  [bottom section — visible after complete] │
│  Break suggestion: "Take a 5 min break"    │
│    bodyMedium, centered                     │
│  [Back to schedule] TextButton              │
└─────────────────────────────────────────────┘
```

**AppBar:** `AppBar(backgroundColor: Colors.transparent, elevation: 0, leading: BackButton())`. The Scaffold `extendBodyBehindAppBar: false` (standard).

**Goal color bar:** Full-width `Container(height: 4, color: goalColor ?? colorScheme.primary)` at the very top of the body, flush with the AppBar bottom.

**Timer states:**

| State | Display | Button state |
|-------|---------|--------------|
| Not started | `25:00` | FilledButton label: "Start 25 min timer" |
| Running | `MM:SS` counting down | FilledButton label: "Pause", OutlinedButton: "Done early" |
| Paused | `MM:SS` frozen | FilledButton label: "Resume", OutlinedButton: "Done early" |
| Finished (timer hits 0) | `0:00` | Both buttons hidden; show break suggestion + "Mark complete" FilledButton |
| Done early (user tapped) | *(dismiss timer)* | Show break suggestion + "Mark complete" FilledButton |

**Timer implementation:** `StatefulWidget` with a `Timer.periodic(Duration(seconds: 1), ...)` driving a local `_secondsRemaining` int. Start at 1500 (25 × 60). Timer is cancelled in `dispose()`. No background execution.

**"Mark complete" action (after timer finishes or Done early):** calls `context.read<ScheduleNotifier>().markComplete(chunkId)` then shows the break suggestion inline (does not auto-navigate). User taps "Back to schedule" (`TextButton`) to pop.

**Break suggestion copy:** Derived from the next chunk in `scheduleNotifier.todaySchedule!.chunks` after the current chunk. If next chunk is a `shortBreak`: `"Nice work. Take a 5 min break."`. If `longBreak`: `"Great focus block. Take a 25 min break."`. If no next chunk: `"You're done for now."`.

**"Skip timer" affordance:** A `TextButton(child: Text('Skip timer'))` below the Start button when the timer has not yet started. Tapping it takes the user directly to the "Done early" state (shows break suggestion + Mark complete).

**Back navigation:** `BackButton` in AppBar pops without marking complete. No confirmation dialog — the chunk remains unresolved if the user backs out.

## Interaction Contracts

### Tap Targets

| Element | Min Size | Flutter Implementation |
|---------|----------|----------------------|
| Work chunk card | 44 × 44 dp | Card + 12dp vertical padding on titleMedium achieves this |
| Break card | 48 dp height | Existing `Container(height: 48)` — do not reduce |
| Bottom sheet buttons | 44 dp height (FilledButton default) | `FilledButton` Material 3 default height 40dp → use `SizedBox(height: 48, child: ...)` wrapper |
| Focus timer Start button | 56 dp height | `SizedBox(height: 56, child: FilledButton(...))` |

### Swipe Gesture Preservation

Phase 8 adds tap-to-open-sheet on work cards. The `Dismissible` in `SwipeableChunkCard` must remain as the outer wrapper. The `GestureDetector` for tap must be inside the `Dismissible` child (i.e., inside `ChunkCard` on the work variant). This ensures horizontal swipes are captured by `Dismissible` before `GestureDetector` sees them. Vertical scroll takes priority over both (standard Flutter gesture arena behavior).

### Bottom Sheet Dismissal

`showModalBottomSheet` with default `isDismissible: true` — user can tap the scrim or drag the sheet down to dismiss without taking action. No confirmation required for dismissal.

### Focus Screen Entry Points

Two valid entry paths to `/focus`:

1. **Via detail sheet** "Start focus" button: `context.push('/focus', extra: chunk.id)`.
2. **Via schedule screen** "Focus" action: A `FloatingActionButton.small` or an `IconButton` in the AppBar actions that passes the first unresolved work chunk id. If the `IconButton` variant is used, declare `tooltip: 'Start focus'` on the `IconButton`. Implementation choice is at executor's discretion; the route and parameter contract is fixed.
