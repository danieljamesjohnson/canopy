## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI → Provider → Service | `lighterDay` (bool) and mood (int) originate in the check-in widget and pass through the notifier into the pure engine. CompletionLog history is read from local Hive (trusted, append-only). No network/auth crosses here. |
| Provider → GoalRepository | Streak write-back persists a recomputed `streakCount` back to local Hive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-07 | Tampering | streak write-back vs completion flag | mitigate | Streak save sits INSIDE the existing `try`; the `catch { chunk.isCompleted = false; rethrow; }` revert keeps schedule, log, and streak consistent if `_goalRepo.save` throws. |
| T-09-08 | Information Disclosure / Integrity | commitment chunks logged with `goalId: ''` | mitigate | Streak write-back guards `chunk.goalId != null && chunk.goalId!.isNotEmpty` and only acts on habit goals fetched by real UUID; `getByGoalId('')` is never called, so empty-id commitment logs never inflate streak/budget. |
| T-09-09 | Denial of Service | empty/large completion history during fetch | mitigate | Per-goal `getByGoalId` (not `getAll`); only active goals fetched; the streak walk stops at the first non-completed due day. Empty history yields streak 0, never a crash. |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase. No legitimacy surface. |

Proportional to a local offline engine: the only meaningful risks are state divergence on a failed write (mitigated by the existing revert) and empty-goalId contamination (mitigated by the non-empty UUID guard).
