## Spacing Scale

Declared values (multiples of 4, matching existing form sheet conventions):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon gaps, inline padding |
| sm | 8dp | Tight element spacing (e.g. Cancel/Save button gap) |

| lg | 24dp | Section padding |
| xl | 32dp | Layout gaps |

Exceptions:
- Priority control label-to-widget gap: 8dp (matches the "Sessions per week" Slider label pattern in goal_form_sheet.dart — label Row then Slider with no SizedBox between)

Source: goal_form_sheet.dart — existing `SizedBox(height: 16)` pattern throughout; `EdgeInsets.fromLTRB(16, 16, 16, ...)` outer padding.

## Component Inventory

### New: Priority SegmentedButton (ENGINE-06)

**Location:** `lib/screens/goals/goal_form_sheet.dart`

**Insertion point:** After the goal name `TextField` (after its `SizedBox(height: 16)`), before type-specific fields. This places it under name/type as specified in CONTEXT.md.

**Widget:** `SegmentedButton<double>` from `package:flutter/material.dart` (Material 3 built-in — no additional packages required).

**Segments:**

| Segment label | `value` | Maps to `priorityWeight` |
|---------------|---------|--------------------------|
| Low | 0.25 | 0.25 |
| Normal | 0.5 | 0.5 |
| High | 0.75 | 0.75 |

**Default:** Normal (0.5). Existing goals where `priorityWeight == null` render as Normal selected. No data migration required.

**State variable:** `_priorityWeight` already exists in `_GoalFormSheetState` (line 27). It holds `double?`. The SegmentedButton selected value is `_priorityWeight ?? 0.5` for display; `setState(() => _priorityWeight = value)` on selection.

**Label above control:** A `Row` child with `Text('Priority', style: theme.textTheme.bodyMedium)` — matching the "Sessions per week: N" label pattern for the Slider (goal_form_sheet.dart line 244-248). No dynamic value appended (unlike the Slider label which echoes the numeric value).

**Full insertion block:**

```
Row(
  children: [
    Text('Priority', style: theme.textTheme.bodyMedium),
  ],
),
SegmentedButton<double>(
  segments: const [
    ButtonSegment(value: 0.25, label: Text('Low')),
    ButtonSegment(value: 0.5,  label: Text('Normal')),
    ButtonSegment(value: 0.75, label: Text('High')),
  ],
  selected: {_priorityWeight ?? 0.5},
  onSelectionChanged: (Set<double> val) =>
      setState(() => _priorityWeight = val.first),
),
const SizedBox(height: 16),
```

**Touch target:** SegmentedButton segments are at least 48dp tall by Material 3 specification. No override needed.

**Dark mode:** ThemeNotifier provides light/dark ColorScheme; SegmentedButton inherits automatically. No manual color specification needed.

Source: CONTEXT.md decisions block — "3-segment SegmentedButton (Low / Normal / High), shown for all goal types, placed near the top of the goal form under name/type, mapping Low=0.25 / Normal=0.5 / High=0.75, default Normal."

### Modified: Check-in "Want a lighter day?" toggle (ENGINE-05)

**Location:** `lib/screens/schedule/checkin_screen.dart`

**Visual change:** NONE. The toggle UI already exists at lines 193-211. The only change is plumbing `_lighterDay` through to `generateToday()`. This phase passes `lighterDay: _lighterDay` as a named parameter.

**Behavioral change:** At mood 3–5, lighter ON reduces effective capacity by one mood tier. At mood 1–2, lighter OFF (heavier) adds back deadline-critical outcome work. The toggle is already shown only for mood 1–2 (`if (_selectedMood != null && _selectedMood! <= 2)`). Per CONTEXT.md, the toggle should become visible for moods 3–5 too (since that is now the operative case). See interaction note below.

**Interaction note:** The toggle display condition must be updated from `_selectedMood! <= 2` to show for all moods 1–5 once a mood is selected. The label "Want a lighter day?" remains unchanged.

**No new copywriting.** No new visual elements.

Source: CONTEXT.md — "At mood 3–5 the toggle reduces the effective capacity by one mood tier... At mood 1–2 the day is already restricted to habits + deadline-critical work; lighter OFF (heavier) adds back deadline-critical outcome work."

## Accessibility

- SegmentedButton segments must have semantics labels matching their text ("Low", "Normal", "High") — provided automatically by Flutter's `SegmentedButton` widget.
- Minimum touch target: 48dp height on SegmentedButton — guaranteed by Material 3 spec.
- Contrast: SegmentedButton inherits `colorScheme` — meets Material 3 contrast requirements for both light and dark themes automatically.
- The toggle remains a `Switch` widget — no change to its accessibility contract.
