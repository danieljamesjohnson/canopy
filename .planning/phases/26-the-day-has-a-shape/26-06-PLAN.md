## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet → static file server | `tools/serve-uat.py` binds `0.0.0.0` and serves `build/web` read-only. Reachable only over Tailscale and the local LAN — no public exposure (per the machine's operating guide). It serves a debug build containing source maps and unminified Dart, which is deliberate for diagnosability and is not a disclosure concern on a single-user private tailnet. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-09 | Spoofing (of the artefact under test, not of a principal) | the served bundle | mitigate | A stale service worker or a heuristically-cached `main.dart.js` can present a previous build as if it were the new one, producing a false UAT verdict — this already happened once in this project. Mitigated by a never-before-used port (no leftover service worker can be scoped to it), `--pwa-strategy=none` (registers none), `tools/serve-uat.py`'s `no-store` headers, and a `curl | grep` byte-level probe for this phase's new copy string before Dan is asked to look. |
| T-26-10 | Information disclosure | debug build with source maps on the tailnet | accept | The build contains unminified Dart and source maps. The host is reachable only over Tailscale and the LAN, is single-user, and the repo is public anyway as a work sample — there is nothing in the bundle that is not already on GitHub. Debug-over-release is a deliberate, documented diagnosability choice in CLAUDE.md. |
| T-26-SC | Tampering | package installs | accept | No packages installed in this phase; `pubspec.yaml` untouched from first commit to last. |

Honest note: this is the only plan in the phase with a genuine boundary at all, and it is a
read-only static file server on a private tailnet. The register is short because the surface is.
