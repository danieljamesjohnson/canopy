<objective>
Teach the row vocabulary to render at a duration-driven density, and strip the per-row time
gutter down to a reserved blank column, without changing anything TodayScreen currently shows.
Every new parameter defaults to today's behaviour, so this plan is a capability addition, not a
visual change.

Purpose: plan 04 positions each row inside a fixed-height pixel slot. A card that does not know
how to shrink will overflow that slot. **D-02** is the reason it must shrink rather than be
rescued: gap compression and min/max row-height clamping are both explicitly rejected, so a
5-minute break gets a 27.5px box and the only thing allowed to change is what is drawn inside
it. This plan makes that shrinking possible and provable in isolation, before any layout is
rewritten.

Output: `ChunkCardDensity` and its two new render paths, a parameterised dashed-border painter,
an inset-only `TimelineRowTile`, and a vertically-centring `FreeTimeRow`.
</objective>

## Locked planner decisions this plan implements

**PD-4 — the density enum has THREE values, with `detailed` as the default.** The UI-SPEC's
two-tier model (Full / Compact) assumes the caller always wants the trimmed card. But
`ChunkCard` is pumped directly by four standalone test files
(`chunk_card_priority_badge_test.dart`, `chunk_card_valence_test.dart`,
`chunk_card_goal_name_test.dart`, `chunk_card_hover_test.dart`) that assert the rationale line,
the priority chip and the valence chip render — coverage for GOALS-02 and ENERGY-04b, which are
still live requirements. Making `full` the default would silently delete that coverage and
inflate this phase's blast radius well past the ~30 tests `26-RESEARCH.md` counted. So:
`ChunkCardDensity.detailed` (default) is today's card, byte-for-byte; `full` is the UI-SPEC's
trimmed Full tier; `compact` is the UI-SPEC's Compact tier. Only `today_screen.dart` ever asks
for `full` or `compact`, and it does not do so until plan 04.

**PD-5 — `TimelineRowTile` is kept as a pure inset wrapper and its `startMinutes` parameter is
deleted outright** (`26-RESEARCH.md` Open Question 2, recommendation adopted;
`26-PATTERNS.md` concurs). Keeping the parameter with no consumer is exactly the dead-path debt
this codebase has repeatedly paid down. The 16dp inset and the `kGutterWidth` reserved column
stay, because the hour axis (plan 01) reuses both to line its labels up with row content.

**PD-6 — "breaks lose their tap target" is NOT a task.** `26-RESEARCH.md` Pitfall 6 and
`26-PATTERNS.md` both verified against the live tree that `SwipeableChunkCard.build()` returns a
bare `ChunkCard` for non-work chunks with no `onTap` forwarded, and `ChunkCard._buildBreak`
contains no `GestureDetector`. There is nothing to remove. Do not write a task, a diff, or a
test for it.
