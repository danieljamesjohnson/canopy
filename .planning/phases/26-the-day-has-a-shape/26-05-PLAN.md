## Locked planner decisions this plan implements

**PD-15 — `ScrollController(initialScrollOffset:)` is forbidden.** `flutter/flutter#96924`
documents a hard crash on iOS from an out-of-bounds `initialScrollOffset`, and the offset here
depends on runtime data (chunk count and durations), so it cannot be safely clamped at
construction time. Use the existing post-frame-callback + `animateTo` shape, which operates on an
already-laid-out, already-attached controller.

**PD-16 — `maxScrollExtent` is read INSIDE the post-frame callback, never in `build()`.**
`rangeStart`, `rangeEnd` and `nowMinutes` are pure arithmetic on already-known data and can be
computed synchronously; `maxScrollExtent` is only valid after the `Stack`'s fixed height and the
viewport have both been laid out. This mirrors the ordering discipline the existing
`_liveRowKey.currentContext` null-check already follows — the pattern is not new to this phase,
only the arithmetic inside it is.

**PD-17 — the `Stack`'s top offset inside the scroll content is queried, not assumed.** On a
mood-≤2 day the restoratives card scrolls above the timeline `Stack`, so
`geometry.yFor(nowMinutes)` is NOT the scroll offset of "now". Resolve the `Stack`'s own leading
offset with `RenderAbstractViewport.of(stackBox).getOffsetToReveal(stackBox, 0.0).offset` — the
same machinery `ensureVisible` uses internally — and add `geometry.yFor(nowMinutes)` to it.
Rejected: moving the restoratives card out of the scroll view (a visible behaviour change on
exactly the days a low-mood user needs the viewport most) and hard-coding a leading height.

**PD-18 — landing alignment stays centred (0.5).** Reusing the exact value Phase 22/24 validated,
per the UI-SPEC, with the same 250ms / `Curves.easeOut`, so the felt motion is unchanged even
though the mechanism computing the destination is new.

**PD-19 — one flag means a state transition does NOT re-centre.** Phase 24 needed two flags
because a day could open in PreStart (marker fallback fires) and later cross into Active (live
row must still be centrable). That branch no longer exists: the now-line always exists at a
computable offset in every state, so opening centres once on "now" regardless of state, and a
later PreStart→Active transition is just the line having moved a few pixels. Re-centring on a
transition would be precisely the "dragging the list out from under a reading user" the one-shot
exists to prevent. The 24-04 two-flag regression test is therefore rewritten, not preserved — its
premise is gone.
