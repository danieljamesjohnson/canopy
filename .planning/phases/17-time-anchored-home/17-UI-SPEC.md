# Phase 17 — UI Design Contract

> Visual and interaction contract for Phase 17: Time-Anchored Home.
> Generated by gsd-ui-researcher.
>
> **Scope note:** This phase reworks the EXISTING Home screen's "Now" and "Next"
> presentation. It is a behavior/correctness change plus two new inline states —
> not a new screen and not a new design language. All tokens, widget shapes,
> and color roles are locked from the existing codebase. This contract specifies
> what changes (chunk selection logic, new state copy, new state visual treatment)
> and what must NOT change (card shape, spacing, typography roles, color tokens).

## State Machine Contract

The Home screen's active-schedule branch (when `hasScheduleToday == true`) must implement the following four mutually exclusive "Now" states. Exactly one is shown at a time.

### State 1: Active chunk (chunk window contains now)

**Condition:** At least one work chunk exists whose `[displayStartMinutes, displayStartMinutes + durationMinutes)` window contains `currentMinutesSinceMidnight`. The matched chunk is neither `isCompleted` nor `isSkipped`.

**Visual:** Existing `ActiveChunkCard` widget — no visual change. Shows the matched chunk.

**"Next" section:** The next scheduled work chunk after the matched chunk's window ends. Rendered as the existing compact "Next" row. If no subsequent chunk exists, "Next" section is hidden.

### State 2: Pre-start (before the first chunk window)

**Condition:** Current time is before `displayStartMinutes` of the first work chunk in the day's schedule (and that chunk is not yet completed/skipped).

**Visual treatment:** Inline — no card, no full-screen takeover. Same inline zone as the existing "Now" content area.

**Layout:**
```
Section label:   "Now"              (labelMedium, onSurfaceVariant, letterSpacing 0.8)
Heading:         "Your day starts at [TIME]"   (titleMedium w600)
Body:            "[GOAL_NAME] · [DURATION] min"  (bodyMedium, onSurfaceVariant)
```

Where `[TIME]` is the first chunk's `displayStartMinutes` formatted via `formatMinutes()` (existing utility). `[GOAL_NAME]` is the first chunk's goal name (or rationale fallback). `[DURATION]` is `durationMinutes`.

**"Next" section:** Hidden — there is no active "Now", so "Next" has no anchor. The "See full schedule" link below the mood row remains.

**Padding:** `Padding(padding: EdgeInsets.symmetric(horizontal: 16, vertical: 8))` — same as the existing "All done today!" inline text.

### State 3: Between-chunks gap (in a gap between chunk windows)

**Condition:** Current time is past the end of a chunk that has not been completed/skipped (i.e., its window has passed but the user has not resolved it), AND current time is before the start of the next chunk's window.

**Visual treatment:** Show the `ActiveChunkCard` for the MOST RECENTLY PAST chunk (the overdue chunk) — it is still the user's actionable item. This is the "chunk is overdue" case, not a new state. The card renders normally with its "Now" badge. The executor may add a subtle visual indicator that the chunk is past its window (see "Overdue indicator" below), but this is at Claude's discretion and must not change the card's primary layout.

**Overdue indicator (Claude's discretion):** A single-line subtext below the clock-time line, `bodySmall` at `onSurfaceVariant`, reading: `"Started [TIME]"` where `[TIME]` is the chunk's `displayStartMinutes` formatted via `formatMinutes()`. This reuses existing text style — no new widget needed. Only show this when the chunk's window start is more than 0 minutes in the past AND the chunk is unresolved.

**"Next" section:** The next scheduled work chunk (the upcoming one). Rendered as existing compact "Next" row.

### State 4: Day-complete (all chunk windows have passed)

**Condition:** Current time is past `displayStartMinutes + durationMinutes` of the LAST work chunk in the schedule (regardless of resolved/unresolved status). OR: all work chunks are resolved (completed or skipped) and no window is currently active.

**Visual treatment:** Inline in the "Now" zone — same padding as pre-start state. No card.

**Layout:**
```
Section label:   "Now"            (labelMedium, onSurfaceVariant, letterSpacing 0.8)
Heading:         "That's a wrap"  (titleMedium w600)
Body:            "You've reached the end of today's schedule."  (bodyMedium, onSurfaceVariant)
```

**"Next" section:** Hidden — the day is over. The "See full schedule" link and mood row remain visible below.

**Relationship to EndOfDayCard:** The day-complete state and `EndOfDayCard` are NOT the same thing and must coexist. `EndOfDayCard` is a dismissable banner that prompts the user to close the day (triggered by time ≥ 18:00 or ≥ 50% resolved). Day-complete state is the "Now" zone replacement. Both can appear simultaneously — the `EndOfDayCard` renders above the "Now" zone, day-complete state renders in the "Now" zone below it.

## Chunk Selection Logic Contract

**Old logic (to be replaced):**
```dart
final unresolvedWork = schedule.chunks
    .where((c) => c.chunkType == ChunkType.work && !c.isCompleted && !c.isSkipped)
    .toList();
final currentChunk = unresolvedWork.isNotEmpty ? unresolvedWork.first : null;
final nextChunk = unresolvedWork.length > 1 ? unresolvedWork[1] : null;
```

**New logic (to implement):**
```
currentMinutes = DateTime.now().hour * 60 + DateTime.now().minute

// Ordered list of all work chunks (completed or not), by displayStartMinutes asc
allWork = schedule.chunks
    .where((c) => c.chunkType == ChunkType.work && c.displayStartMinutes != null)
    .toList()
    ..sort by displayStartMinutes ascending

// State classification:
if allWork.isEmpty:
    → show day-complete state (no chunks scheduled)

if currentMinutes < allWork.first.displayStartMinutes:
    → pre-start state; firstChunk = allWork.first

else if currentMinutes >= allWork.last.displayStartMinutes + allWork.last.durationMinutes:
    → day-complete state

else:
    // Find the chunk whose window contains now OR the most recent overdue unresolved chunk
    activeChunk = allWork.lastWhere(
        (c) => c.displayStartMinutes! <= currentMinutes,
        orElse: null
    )
    // If that chunk's window has also ended, it is "overdue" — still show it as Now
    // so user can complete/skip it before the next chunk starts
    currentChunk = activeChunk (unresolved) OR next unresolved after activeChunk's window

    nextChunk = next work chunk after currentChunk in schedule order
```

**Key invariant:** If a chunk is completed or skipped, it is never shown as "Now." The selection advances to the next unresolved chunk within the current or upcoming window. If all chunks are resolved, show day-complete state.

**Implementation note:** The executor must derive a concrete `_resolveNowState()` function from this logic. The pseudo-code above is intentionally descriptive, not literal Dart. The function must accept a `DateTime Function() now` injectable parameter (matching the existing `ScheduleNotifier` and `ThemeNotifier` pattern) to enable unit testing without real wall-clock time.

## Timer / Live Update Contract

"Now" must update with the passage of time, not only on user actions.

**Mechanism:** `HomeScreen` must drive a 1-minute periodic timer (matching the minute granularity of `displayStartMinutes`). The timer calls `setState()` on `_HomeScreenState` to trigger a rebuild that re-evaluates `_resolveNowState()`.

**Timer lifecycle:**
- Start in `initState()`.
- Cancel in `dispose()`.
- Pause/resume on `AppLifecycleState` changes (follow `ScheduleNotifier` / `ThemeNotifier` lifecycle observer pattern — register `WidgetsBindingObserver`, cancel on `paused`, restart on `resumed`).
- The timer does NOT need to call any notifier — it only needs to rebuild the Home widget, since `_resolveNowState()` is a pure function of `DateTime.now()` and the existing `schedule.chunks`.

**Granularity:** 1-minute interval (60 seconds). Chunk boundaries are expressed in whole minutes (`displayStartMinutes`), so sub-minute polling is unnecessary.

**Reduced-motion:** Timer fires regardless of reduced-motion setting — it is a state update, not an animation. No accessibility guard needed.

## Now Card — Active State Contract

When State 1 (active chunk) or State 3 (between-chunks / overdue) is shown, render `ActiveChunkCard` with no visual change to the card widget itself. The only change is which chunk is passed to it.

**"Now" badge:** `colorScheme.primary` fill, `colorScheme.onPrimary` label, text "Now". Unchanged.

**Left color bar:** Goal's `color` hex, or `colorScheme.primary` fallback. Unchanged.

**Action row:** "Complete" (`FilledButton.icon`) and "Skip" (`OutlinedButton.icon`). Unchanged.

**Priority chip:** Shown when `priorityWeight != 0.5` and `priorityWeight != null`. Unchanged.

## Next Row Contract

When a next chunk exists (State 1 or State 3), render the existing compact "Next" row:
- Goal name (`titleMedium w600`) + rationale fallback.
- Optional `bodySmall` subtitle (rationale if goal name is present).
- Clock-time range (`bodySmall`, `onSurfaceVariant`) right-aligned.

The "Next" row selects the first unresolved work chunk AFTER the current "Now" chunk in schedule order. "After" means: `displayStartMinutes` is greater than the `Now` chunk's `displayStartMinutes`. If no such chunk exists, hide the "Next" section.

## State Boundary Handling

| Edge Case | Handling |
|-----------|----------|
| Chunk with `displayStartMinutes == null` | Exclude from time-window calculation; treat as having no clock position. These chunks cannot participate in "active" matching. |
| All work chunks have `displayStartMinutes == null` | Fall back to the old "first unresolved" behavior (no regression for schedules generated without clock times). |
| Chunk completed/skipped mid-window | Advance to next unresolved chunk in schedule order. If none, show day-complete state. |
| Last chunk ends exactly at current minute (boundary) | `currentMinutes >= lastChunk.displayStartMinutes + lastChunk.durationMinutes` is `true` → day-complete. |
| No work chunks in schedule (breaks/commitments only) | Show day-complete state — the "work" day has no scheduled work chunks. |
| Schedule has chunks but user is viewing before midnight (e.g., late-night planning) | Pre-start state if `currentMinutes < firstChunk.displayStartMinutes`. |

## Widget Test Contract

All tests must use `pumpWithMood` (from `test/test_helpers/mood_pump.dart`) with default `moodIndex: 3` (seed `#4A8C7A`). Do not construct `ThemeNotifier` directly in tests.

**The `now` parameter must be injectable.** The `_resolveNowState()` function (or its equivalent) must accept a `DateTime Function() now` parameter so tests can simulate specific times without sleeping or mocking `DateTime.now`.

**Scenarios to cover:**
1. Pre-start: `now` = 6:00 AM, first chunk starts at 8:00 AM → pre-start heading shown, first chunk name/time in body.
2. Active: `now` = 9:00 AM, chunk window = 8:30–9:30 AM → `ActiveChunkCard` shown for that chunk.
3. Between-chunks: `now` = 10:00 AM, chunk 1 window = 8:30–9:30, chunk 2 window = 10:30–11:30 → overdue chunk 1 shown as Now; chunk 2 shown as Next.
4. Day-complete (time-based): `now` = 6:00 PM, all chunk windows have passed → day-complete heading shown.
5. Day-complete (all-resolved): all work chunks `isCompleted` or `isSkipped` → day-complete heading shown.
6. Timer: after 1-minute timer fires, state transitions from pre-start to active when `now` crosses the first chunk's start minute.
