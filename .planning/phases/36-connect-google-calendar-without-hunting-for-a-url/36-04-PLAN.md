<objective>
The scaffolding half of D-36-01, which the owner correctly predicted would be the slow part: get the
client ID from one gitignored file into two places that need it — Dart, and the iOS URL-scheme
registration — without ever committing it, and make a build without it fail loudly instead of quietly.

Purpose: CALAUTH-04 says no client secret exists in the repository. For a native iOS client that is
free — Google does not issue one, and its own native-app documentation says the secret parameter is
not applicable to iOS clients at all. What is NOT free is the client **ID**: CONTEXT decision 1
locks it to build-time injection from the gitignored `.google-client-id`, and `Info.plist` normally
wants that value written in as a literal. This plan is how both constraints hold at once.

Output: a `CFBundleURLTypes` entry driven by a build setting, a build wrapper that derives it, and
the machine checks that prove no secret and no committed ID.

Decisions implemented: **D-36-01** (native iOS client, reversed-client-ID redirect, no secret),
**D-36-02** (the OAuth client is registered against the renamed bundle ID, which is the thing a
mismatch here would break).

|----------|-------------|
| `.google-client-id` on disk -> the build | A private-by-owner-preference value crosses into generated build artifacts and must not cross into git |

| Cloud Console registration -> the built app | The bundle identifier must match exactly or sign-in fails in a way that reads as a code bug |
