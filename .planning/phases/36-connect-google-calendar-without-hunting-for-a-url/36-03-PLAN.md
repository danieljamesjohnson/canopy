<objective>
Build out the mapping layer from the tracer's one happy path to the full set of shapes Google
actually returns — and settle CALAUTH-02 mechanically while the file is open.

Purpose: this is the one place where the Google path is genuinely BETTER than the `.ics` path and
not merely different. `singleEvents=true` expands a recurrence with its exceptions applied, so a
moved occurrence resolves to where it actually is — `WINDOWS.md` entry 1, which Phase 35 proved the
ICS stack cannot fix. If that holds, it is worth saying loudly, because it changes which path the
owner should prefer on the browser and desktop builds.

**The correction on the record applies here and must not be overstated.** This is an advantage over
the **`.ics`** path only. On iOS the device path already returns expanded occurrences with exceptions
applied (Phase 35 Assumption A1), so Google sign-in adds no recurrence advantage there — and A1 is
itself still unverified, because 35-05's device gate is open. Any claim in the SUMMARY must be scoped
to the `.ics` comparison.

Output: pure mapping functions with fixture-driven tests, `CalendarInfo.sourceLabel`, and the
read-only scope proven by grep rather than asserted in prose.

  <behavior>
    - A recurring series with one instance moved: the moved instance maps with `start` equal to its own `dateTime`, NOT to `originalStartTime`. Its siblings map at the base times.
    - The moved instance's `uid` is the series id and its `recurrenceId` is the instance id — so all instances of one series share a uid, and each instance has its own occurrence identity, matching the `CalendarSource` interface's documented contract.
    - A cancelled instance, returned only because `showDeleted` is true, maps to `CalendarEventStatus.cancelled` and is NOT dropped by the mapper. Downstream, `CalendarSyncService` skips it with the existing cancelled reason.
    - A cancelled stub carrying no `start` and no `end` at all — the minimal shape Google returns for a deleted instance — maps by falling back to `originalStartTime`, and if that is also absent, is dropped without throwing. This is the shape most likely to crash a naive mapper.
    - An all-day event (its `start` carries `date`, not `dateTime`) maps with `isAllDay` true and a start/end spanning that local calendar day.
    - A timed event whose `dateTime` carries a non-local UTC offset maps to the correct absolute instant, and is NOT re-anchored to this machine's system timezone.
    - An event with no `summary` (which cancelled stubs routinely lack) maps to a non-null title rather than throwing.
    - A `tentative` event maps to tentative and still imports — matching the ICS path's existing behaviour exactly.
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google Calendar API -> app | Event titles, calendar names and colours are untrusted free text rendered in the UI |
| app -> Google Calendar API | Every outbound call must carry only read verbs and only a read-only token |
