## Two copy rulings this plan takes, with reasons

**1. The reconnect card's colour.** `36-PATTERNS.md` flagged this as a genuine open call rather than a
settled pattern. Ruling: copy `_deniedCard`'s structure exactly — neutral `surface`, `outline` border
— but render its **icon** in `colorScheme.error`. `_deniedCard` is deliberately neutral because a
denied permission is a user's choice and not a fault, and 35-UI-SPEC's colour contract reserves the
error role for "a genuine failure, not a benign state". An expired refresh token is a real operation
that really failed, and the user is being shown data that is really out of date. That is the error
role's own definition, so this is consistent with the locked contract rather than an exception to it.
The card body stays neutral so the screen does not shout.

**2. A `Disconnect` action exists, and its copy does not repeat an existing false claim.** The
shipped "Remove this calendar?" dialog tells the user that already-imported commitments "will
disappear the next time you sync" — but `CalendarSyncService.sync()` only ever upserts and never
deletes, so that sentence is not true today. Do not copy it. The disconnect dialog says what actually
happens. Record the discrepancy in the SUMMARY as an observation about the existing ICS copy; fixing
it is not this phase's job and touching `calendar_sync_service.dart` is not in this plan's scope.
</objective>
