**1. Green on the tree you are about to build.** `export PATH="$PATH:/home/dan/development/flutter/bin"`,
then `flutter analyze` and `flutter test`. Both must be clean/green BEFORE building. Record the test
count.

**2. Take the port, and verify you took it.** `ss -ltn | grep 8143` to see what is there; if anything
is listening, find it with `ss -ltnp | grep 8143` and kill it (`kill <pid>`, or `fuser -k 8143/tcp`).
Then re-run `ss -ltn | grep 8143` and confirm it returns NOTHING. The verification is the point, not
the kill — this project has twice served a two-day-old bundle to the owner because a kill was assumed
rather than checked.

**3. Build the DEBUG bundle, exactly as CLAUDE.md specifies:**
`flutter build web --debug --source-maps --pwa-strategy=none`. Debug, not release: release minifies to
`main.dart.js:<n>` and is unreadable when something throws. `--pwa-strategy=none` so this build cannot
register a service worker. Do NOT use `flutter run -d web-server` — its DDC output fans out into ~866
modules and never finishes loading over tailscale latency.

**4. Serve it, with the sandbox disabled.** Run
`python3 tools/serve-uat.py 8143 --dir build/web` in the background with `dangerouslyDisableSandbox:
true`. Inside the tool sandbox `--bind 0.0.0.0` is silently ignored and the socket comes up on
127.0.0.1, which makes the tailnet URL dead while loopback answers 200. Use `tools/serve-uat.py`, not
`python3 -m http.server`: the latter sends no `Cache-Control`, and a browser will happily keep serving
a cached 13 MB `main.dart.js` — trap #3, which already cost a round trip in Phase 25's UAT.

**5. Prove the binding.** `ss -ltn | grep 8143` must read `0.0.0.0:8143`, not `127.0.0.1:8143`. Then
`curl -s -o /dev/null -w '%{http_code}\n' http://$(tailscale ip -4):8143/` must return 200. A 200 from
localhost is not evidence.

**6. Prove the bytes.** `sha256sum build/web/main.dart.js` and
`curl -s http://danserver:8143/main.dart.js | sha256sum` must match.

**7. Prove the feature is in the bundle — with a probe that is actually valid.**
`curl -s http://danserver:8143/main.dart.js | grep -c 'Just added'` must be greater than 0. `Just
added` is used deliberately: it is a string literal (which `dart2js` preserves) that did not exist
anywhere in `lib/` before this phase. Do NOT probe for `Add your own` or `Add a goal` — both already
existed in the codebase before this phase and would return a false positive. Do not probe for a const
double or an icon name at all: `dart2js` folds both, and reading that zero as "the feature is missing"
already nearly sent a working build back for a pointless rebuild in Phase 31.

**8. Prove trap #4 does not bind.** `git diff --name-only <phase-base-commit>..HEAD -- lib/` must not
contain `schedule_generator.dart`. Record the full file list; Task 2 pastes it into the UAT as the
stated reason Re-check-in is skipped.
