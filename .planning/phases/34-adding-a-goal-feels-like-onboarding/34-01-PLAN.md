**1. `lib/widgets/preset_chip_grid.dart` (new).** Lives in `lib/widgets/` because three screens use
it and none should own it (D-34-05). Declare `enum PresetChipMode { createOnly, toggle }` with a doc
comment naming which surface uses which and why (`createOnly` = goals and onboarding: archiving a
goal is consequential, so no tap may remove one; `toggle` = restoratives: a `RestorativeItem` has no
attributes to lose, and this is its shipped behaviour). Declare
`class PresetChipGrid extends StatelessWidget` with named params
`{required List<(String name, String emoji)> presets, required Iterable<String> existingNames,
required PresetChipMode mode, required void Function(String name, String emoji) onCreate,
void Function(String name)? onRemove, String? heading,
WrapAlignment alignment = WrapAlignment.start}` and an assert that `onRemove != null` whenever
`mode == PresetChipMode.toggle`. Add one static helper
`static List<(String name, String emoji)> unclaimed(List<(String, String)> presets, Iterable<String> existingNames)`
holding the single matching rule, generalised from `_matchFor`/`_suggestionsFor`: trim and lowercase
both sides, keep presets whose name is not present. Callers use this static to decide whether the
section renders at all, so the rule has exactly one definition.

`build()` computes `visible = mode == createOnly ? unclaimed(presets, existingNames) : presets`;
returns `const SizedBox.shrink()` when `visible` is empty (this is UI-SPEC Decision 5's "heading and
grid omitted together" — the heading lives inside this widget precisely so it cannot be orphaned).
Otherwise returns `Column(crossAxisAlignment: CrossAxisAlignment.start, mainAxisSize: MainAxisSize.min,
children: [if (heading != null) Text(heading!, style: Theme.of(context).textTheme.titleSmall),
if (heading != null) const SizedBox(height: 8), Wrap(alignment: alignment, spacing: 8, runSpacing: 8,
children: [...])])`. Each chip is `FilterChip(avatar: Text(emoji), label: Text(name),
selected: mode == PresetChipMode.toggle && <name is claimed>, onSelected: (selected) { if (selected)
onCreate(name, emoji); else onRemove?.call(name); })`. Do NOT introduce `InputChip`, `ActionChip`, a

**2. `GoalsNotifier.addPresetGoal` (in `lib/providers/goals_notifier.dart`).** Per D-34-06 add a NEW
sibling method rather than widening `quickAddGoals`. Justification, one line, to be written into the
method's doc comment: `quickAddGoals` returns `Future<int>` and the picker needs the created `Goal`
object itself (for the "Just added" card and the edit-sheet handoff), and widening its parameter type

and returns `null` if empty; builds the goal; wraps the single `await _repository.save(goal)` in
`try/catch` and returns `null` on failure without rethrowing (the honest-failure contract
`quickAddGoals` already uses); calls `await loadGoals()` on success and returns the created `Goal`.

So the defaults have ONE definition, extract a private factory
`Goal _newDefaultGoal({required String name, required String color, required int sortOrder, String? emoji})`
that constructs `Goal(name:, goalTypeIndex: GoalType.timeTarget.index, color:, weeklyHourBudget: 3.0,
sortOrder:, emojiTag: emoji)`, and make `quickAddGoals`'s loop call it instead of constructing `Goal`
inline. `quickAddGoals` keeps its exact existing observable behaviour — its own test file must pass
with zero edits, and that is the acceptance criterion for this refactor. `addPresetGoal` computes
