## Adaptive Modal Contract

This section specifies the shared helper that replaces all direct `showModalBottomSheet` calls for user-facing forms (goal and commitment forms).

### Helper API

```dart
// lib/widgets/adaptive_form_modal.dart
Future<void> showAdaptiveFormModal({
  required BuildContext context,
  required Widget Function(ScrollController scrollController) builder,
});
```

The helper internally checks `MediaQuery.of(context).size.width` against 720dp and routes accordingly.

### Desktop path (>= 720dp): Material Dialog

- Widget: `showDialog` wrapping a `Dialog` with `clipBehavior: Clip.antiAlias`
- Max width: **560dp** (established by `ConstrainedBox(constraints: BoxConstraints(maxWidth: 560))`)
- Max height: **80% of viewport height** (`BoxConstraints(maxHeight: screenHeight * 0.8)`)
- Horizontal position: centered (default `Dialog` behavior)
- Corner radius: `BorderRadius.circular(28)` (Material 3 `Dialog` default)
- Scrollable interior: `SingleChildScrollView` with a fresh `ScrollController()` injected — the form's `widget.scrollController` is satisfied; no `DraggableScrollableSheet` wrapper
- Drag handle: **hidden** — the drag indicator `Container` (40×4, outlineVariant) in both form sheets must be hidden when rendered inside a dialog. Achieved by passing an `isDialog: bool` parameter to `GoalFormSheet` and `CommitmentFormSheet`, defaulting to `false`
- Padding: 24dp horizontal, 24dp top, 24dp bottom (no `viewInsets.bottom` addition — dialogs float above the keyboard)
- Elevation: `Dialog` default (Material 3 tonal elevation level 3)
- Barrier dismissible: `true` (tapping outside closes the dialog)

### Mobile path (< 720dp): Bottom Sheet (unchanged)

- Existing `showModalBottomSheet` behavior is preserved exactly
- `isScrollControlled: true`, `useSafeArea: true`
- `DraggableScrollableSheet` with `initialChildSize: 0.6`, `minChildSize: 0.4`, `maxChildSize: 1.0`, `snap: true`, `snapSizes: [0.6, 1.0]`
- Drag handle remains visible
- `viewInsets.bottom` padding remains in effect

### Modal callers to migrate

All three callers must be routed through the shared helper. No caller may invoke `showModalBottomSheet` directly for a user-facing form:

| Caller | File | Current invocations |
|--------|------|-------------------|
| Goal add | `lib/screens/goals/goals_screen.dart` | `_openAddSheet` — 1 call |
| Goal edit | `lib/screens/goals/goals_screen.dart` | `_openEditSheet` — 1 call |
| Commitment add/edit | `lib/screens/commitments/commitments_screen.dart` | `_openAddSheet` — 1 call (handles both add and edit via optional `block` param) |

**Out of scope for the adaptive helper:**

- `ChunkDetailSheet` (schedule_screen.dart): informational, action-button only, no text input, lower friction on desktop. Migrate if time permits; not required for RESP-03.
- Confirmation `AlertDialog` calls (commitments delete, settings): these are already dialogs — no change needed.

## Primary Screen Content Width Constraint

**Source:** RESP-01 / POLISH-01 requirements; precedent from `checkin_screen.dart` (already uses `ConstrainedBox(maxWidth: 480)`)

### Contract

At `>= 720dp`, each primary screen's scrollable/list body is wrapped in a horizontally-centered `ConstrainedBox`:

```
ConstrainedBox(
  constraints: const BoxConstraints(maxWidth: 720),
  child: <existing body content>,
)
```

Center the box with `Align(alignment: Alignment.topCenter, ...)` or `Center(...)` to avoid left-flush content on ultra-wide displays.

**Max content width: 720dp** (matches the rail breakpoint — content never wider than a phone-equivalent column at the rail edge).

**Screens in scope:**

| Screen | File | Body widget to constrain |
|--------|------|--------------------------|
| Home | `lib/screens/home/home_screen.dart` | The `Column` inside `body:` |
| Schedule | `lib/screens/schedule/schedule_screen.dart` | The `CustomScrollView` |
| Goals | `lib/screens/goals/goals_screen.dart` | The `CustomScrollView` inside `Consumer` |
| Check-in | `lib/screens/schedule/checkin_screen.dart` | Already constrained at 480dp — **no change needed** |

**AppBar:** Not constrained — spans full width as per Material 3 convention.

**NavigationRail:** Not constrained — it is the side column, 80dp wide, and the content fills the `Expanded` remainder.

## Spacing Scale

Source: pre-existing codebase usage (goals_screen, home_screen, commitment_form_sheet).
The 12dp value appears in a small number of commit-era legacy callsites; it is tolerated in existing code but new code uses 8dp instead.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon gaps, tight inline spacing (e.g. `SizedBox(height: 4)` between title and subtitle) |
| sm | 8dp | Compact element spacing (between fields, between buttons) |
| md | 16dp | Default element padding (horizontal screen edge, vertical section padding) |
| lg | 24dp | Section gaps (heading-to-body, form field groups, modal vertical padding) |
| xl | 32dp | Empty-state vertical centering, top safe area buffer |
| 2xl | 48dp | Not used in this phase |
| 3xl | 64dp | Icon size in empty states only |

**Exceptions:**
- 12dp: legacy callsites in existing files are not touched; new code avoids 12dp
- Touch targets: interactive icon buttons maintain 44×44dp minimum (ReorderableDelayedDragStartListener, drag handles)
- Dialog corner radius: 28dp (Material 3 default — not a spacing token)

## Typography

All type roles are Material 3 `TextTheme` slots resolved from `Theme.of(context).textTheme`. No custom font sizes or weights are introduced in this phase.

| Role | Material 3 slot | Approx size | Approx weight | Line height | Usage |
|------|-----------------|-------------|---------------|-------------|-------|
| Display/Heading | `titleLarge` | ~22sp | w400 | ~1.27 | Modal titles ("Add goal", "Edit goal", "New commitment") |
| Subheading | `titleMedium` | ~16sp | w500 | ~1.5 | Section labels ("Your goals", "Now", "Next") |
| Body | `bodyMedium` | ~14sp | w400 | ~1.43 | Body text, form hints, descriptions |
| Label/Caption | `bodySmall` | ~12sp | w400 | ~1.33 | Metadata (days, times, subtitles, onSurfaceVariant text) |

**Weight overrides used in the codebase (carry forward, do not change):**
- `titleMedium` with `fontWeight: FontWeight.w600` for prominent inline headings ("Your day starts at…", "That's a wrap", goal section titles)
- `titleSmall` with `color: colorScheme.primary` for goal type section headers

**New typography in this phase:** None. The dialog title reuses the existing `titleLarge` style already in both form sheets.

## Color

Source: `lib/providers/theme_notifier.dart` — dynamic `ColorScheme.fromSeed`, mood-driven.
No hex values are hardcoded in this phase. All references use `colorScheme.*` semantic slots.

| Role | ColorScheme slot | Approximate role | Usage |
|------|-----------------|-----------------|-------|
| Dominant (60%) | `colorScheme.surface` | Background surfaces | Screen backgrounds, dialog backgrounds |
| Secondary (30%) | `colorScheme.surfaceContainer` | Elevated containers | Cards, navigation rail surface, dialog surface tonal fill |
| Accent (10%) | `colorScheme.primary` | Interactive emphasis | FAB background, `ElevatedButton` fill, section headers, selected navigation indicators |
| Destructive | `colorScheme.error` | Destructive actions only | Archive button text color in goal form (existing); Delete button text in commitment delete dialog (existing) |

**Accent reserved for:**
- `FloatingActionButton.extended` ("Add goal", "Add commitment")
- `ElevatedButton` / `FilledButton` primary action ("Add goal", "Save", "Save changes", "Add commitment")
- Goal type section header text (`titleSmall` with `colorScheme.primary`)
- Navigation rail selected indicator

**Not accented:** Cancel buttons (TextButton with default theme), drag handles (outlineVariant), field borders (outline), drag indicator icons (outlineVariant)

**Dialog surface:** Material 3 `Dialog` surfaces automatically use `colorScheme.surface` with tonal elevation — no explicit color override needed.

## Interaction Contracts

### Adaptive Modal: dismiss behavior

| Context | Dismiss mechanism |
|---------|-------------------|
| Desktop dialog | Tap outside barrier (default `barrierDismissible: true`), or Cancel button |
| Mobile sheet | Swipe down below `minChildSize`, or Cancel button |

Both dismiss without saving. No unsaved-changes warning — this is unchanged from the existing bottom sheet behavior.

### Desktop dialog: keyboard behavior

- Dialog appears centered; system keyboard (if any — desktop typically has physical keyboard) does not push the dialog
- `viewInsets.bottom` is NOT added to dialog padding (unlike the sheet)
- `autofocus: !_isEditMode` on the goal name `TextField` remains — the dialog receives focus immediately in add mode

### Primary screen content: scroll behavior

- `CustomScrollView` / `Column` remain the scroll container
- The `ConstrainedBox` wraps the child of `body:`, not the scroll view itself, so scrolling still works naturally
- `Align(alignment: Alignment.topCenter)` centers the constrained column without clipping

### GoalTypePicker in dialog

- `GoalTypePicker` renders as a vertical column of three `_TypeCard` rows
- At 560dp dialog width, all three type cards display without horizontal clipping
- No changes to `GoalTypePicker` widget are needed — it uses `Column(mainAxisSize: MainAxisSize.min)` which fits within 560dp

## POLISH-02 Audit Scope

POLISH-02 requires a fresh desktop walkthrough to identify high-friction UI nits. The executor must:

1. Build the debug web bundle (`flutter build web --debug --source-maps --pwa-strategy=none`) and serve it on a fresh port
2. Walk through every primary screen and all modal forms at desktop width (>= 720dp)
3. Log each friction point with: screen, element, observed problem, proposed fix
4. Fix items rated "high friction" (blocks task or causes visible layout breakage); defer "low friction" nits to later phases

**Known pre-identified nit (from STATE.md / SEED-002):** Goal form desktop layout — the form currently renders as a bottom sheet on desktop, making the type picker, Priority, and Save button require scrolling or feel cramped. This is the primary motivation for RESP-01/02 and is resolved by the adaptive helper above.
