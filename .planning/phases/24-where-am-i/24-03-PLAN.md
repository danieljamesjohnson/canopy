  <action>
1. Confirm the tree is the post-24-02 state: `git status --porcelain` shows no uncommitted source
   changes under `lib/`, and `flutter test test/screens/today_screen_test.dart` is green. Do not
   build a dirty or failing tree.

2. Build with exactly this command — a single dart2js bundle in **debug mode**:
   `flutter build web --debug --source-maps --pwa-strategy=none`

   Do NOT use `flutter run -d web-server`. That uses the DDC incremental compiler and fans the app
   out into ~866 module files; over tailscale latency the browser's ~6-connections-per-origin limit
   turns that into minutes of serial round-trips and a white page. Measured: at 80ms emulated
   latency the DDC build's `load` event never fired in 90s / 877 requests, while this single-bundle
   debug build fired in ~21s / 9 requests. Do NOT switch to `--release` — debug mode is deliberate
   at this UAT stage because release minifies every stack trace to `main.dart.js:<n>`.
   `--pwa-strategy=none` is required so this build can never register a service worker.

3. Pick a **fresh port** in the 8800-8899 range that has never served a *release* build on this box.
   A leftover `flutter_service_worker.js` registered by a prior release build on the same origin
   will keep intercepting requests and serve a cached release shell against a mismatched server —
   a persistent blank page that survives reloads and incognito. Check what is already listening
   (`ss -ltnp | grep -E ':88[0-9][0-9]'`) and pick an unused one. Known occupied: 8815
   (`roadmap_app/served/rogue`). Record the chosen port — it goes in the SUMMARY and in the
   notification.

4. Serve statically from the build output, in the background:
   `python3 -m http.server <PORT> --bind 0.0.0.0` with working directory `build/web`.

5. Smoke-check before handing it over:
   - `curl -sI http://danserver:<PORT>/ | head -1` returns a `200`.
   - `curl -s http://danserver:<PORT>/ | grep -c "main.dart.js"` returns at least `1`.
   - `ls build/web/flutter_service_worker.js` reports no such file.

   Optionally run a single `go-look-at` render as a boot smoke check, but do NOT treat a headless
   screenshot as the verification of record: repeated headless Chromium launches exhaust the 780M's
   WebGL context (`CONTEXT_LOST_WEBGL`) and produce a false blank page. The perceptual verdict comes
   from a real GPU-backed browser in Task 2.

6. Notify Dan with the URL:
   `notify-dan "Canopy Phase 24 ready" "Now-marker UAT: http://danserver:<PORT>"`
  </action>
