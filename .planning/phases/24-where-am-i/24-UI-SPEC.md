## The Now-Marker (NOW-01)

### Verdict on the recovered pre-merge widget

`git show ea97862^:lib/screens/schedule/widgets/now_marker.dart` (46 lines, quoted in
`24-RESEARCH.md`) is **adapted, not resurrected as-is and not replaced wholesale.** Kept: the
`colorScheme.primary` convention, the "Now" label copy, the leading-rule + label + trailing-rule
row shape. Dropped/changed, with reasons:

| Old widget | This contract | Why |
|---|---|---|
| Wrapped in `ExcludeSemantics` (fully removes the node — a screen-reader user gets nothing) | Wrapped in `Semantics(label: ..., excludeSemantics: true)` at the call site (one clean node, not zero nodes) | `24-UI-SPEC.md`'s accessibility constraint requires the marker be findable without relying on sight alone. Old behavior fails a screen-reader user outright; the fix keeps a single well-labeled node instead of silence. |
| 8×8 circle dot between the leading rule and the label | Dropped | The row vocabulary this app already has is: dotted vertical tick + text (`FreeTimeRow`, quiet/neutral) vs. full-bleed card (`LiveRowCard`, loud/primary). A dot introduces a third, unprecedented rule-motif. Two motifs (dotted tick = descriptive, solid horizontal rule = positional) is a vocabulary; three is noise. |
| Placement logic: `_buildActiveChunkItems`, a crude first-unresolved-chunk scan | Not reused — this phase's placement is the position-based rule below, driven by the injected `nowMinutes`, never a re-scan | This was the actual regression (Phase 17/22 killed exactly this pattern elsewhere). The old file's *visual* convention is worth keeping; its *placement* logic must not come back. |
| Placed by an old screen no longer in the tree (`schedule_screen.dart`) | New file: `lib/screens/today/widgets/now_marker.dart`, rendered via the one exhaustive switch in `today_screen.dart:556` | Follows the existing `today/widgets/` convention (`free_time_row.dart`, `live_row_card.dart`, `timeline_row_tile.dart`). |

### Visual treatment

| Property | Value |
|---|---|
| Container | No `Card`, no elevation, no fill — a quiet row, same tier as `FreeTimeRow`, explicitly not competing with `LiveRowCard` |
| Wrapping | `TimelineRowTile(startMinutes: minutes, child: ...)` — inherits the 16dp horizontal inset and the 52dp gutter for free, exactly like every other row |
| Row height | Content-driven: `Padding(vertical: 8)` (the `sm` token, matching `FreeTimeRow`'s own vertical rhythm exactly — same visual weight/spacing family) |
| Leading rule | Horizontal line, `24`dp wide (the `lg` spacing token) × `2`dp tall, `colorScheme.primary` at full opacity |
| Gaps | `8`dp (`sm` token) on both sides of the label |
| Label copy | `"Now"` — exact string, locked |
| Label style | `textTheme.labelMedium` (Material 3 default: 12px / 16px line-height), overridden `fontWeight: FontWeight.w600`, `color: colorScheme.primary` |
| Trailing rule | Horizontal line, `Expanded` (fills remaining row width) × `2`dp tall, `colorScheme.primary.withValues(alpha: 0.35)` |
| Gutter content | The current compact time (e.g. `"12:34p"`), rendered automatically by `TimelineRowTile` from the same `minutes` value — no special-casing needed |
| Semantics | `Semantics(label: 'Now — ${formatMinutes(minutes)}', excludeSemantics: true, child: NowMarker())` at the call site in `today_screen.dart`'s switch, e.g. `'Now — 12:34 PM'`. `excludeSemantics: true` merges the row into one announced node instead of the screen reader also reading the bare "Now" `Text` underneath — one clean announcement, not a double one. |

**Why a horizontal rule, not a repeat of `FreeTimeRow`'s vertical tick:** `FreeTimeRow`'s vertical
2×16dp tick is a small, descriptive accent beside text — appropriate for a row that's explaining a
span of time. The now-marker's job (NOW-01 criterion 1) is different: it must be scannable at a
glance while skimming the whole list top-to-bottom to answer "where am I." A rule that spans the
full row width reads as a horizontal divider — the shape itself says "boundary in the list," which
is the marker's actual job — where a small vertical tick would not stand out while scrolling.

**Why not rely on color alone (accessibility):** the marker is identifiable by three independent
cues, not one — (1) shape: a full-width horizontal rule, a silhouette nothing else in the row
vocabulary uses, (2) text: the literal word "Now", (3) color: `colorScheme.primary`. A colorblind
or low-vision user still gets (1) and (2) with zero dependency on hue discrimination.

**Why "Now" and not a repeated time string:** every row in the list already carries its clock time
in the 52dp gutter (`TimelineRowTile`'s established contract) — chunk rows, free rows via their
label text, and now the marker via the same gutter mechanism. Putting a second time string inside
the marker's own label (e.g. "Now — 12:34 PM" as visible text) would make it the only row in the
list carrying two separately-formatted time strings for the same instant. "Now" is the
information the gutter's time can't already convey — it says *what this row means*, the gutter says
*when*. The full `formatMinutes` string is still available to screen-reader users via the
`Semantics` label above; it's redundant only as *visible* text, not as spoken text.

### Insertion rule (NOW-01) — supersedes the raw loop order sketched in `24-RESEARCH.md` Pattern 2

`buildTimeline` gains one optional parameter, `int? nowMinutes` (default `null` — preserves all
15 existing call sites in `today_timeline_model_test.dart` unchanged, per `24-RESEARCH.md`
Pitfall 2). The marker is inserted with a single forward-pass rule:

> Insert `NowMarkerRow(nowMinutes)` immediately before the `ChunkRow` for the first chunk (in
> clock order) whose `displayStartMinutes > nowMinutes` — **but after** any `LeadingFreeRow` or
> `GapFreeRow` that the same loop iteration emits for that gap. If no such chunk exists (the day
> is over), append the marker at the very end of the list.

This differs from `24-RESEARCH.md`'s raw diff, which checks marker-placement *before* the
leading/gap free-row block in the same iteration — that ordering would put `NowMarkerRow` ahead
of `LeadingFreeRow`/`GapFreeRow` whenever both apply (e.g. `PreStart` with an open leading
window). This contract requires the opposite order — **free row (if any), then the marker, then
the chunk** — because it reads chronologically correctly: the free/gap row describes the whole
span from the previous boundary to the next chunk; "now" is a point that falls *within* that span,
so it belongs directly after the row that names the span, immediately before what's next. The fix
is a one-line reorder within the same single forward pass (move the marker check to just before
`rows.add(ChunkRow(...))` instead of at the top of the loop body) — it does not add a second pass
or any re-scan, so `timeline.dart`'s INVARIANT 1/2 are unaffected.

Suppression guard: `nowState is! Active`. The marker check and the free-row block are independent
of each other — a gap shorter than `kMinGapMinutes` still gets a marker even though it gets no
`GapFreeRow` (per `24-RESEARCH.md`'s explicit anti-pattern: never attach the marker's presence to
`GapFreeRow`'s existence).

### Active-state suppression — ratified, with `Overdue` explicitly carved out

**Ratify `24-RESEARCH.md`'s recommendation as-is: suppress for `Active`, show for `PreStart`,
`GapBeforeNext`, `Overdue`, `DayComplete`.**

- Suppress for `Active`: `LiveRowCard` is already the loudest element on the screen (full-bleed,
  `primaryContainer` fill, elevation 6, uppercase "RIGHT NOW" kicker) — a marker landing
  immediately after it (per the insertion rule, that's exactly where it would go) would be pure
  redundancy beside the one row that least needs help being found. It would also be mildly
  *wrong*: the rule places a marker at a chunk boundary, but during `Active` "now" is somewhere
  mid-way through the live chunk's own window — rendering a marker there would visually assert a
  boundary position that isn't the true one.
- Show for `Overdue`, even though it *also* renders through `LiveRowCard`: `Overdue`'s card shows
  the chunk's original static time range with a full, non-moving progress bar and no countdown —
  by the Phase 23 copywriting contract, it deliberately does not say *how* overdue the chunk is.
  The marker is the only element that can show "and here's how far past that window 'now' actually
  is" without inventing "behind" language — it fills a real gap the card intentionally leaves open,
  it doesn't duplicate anything.
- Dan's actual reported confusion (`24-evidence-dan-drop.png`) was a `GapBeforeNext` screen — the
  live row wasn't even rendering at the moment he couldn't tell "where now is." This is direct
  evidence the non-`Active` states are exactly where the marker earns its keep, and confirms
  `Active` was never the confusing case to begin with.

### When "now" falls inside a resolved chunk's original window

The marker never renders *inside* a card — insertion is always between two rows, never a mid-row
overlay (this is also why an overlay/`Stack` approach was rejected in `24-RESEARCH.md`'s
alternatives). When "now" numerically falls within a chunk that's already resolved (completed or
skipped early — e.g. the `Family time` row in the evidence screenshot), the general insertion rule
still applies unmodified: the marker lands directly before the next chunk whose
`displayStartMinutes > nowMinutes`, i.e. immediately after whatever resolved/overdue rows and free
rows sit in between.

**Does that read as correct?** Yes. A resolved row is already visually marked as behind the user —
struck-through title, dimmed, a checkmark or "skipped" label (confirmed in the evidence screenshot,
and explicitly out of this phase's scope to change). The marker doesn't need to intersect that
row's bounds to communicate "you're past this" — the row's own resolved styling already says that.
The marker's job is narrower and humbler, per `24-CONTEXT.md`'s "position, not a second detector"
framing: it answers "relative to what's coming next, here's where the clock actually is," and
placing it immediately above the next upcoming row does exactly that without claiming any false
precision about a card it can't split.

## Free Row States (NOW-02)

| State | Condition | Rendered row | Copy |
|---|---|---|---|
| Window still open | `nowMinutes < firstChunk.displayStartMinutes` (equivalently: `nowState` is `PreStart`) | `LeadingFreeRow` renders, unchanged | `"Free until <time>"` — exact locked string, reused verbatim from `free_time_row.dart:26`, not reworded |
| Window closed | `nowMinutes >= firstChunk.displayStartMinutes` | `LeadingFreeRow` suppressed entirely — no row, no replacement copy | n/a — the row simply does not exist once its window has passed; whatever state now applies (`Active`, `GapBeforeNext`, etc.) governs the `NowMarkerRow` independently, no special-casing needed for "the leading row used to be here" |
| No leading gap at all | `firstChunk.displayStartMinutes == 0` | No row, unchanged pre-existing behavior (`start > 0` guard) | n/a — this was never a NOW-02 case; there was never text to suppress |

The fix is suppression, not relabeling: once the window has closed there is no truthful alternate
copy to show in its place (the time already passed) — the row is absent, and the now-marker (which
independently governs its own visibility per the Active-suppression rule above) is what tells the
user where they actually are instead.
