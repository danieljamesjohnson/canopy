<objective>
Close the one confirmed gap from plan 24-03's UAT checkpoint: when `TodayScreen` opens in a
`NowState` that renders no live row — `DayComplete` (Dan's reported defect), and structurally
identical `PreStart` / `GapBeforeNext` — the day list never scrolls the now-marker into view. It
opens at the natural top of the day, which late in the day is entirely in the past. Extend the
existing D-02 centre-on-open mechanism with a second, independent fallback that centres on the
`NowMarkerRow` when there is no live row to centre on instead.

**Root cause (already diagnosed in `24-03-SUMMARY.md`, do not re-investigate):**
`lib/screens/today/today_screen.dart`'s centre-on-open block gates
`Scrollable.ensureVisible` behind `hasLiveRow = timelineRows.any((row) => row is ChunkRow &&
row.isLive)`. `hasLiveRow` is true only for `Active` and `Overdue`. The `NowMarkerRow` itself
renders correctly and is positioned last for `DayComplete` (`timeline.dart:127-131`) — the user
simply never scrolls far enough to see it.

**Locked decisions this plan implements** (from `24-CONTEXT.md` → `### Locked` and
`24-UI-SPEC.md`, referenced as D-01/D-02/D-03 for traceability, plus Dan's explicit gap-closure
routing decision recorded in `24-03-SUMMARY.md`):

- **D-01 — position, not a second detector.** The fallback reuses the exact `nowMinutes` /
  `timelineRows` this `build()` already computed. No new `_nowFn()` or `DateTime.now()` call, and
  `timeline.dart` (INVARIANT 1) is not touched at all — this is a `today_screen.dart`-only
  scroll-position fix.
- **D-02 — show the marker when it adds information; centre on whatever answers "where am I."**
  Today that's the live row when one exists. This plan extends the same principle to the marker
  when no live row exists — it's the only other row that answers the question.
- **D-03 — no sticky bar, floating pill, or jump button** (the rejected sketch variant B). The fix
  must be scroll-position only, exactly like the existing live-row centring it extends.
- **Dan's routing decision** (`24-03-SUMMARY.md`, via `AskUserQuestion`): fix `DayComplete` inside
  phase 24 via this gap-closure plan; a time-proportional calendar view with a moving "now" line,
  and any general "past items recede/collapse" treatment, are explicitly routed to a **separate,
  future phase** — not this plan. Do not implement either here; this plan touches scroll position
  only, no row-height, dimming, or layout changes.

Purpose: make phase 24's own success criterion — "where am I" is answerable by looking at the
timeline — actually true for `DayComplete`, the one state Dan verified and found lacking.
Output: a scrolled-to-the-marker `DayComplete` (and `PreStart`/`GapBeforeNext`) on open, a
regression-proof that the pre-existing live-row centring still works after such a day transitions
into `Active`, and a still-fully-green test suite.
</objective>
