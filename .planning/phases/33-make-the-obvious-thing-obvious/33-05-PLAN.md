
Debug, not release: unminified Dart stack traces are the point at this stage, and load speed is
explicitly not the concern. `--pwa-strategy=none` means this build registers no service worker, so it
cannot create a trap #1 collision. Do **not** use `flutter run -d web-server` — its DDC output fans
into ~866 module files and never finishes loading over tailscale latency.

**D. Serve it.**

```
python3 tools/serve-uat.py 8143 --dir build/web
```

in the background. `serve-uat.py`, not `python3 -m http.server`: it sends `Cache-Control: no-store`
and strips `If-Modified-Since`/`If-None-Match`, which is what stops a cached `main.dart.js` from
being served against the new build (trap #3, which cost a round trip in Phase 25's UAT).

**E. Pre-flight the served bytes** — the trap #3 diagnosis, run proactively rather than after a
false failure:

```
curl -s http://danserver:8143/main.dart.js | grep -c 'Priority order'
curl -s http://danserver:8143/main.dart.js | grep -c 'To do'
curl -s http://danserver:8143/main.dart.js | grep -c 'Something that restores you'
curl -s http://danserver:8143/main.dart.js | grep -c 'Walk outside'
```

All four must be non-zero. **These are valid presence probes and the reason matters**: dart2js
preserves string literals that reach a `Text` widget, while it const-folds numeric constants to
literals and reduces icons to codepoints — which is why Phase 32's pre-flight greps for
`drag_indicator` and `kSubCompactGripSize` both returned zero on a bundle that definitely contained
them. Probe for strings, never for constant names or icon identifiers.

Also confirm no service worker is being served: `curl -s -o /dev/null -w '%{http_code}'
http://danserver:8143/flutter_service_worker.js` should not return 200.

Record the served-bundle sha (`sha256sum build/web/main.dart.js` compared against
`curl -s http://danserver:8143/main.dart.js | sha256sum`) so a later reader can tell whether the
pre-flight is still true without re-running it.
