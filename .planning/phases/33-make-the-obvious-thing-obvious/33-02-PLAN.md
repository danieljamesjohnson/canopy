API:

```
class WeeklyProgressService {
  const WeeklyProgressService();

  static DateTime weekStart(DateTime date);
  int completedChunksThisWeek(String goalId, List<CompletionLog> logs, DateTime today);
  int completedDaysThisWeek(String goalId, List<CompletionLog> logs, DateTime today);
  double completedHoursThisWeek(String goalId, List<CompletionLog> logs, DateTime today);
  double? weekFractionFor(Goal goal, List<CompletionLog> logs, DateTime today);
}
```

Rules:

- `weekStart` returns the **date-only** Monday of the week containing `date`: normalise first with
  `DateTime(date.year, date.month, date.day)`, then subtract `date.weekday - 1` days.
- The window filter matches the generator's shape — `l.goalId == goalId`,
  `l.event == CompletionEvent.completed`, and `DateTime.parse(l.dateYmd)` neither before `weekStart`
  nor after the date-only normalisation of `today`. Filter on `goalId`, **not** `attributionId`, so
  commitment logs (`goalId == ''`) fall out naturally, exactly as the generator does.
- `completedDaysThisWeek` counts **distinct** `dateYmd` values among that same filtered set.
- `completedHoursThisWeek` is
  `completedChunksThisWeek(...) * ScheduleGeneratorService.workChunkMinutes / 60.0`. This is the
  only place in the new code that converts chunks to hours; do not re-type 25 anywhere.
- `weekFractionFor` switches on `goal.goalType`:
  - `outcome` → `null`. The model carries only `deadline` and `outcomeDescription` for outcomes, so
    any number would be invented state (UI-SPEC item 16).
  - `timeTarget` → `null` when `weeklyHourBudget` is null or not greater than zero; otherwise
    `(completedHoursThisWeek / weeklyHourBudget!).clamp(0.0, 1.0)`.
  - `habit` → `freq = goal.frequencyPerWeek ?? 7`; `null` when `freq <= 0`; otherwise
    `(completedDaysThisWeek / freq).clamp(0.0, 1.0)`.

**Record the one deliberate divergence from the generator, in the `weekStart` doc comment.**
`schedule_generator.dart:317-318` computes `date.subtract(Duration(days: date.weekday - 1))`
*without* normalising the time of day, so its `weekStart` carries `today`'s clock time. A log dated
Monday parses to Monday 00:00, which `isBefore` a Monday-14:30 week start — so on any afternoon the
generator silently drops Monday's own completions from the week's count. This helper normalises to
date-only and is therefore correct. State plainly in the doc comment that the generator has the same
latent off-by-one, that it is **out of scope by the ROADMAP's "do not modify `schedule_generator.dart`"
fence**, and that a fix belongs to a later phase. Do not "align" this helper to the bug for
consistency, and do not fix the generator.

Then write `.planning/seeds/SEED-006-week-start-carries-time-of-day.md` capturing that finding —
