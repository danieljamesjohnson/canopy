<objective>
Make adding a restorative cost a tap instead of nine round trips, and stop the app assuming that
anything worth recording must be a goal.

Purpose: OBVIOUS-03 — adding a restorative is tappable, and declaring something energizing does not
force it to be a goal. Both items were raised on the live build on 2026-07-02. The guitar friction is
that `EnergyValence.gives` is reachable only from inside a goal form, so "guitar energizes me" forces
guitar to acquire a type, a weekly budget and a priority, or go unrecorded.

Output: a nine-chip quick-pick grid on the restoratives screen, and a front-door fork in front of the
Goals FAB whose second door never shows a goal form.
</objective>

fork.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → persistence | Free-text restorative names and emoji cross into Hive via `saveItem` |
| Chip tap → delete | A single tap on a selected chip hard-deletes a `RestorativeItem` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-11 | Tampering | chip deselect → `deleteItem` | medium | accept | One tap hard-deletes with no confirmation. Accepted deliberately: UI-SPEC item 22 requires "tapping an added chip removes it", the data is a nine-item list of restorative names with no downstream references, and re-adding is one tap. The heavier `_confirmDelete` is retained for the list rows, which can hold user-typed items the chips cannot restore |
| T-33-12 | Elevation of Privilege | restorative door | high | mitigate | The restorative door must never produce a `Goal` — a restorative that became a goal would acquire a budget and enter the scheduler, breaking the promise in its own consequence line. Pinned by `goals_add_fork_test.dart` case 3 asserting `goalsNotifier.goals` stays empty and `GoalFormSheet` never mounts |
| T-33-13 | Information Disclosure | emoji field | low | accept | `maxLength: 2` matches the existing restoratives dialog; the value is rendered as text in-app only and never leaves the device |
| T-33-14 | Tampering | package supply chain | n/a | accept | No packages installed; no `pubspec.yaml` change. `FilterChip` ships with the Flutter Material library already in use |
