says so, type demoted to a labelled chip, and the loudest mark on the card reassigned from identity
colour to progress this week.

screen names its purpose, and the one strong colour on a card carries a scale instead of an identity.

chip) and a `GoalsScreen` that renders one ranked list and reads real weekly progress.

a 90% line on a short card shorter in real pixels than a 62% line on a tall one, which is the defect
the sketch found and the eye compares pixels, not percentages. **Do not use `FractionallySizedBox`
here and do not tie the fill to the card's height by any route.**

**B. Load progress, and keep it fresh.** Add state `Map<String, double?> _weekProgress = {}` and a

`loadGoals()` and then `_loadWeekProgress()`, and register

The listener is not optional polish. `router.dart:45` uses `StatefulShellRoute.indexedStack`, so
`GoalsScreen` stays mounted across tab switches — a mount-only read would show a stale bar the moment
the user completes a chunk on Today and comes back, and "the served bytes are correct but the screen
shows old data" is exactly the class of false-failure `CLAUDE.md` trap #4 documents.

`_loadWeekProgress()`: return early if `!mounted`; capture `context.read<GoalsNotifier>()` and the
repository **before** the first `await` (Pitfall 6, stated in `quarterly_review_screen.dart:73-75`);
`await repo.getAll()`; then build the map with `const WeeklyProgressService().weekFractionFor(goal,
logs, DateTime.now())` per goal; then `if (mounted) setState(...)`. One `getAll()` per refresh, not
one `getByGoalId` per goal.

**Two defensive guards, both required, both with existing precedent — without them this task turns
six currently-green test files red.**

1. **Wrap the repository read in a try/catch** that leaves `_weekProgress` empty on failure. When no
   repository is injected the default is `HiveCompletionLogRepository()`, and every widget test that

2. **Catch `ProviderNotFoundException` around the `ScheduleNotifier` lookup.** `context.read<

   `content_width_constraint_test.dart` and `responsive_layout_test.dart` — all of which provide only
   a `GoalsNotifier`. Catch it narrowly (`on ProviderNotFoundException`), leave `_schedule` null, and
   document in a comment that the refresh listener is simply absent in that case. Do **not** catch a
   bare `Exception` here; a broad catch would hide a real production wiring failure behind a silent
